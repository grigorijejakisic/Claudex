# v4 Proposal: Make the memory system actually good

**Date:** 2026-04-27. **Origin session:** 7f479833 (audit pickup from e0d0a138).
**Status:** Draft for user review. Supersedes ROADMAP gates and Phase 5 plan once approved.
**Anchor:** This proposal is bound to one criterion — *does the memory system help the agent think and recall organically?* — and rejects benchmark numbers as decision-makers.

---

## 1. The pattern of failure (why every phase looks green while the system gets worse)

v4's thesis is correct. The plan that implements it is structured around the wrong unit of success. Every phase ships when one of three things happens:

| Phase ships when | Examples | Problem |
|---|---|---|
| A writer produces rows | Phase 3 (`directive_rule`), Phase 4 (MEMORY.md curator) | Writer producing rows ≠ rows being read by anything |
| LOC are deleted on plan | Phase 5 (delete 9 sections), Phase 9 (delete cognitive layer) | Deletion ≠ better cognition; could be removing things that worked |
| A benchmark stays at floor | LongMemEval ≥88%, LoCoMo within 2pp, BENCH-09 ≥ baseline | Benchmarks don't exercise the assembler, MEMORY.md, or directive surface |

This is structural, not bug-level. The audit doc captures the symptoms (BENCH-09 contaminated, LongMemEval doesn't touch assembler, LoCoMo bypasses session-start). The disease underneath is: **the v4 plan never defined "is the memory good?" as a measurable thing**, so it borrowed retrieval-quality benchmarks as proxies and started executing.

What the failures from T1+T2 show:

- **T1 finding (MEMORY.md):** Auto-curated MEMORY.md ships on 2/5 active projects (40% reach). Where it ships, content is *worse* than the manual pointer-index it replaces. Generic-noun "entities" (`predictor`, `system`, `prompt`) carry zero project-specific signal; 2/8 entries are corrupt (`"`, `" 2>&1`); 50% of recent threads have topic = session ID; writer state machine duplicates the managed section in some files. **The flagship deliverable of Phase 4 regressed memory quality in production**, and Phase 4 SUMMARY reported PASS because LongMemEval and LoCoMo don't read MEMORY.md.
- **T2 finding (directive_rule):** 2 rows in the entire DB after 5 days of live operation. Both from one project (`big-mozzy-v2`). **Zero production consumers.** Phase 3's calibration tuning (joint precision 0.353 → 0.500 over six plans) was tuning a writer whose output is silently dropped. The Phase 3 SUMMARY framed "no injection-path changes" as a virtue ("we didn't break anything"); it's actually the defect signature.

These are the same anti-pattern. **Ship what's measurable; defer what would actually help.**

## 2. The single criterion this proposal binds to

A memory system is good when, at any point in a session, the agent has *the smallest amount of context that still lets it reach for the right deeper artifact when it matters.*

Operationally:

1. **Session-start budget is small** — only what every session needs (identity, project pointer, active handoff). Not a catalog of everything ever known.
2. **The index surface (MEMORY.md) consists of pointers** to deeper artifacts, each pointer carrying project-specific salience — not frequency-counted nouns.
3. **The recall path (`claudex_search`, `claudex_recall`, `claudex_events`) is excellent** — when the agent searches for "Mozzart Cloudflare 429," the deep artifact arrives in the top result.
4. **Surfacing is decision-time, not session-start** — directives reach the agent when relevant tool calls are about to fire, not pre-injected as imperatives.
5. **No imperatives in memory** — the v4 thesis is right; the implementation must hold the line.
6. **Validation is behavioral** — does the agent reach correctly? Vesna probes, content-quality scoring, real-world soak. Benchmarks are sanity checks (-1pp tolerance, no-regression).

These six are the criteria. Every phase that ships under this proposal must answer how it serves at least one of them.

## 4. Cross-cutting principles for the rewrite

These are non-negotiable. Every phase from here on is bound by them.

1. **Writers ship with consumers.** A writer that produces rows nothing reads is not "shipped" — it's dead infrastructure. Phase 3's directive detector and Phase 10's lifecycle must merge into one shippable unit, with the PreToolUse hook (or whatever the chosen surface is) being part of "Phase 3 ship."
2. **Auto-extraction is fine for factual data, never for cognitive data.** Active project rotation, handoff status, file mtimes — auto-extract. Entities, themes, threads, mental models — these need curation. If you can only get them by counting, they aren't worth having.
3. **No imperatives in any memory surface.** The v4 thesis is correct. Every new surface (MEMORY.md, PreToolUse warnings, system-role primes) must be observational. *"Similar prior situation: user wanted Y; outcome was Z"* — not *"Correct approach: always X."*
4. **Index = pointers, body = artifacts.** MEMORY.md is the index. Deeper artifacts live in `~/.claude/projects/<slug>/memory/*.md` (already the convention) and the DB. The agent reads the index, decides what to recall, pulls via tools. The index should NEVER contain extracted summaries that the agent can't act on without a tool call anyway.
5. **Quality scoring is part of CI.** A content-quality score for MEMORY.md (parsing-bug count, thread-topic usefulness, pointer density) becomes a gate. T1's audit becomes a script that runs every PR.
6. **Benchmarks are no-regression sanity checks.** -1pp tolerance on LongMemEval/LoCoMo — they're noise floor, not direction. The thing they're useful for is detecting catastrophic regression. They're not the gate.
7. **Behavioral probes are the real validation.** Vesna-style probes ("can the agent answer X about Y in one turn without filesystem exploration?") need to grow from one probe to 8-12 covering different recall patterns. These run after every phase, *and* in real-world soak.
8. **The user's manual curation is the gold standard.** Lacuna/Oracle/Nexus pointer-indexes work because the user wrote them at /endsession. The auto-curator should *help* this — easier curation flow, prefill suggestions — not *replace* it with frequency-extraction noise.

### Phase 5 (P4 — Kill legacy injection) → 🔄 EXECUTE WITH NEW GATES

The deletion is correct (it implements the v4 thesis). The gates are wrong. New gates:

**Real gates (must pass to merge):**
1. **Token budget ≤500** at session-start (tokenizer assertion).
2. **Cache stability** — 3-layer (golden snapshot + invariance test mutating volatile state + repeated session-start byte-identical). Pre-work hardening list lands first: clock leaks (3 sites), session-ID strips (2 sites), host-env normalization (2 sites), stable tiebreakers (4 sites), CRLF/BOM normalizer + `.gitattributes * text eol=lf`.
3. **MEMORY.md content quality score** — T1's scoring rubric (parsing bugs / thread usefulness / pointer density) run as CI on every active project's MEMORY.md. Hard threshold: zero parsing-bug rows; ≥80% of pointers are project-specific (not generic nouns).
4. **Vesna behavioral probe expanded** — instead of one probe, 8-12 probes covering: entity recall ("what is X"), constraint recall ("what should I avoid in Y"), handoff recall ("what was last session about"), cross-project recall ("does claudex have a Mozzart equivalent"), etc. ≥80% pass without filesystem exploration.

**Sanity checks (no-regression, not gate):**
- LongMemEval Oracle within -1pp of pre-Phase-5.
- LoCoMo within -1pp of pre-Phase-5.

**Post-land monitoring (separate workflow):**
- BENCH-09 with the cap fixed (raise `recordUserFraming` cap from 3 → 30, rebaseline). 30-day soak. Median tracked daily, published to `bench09_daily.jsonl`. Drop below floor triggers investigation, not auto-revert.

**Pre-work that must land before deletion:**
- Cache leaks (3 sites: `assembler.ts:572`, `:657`, `:447`)
- Session-ID strip (2 sites: `sections.ts:859`, `:1005`)
- Host-env normalization (2 sites: `sections.ts:635`, `assembler.ts:646`)

### Phase 6 (P5 — Retrieval simplification) → 🔄 RE-FRAME around recall path quality

LoCoMo IS load-bearing for this phase (`hybridSearchAsync` is the actual production code path tested). Keep LoCoMo as a no-regression gate here.

But re-frame the goal: the agent's organic recall depends on this path. The 6-multiplier chain may have been compensating for reranker weaknesses. **Add a per-multiplier ablation** (one A/B per multiplier) before the bulk delete, so we know what each one contributed. Cheap to run, high information value.

Reranker availability: BGE-v2-m3 cross-encoder must be a hard dependency for production retrieval, with the bi-encoder fallback explicitly degraded-mode (telemetry counter when fallback fires).

### Phase 7 (P6 — Framing rewrite) → ✅ keep + add behavioral gate
The work is correct. Add a behavioral gate: subjective AB on real sessions for a week, scoring whether agent behavior shifts on imperative-vs-advisory framing. Benchmarks won't show it; manual review will.

### Phase 8 (P6.5 — RL ablation) → ✅ keep
Cleanest phase in the plan. Deterministic A/B. Edge case: if the flagged LoCoMo is exactly at -2pp, default to "keep RL" (conservative), document, revisit Phase 9.

### Phase 9 (P7 — Angel simplification) → 🔄 GATE on consumer audit
Per-module: sample current outputs in DB, find consumers via grep. Same audit pattern as T2 (directive_rule). Three categories:
- **Silo (no consumers):** safe delete. Probably most of CARA, dream consolidation, skill crystallization based on what we know.
- **Consumed by Phase 5 deletion target:** delete with Phase 5; data was already orphaned.
- **Consumed by surviving code:** redesign the consumer or defer the deletion.

If T6 audit finds that ALL deleted modules are silos (likely, given the same anti-pattern as Phase 3): delete confidently, mark the cumulative `~3000-4000 LOC` reduction as a *cleanup of dead infrastructure*, not a cognitive-capacity cut.

### Phase 10 (P8 — Rule lifecycle) → 🔄 ABSORBED INTO NEW PHASE 3
See Phase 3 rebind above. Lifecycle ships with detector + consumer surface as one unit.

### Phase 11 (P9 → renumber to Phase 10) → 🔄 REPLACE GATES

Drop LoCoMo ≥70% as the tag-gate. Replace with:

1. **Vesna behavioral probe suite** — 8-12 probes, ≥80% pass.
2. **Content-quality score** on MEMORY.md across all active projects ≥80%.
3. **Real-world soak** — 30 days post-Phase-5-merge with BENCH-09-fixed daily medians.
4. **Cross-session continuity probe** — agent picks up handoff in one turn without filesystem exploration.

LongMemEval / LoCoMo: keep as no-regression sanity (-1pp tolerance from pre-v4).

The 62.3% → 70% LoCoMo growth math problem disappears because LoCoMo isn't the gate. It's allowed to drift, and the drift is informative (does the simplification help or hurt the recall path?), not a tag-blocker.

## 8. Why this proposal is honest

- It admits Phase 3 and Phase 4 shipped with anti-patterns that the gates didn't catch.
- It refuses to build Phase 5 on top of a regressed Phase 4 (4.1 corrective is non-negotiable).
- It rebinds every gate to the v4 thesis instead of borrowing convenient benchmarks.

- It treats the user's manual pointer-index as the gold standard rather than something to replace.
- It separates writers from consumers and refuses to count writers as "shipped" without their consumers.
- It treats the directive_rule data already in the DB (2 rows, big-mozzy-v2 only) as informative — the detector is barely producing data because the trigger surface is wrong, not because users aren't issuing directives. The PreToolUse design fixes that.
