## §0 — How this proposal differs from the prior draft

The prior draft (synthesized from T1 MEMORY.md audit + T2 directive_rule consumer audit) correctly diagnosed the gate-fit problem and proposed a Phase 4.1 corrective + benchmark-as-sanity reframe. It stopped there.

This proposal extends the diagnosis with three things the prior draft missed:

1. **Benchmarks slipped from instruments into product values** (user's correction): the failure isn't "we picked measurable gates over what we cared about" — it's "we let benchmarks drift from sanity-checks into success-targets, and nobody caught the drift because green numbers feel like progress." **This proposal removes benchmarks from v4 entirely — not as targets, not as sanity floors, not as gates of any kind.** User confirmed 2026-04-27: *"do we really need any benchmarking at all at this point?"* — answer is no. Vesna probes + content-quality scoring + cache-stability tests + real-world soak cover catastrophic-regression detection without the target-creep temptation. Harness stays runnable for a one-shot vibe check at v4 ship; never a gate.

2. **The goal is organic recall, not generic "better memory"** (user's reframe via shadowban example): the agent should think *with* prior experience as part of natural reasoning, not retrieve on command. This is a sharper bar than the prior thesis allowed for, and it has direct mechanism implications (MEMORY.md must index lessons; recall must trigger on task-pattern similarity; Vesna becomes central).

3. **v4 must be a real upgrade, not v3-minus-excess** (user's challenge): of the original 11 phases, 8 are subtractive or hygiene. The agent gains very little new capability. This proposal adds five upgrade phases (4.1, 5.5, 6.5, 7.5, 8.5) plus a Vesna promotion (Phase 10) so v4 is unambiguously an upgrade.

## §2 — The four success criteria

Replacing all benchmark-target language. Falsifiable, mechanical, no targets above floors.

### SC#1 — Behavioral (primary gate)

**Vesna probe suite ≥80% pass rate.** ~20 probes covering recall patterns:

- Entity recall (*"what is the Vesna project?"*)
- Constraint recall (*"what should I avoid when polling backend X?"* — surfaces shadowban)
- Handoff pickup (*"what was last session about?"* — answered without filesystem)
- Cross-project recall (*"have we hit a Cloudflare 429 issue before?"*)
- Lesson application (cross-project: *"this looks like a rate-limit-research task — what do prior similar tasks tell us?"*)
- Self-instrumented gap detection (*"I searched for X, got nothing — going in cold"* — surfaces correctly)

Maintained alongside code, in `src/benchmark/vesna/probes/*.json`. Pass rate measured every PR.

**This is the primary gate.** Falsifies organic recall directly.

### SC#2 — Structural

**Session-start ≤500 tokens, cache-stable across runs.** 3-layer test:

- Tokenizer assertion on actual session-start output.
- Golden snapshot comparison (byte-identical).
- Invariance under volatile-state mutation (clock change, session-ID change, host-env change must not change output bytes).

Hard.

### SC#3 — Index quality

**MEMORY.md content score ≥80% across all 5 active projects.** Mechanical scoring rubric:

- Zero parsing-bug rows (no `entity:-`, no shell fragments).
- ≥80% of pointers carry project-specific salience (not generic nouns like `predictor`, `system`, `prompt`).
- Thread topics are real topics, not session IDs.
- Pointer density ≥1 useful pointer per 10 lines.
- Freshness: handoff section reflects current state (frontmatter `phase` matches `STATE.md`).

Run as CI on every PR for every active project's MEMORY.md.

### SC#4 — Continuity

**One-turn handoff pickup on 3 cold sessions across 3 different projects.** Cold-start session reads handoff + MEMORY.md, acts on first user message without filesystem exploration before first action. Probes the agent's ability to absorb session continuity from the index alone.

### Benchmarks are not used in v4 (locked 2026-04-27)

**LongMemEval, LoCoMo, BENCH-09 are not gates. Not targets. Not sanity floors. Not used at all.**

**Rationale.** Keeping benchmarks "as sanity floors" was the prior draft's compromise. The user pushed past it: *"do we really need any benchmarking at all at this point?"* — and they're right. The half-measure costs compute (LongMemEval ~10h, LoCoMo ~4-6h per run), still creates target-creep psychological pressure, and doesn't catch anything Vesna + content-quality + soak don't already catch. SC#1-#4 cover all the failure modes the benchmarks were meant to detect, more directly.

**What replaces them:**
- Catastrophic retrieval regression → Vesna pass rate craters (SC#1).
- Index-side regression → MEMORY.md content score (SC#3).
- Pre-injection regression → cache-stability + token-budget tests (SC#2).
- Continuity regression → handoff pickup probes (SC#4).
- *Subjective* feel-worse → user's daily use. The user is the regression detector.

**Harness disposition:**
- Stays on disk (`src/benchmark/longmemeval-harness.ts`, `locomo-harness.ts`). Atrophies as code. Not actively maintained.
- Runnable on demand for ad-hoc diagnostic spelunking.
- **Run ONCE at v4 ship** as an archival record entry (*"v4 shipped at LongMemEval X% / LoCoMo Y%"*) — useful for any future "what did v4 cost in retrieval-quality terms" question. Not a gate; the ship doesn't depend on the number.

**All target / floor / sanity language removed** from PROJECT.md, REQUIREMENTS.md, ROADMAP.md, SCOPE.md as part of the rebind execution.

## §3 — Cross-cutting principles

Eight non-negotiables. Every phase is bound by them.

1. **Writers ship with consumers.** A writer that produces rows nothing reads is dead infrastructure. Phase 3's `directive_rule` (2 rows in 5 days, zero consumers) is the canonical anti-pattern. Phase 3 + Phase 10 merge as one shippable unit going forward.

2. **Auto-extraction is fine for factual data, never for cognitive data.** Active-project rotation, file mtimes, session counts — auto-extract. Lessons, mental models, gotchas, themes — these need curation. If you can only get them by counting, they're not worth indexing.

3. **No imperatives in any memory surface.** v4 thesis is correct. Every surface (MEMORY.md, PreToolUse warnings, system-role primes) must be observational. *"Similar prior situation: user wanted Y; outcome was Z"* — never *"Correct approach: always X."*

4. **Index = pointers, body = artifacts.** MEMORY.md is the index. Deeper artifacts live in `~/.claude/projects/<slug>/memory/*.md` and the DB. The index never contains extracted summaries the agent can't act on without a tool call anyway.

5. **Live-fire verification is mandatory for side-effect components.** Static tests are necessary but not sufficient (Phase 4 pattern: 3 inline bugfixes 04-06/07/08 all hit "static tests passed but live was broken"). Every plan that ships a writer or processor must include live-fire verification as a blocking acceptance gate.

6. **Benchmarks are not used in v4.** Not as targets, not as sanity floors, not as gates of any kind. Harness stays runnable on disk for ad-hoc diagnostic and one-shot ship-time record entry. **If a future plan proposes a benchmark gate, this is the failure mode replaying — reject and point at this principle.**

7. **Behavioral probes are the real validation.** Vesna grows from 1 probe to ~20. Runs every PR. SC#1 is anchored on Vesna pass rate.

8. **The user's manual curation is the gold standard.** Lacuna/Oracle/Nexus pointer-indexes work because the user wrote them at /endsession. The auto-curator helps this — easier curation flow, prefill suggestions — never replaces it with frequency-extraction noise.

### Phase 5.5 — Curation feedback loop

**Goal:** pointers earn their place by being used.

**Mechanism:**

- New table: `pointer_recall_log(pointer_id, session_id, retrieved_at, helpful_yn, query)`. Recorded when agent's retrieval surfaces a Lesson/User-Notes pointer.
- At `/endsession`, Angel shows user the pointers retrieved this session in the suggestion flow + asks which were helpful (light tap, not friction).
- Auto-archive: pointer with 0 retrievals in 90d AND `helpful_yn = null` → moved out of MEMORY.md index (artifact preserved in DB).
- Auto-promote: pointer with ≥3 retrievals + `helpful_yn = true` → moved to high-salience top of section.

**Self-corrects** the bias toward generic-noun extraction by closing the feedback loop on usefulness.

**Vesna probe:** "After 30 simulated days, did the high-recall pointer stay while the never-touched one archived?" → validates the lifecycle.

### Phase 6.5 — Cross-project task-pattern recall

**Goal:** the shadowban example works mechanically. Task-similar prior findings surface across projects.

**Mechanism:**

- Query expansion at `claudex_search` time: when query is task-shaped (verb + domain noun, e.g., *"investigate backend X"*), expand to also search cross-project artifacts of `kind ∈ {mental_model, learning, experience_pattern, workspace_fact}` where task-pattern fingerprint matches.
- Task-pattern fingerprint: short tag (e.g., `scraping rate-limits`, `auth flow design`, `live-fire vs static-test`). Auto-classified at write time by Angel's segmentation. Stored as a column on artifacts.
- Cross-project search ranks task-pattern-match high. Bi-encoder cosine + cross-encoder rerank.
- Privacy: **default cross-project ON.** Per user 2026-04-27: *"between you and me there are no secrets ... methodology and knowledge are not [secret]."* Per-project opt-out via CLAUDE.md flag if needed later.

**Surface:** retrieved cross-project lessons surface as observational context (*"prior similar task in project X found Y"*), never as imperatives.

**Vesna probes:** at least 3 cross-project lesson-application probes. (Lacuna lesson applies in Oracle. Mozzart 429 lesson applies in big-mozzy-v2. Etc.)

### Phase 8.5 — Recall observability + self-instrumented agent

**Goal:** agent + user can see what memory did, what worked, what cost.

**Mechanism:**

- **Per-session retrieval log:** every `claudex_search` / `claudex_recall` invocation captured with query, top-k results, which were used in subsequent agent output, token cost.
- **Agent system prompt addition:** when retrieval returns nothing useful, narrate it (*"no prior experience on this — going in cold"*). When retrieval returns gold, narrate it (*"checking shadowban research from Lacuna … found, applying"*). User confirmed at 2026-04-27: visible by default, silent on demand.
- **Visible token cost:** at `/endsession`, *"session-start spent N tokens; recall added M tokens; total memory cost X tokens."* Forces discipline.
- **User-facing observability:** lightweight `claudex why?` (or `/claudex-why`) that shows the retrieval log for the current session. Ad-hoc debugging when retrieval feels off.

**Vesna probes:** "When agent had relevant prior experience, did it surface it during framing?" → validates self-instrumentation.
