Each extractor is a pure function with signature:
```typescript
export function extract{Tool}(
  input: Record<string, unknown>,
  output: Record<string, unknown> | undefined
): ExtractionResult | null
```

Where `ExtractionResult` is defined as a shared type (put in `src/extraction/extractors/types.ts` or inline in each file — your call):
```typescript
interface ExtractionResult {
  title: string;        // {toolName}: {key_detail}, max 120 chars
  content: string;      // Meaningful extracted output, max 2000 chars
  files_modified: string[];  // Affected file paths
}
```

Title format per CONTEXT.md decisions: `{toolName}: {key_detail}`, max 120 chars, truncate with ellipsis via `truncateText(title, 120)`.
Content truncated at 2000 chars via `truncateText(content, 2000)`.

**Per-tool extraction logic:**

**read.ts** — `extractRead`: Title = `Read: {basename(file_path)}`. Content = first 2000 chars of file content from output. files_modified = `[file_path]`. Return null if no file_path in input.

**edit.ts** — `extractEdit`: Title = `Edit: {basename(file_path)}`. Content = old_string → new_string diff summary (show both, truncated). files_modified = `[file_path]`. Return null if no file_path.

**write.ts** — `extractWrite`: Title = `Write: {basename(file_path)}`. Content = first 2000 chars of content from input. files_modified = `[file_path]`. Return null if no file_path.

**bash.ts** — `extractBash`: Title = `Bash: {first 80 chars of command}`. Content = stdout output (or stderr if stdout empty) up to 2000 chars. Include exit code if non-zero. files_modified = `[]` (bash doesn't reliably track files).

**grep.ts** — `extractGrep`: Title = `Grep: {pattern} ({match_count} matches)`. Content = file list + match counts from output, up to 2000 chars. files_modified = matched file paths from output (if available).

**glob.ts** — `extractGlob`: Title = `Glob: {pattern} ({file_count} files)`. Content = matched file list from output, up to 2000 chars. files_modified = `[]`.

**web-fetch.ts** — `extractWebFetch`: Title = `WebFetch: {url}`. Content = status + content summary up to 2000 chars. files_modified = `[]`.

**web-search.ts** — `extractWebSearch`: Title = `WebSearch: {query}`. Content = result count + top results summary, up to 2000 chars. files_modified = `[]`.

**task.ts** — `extractTask`: Title = `Task: {agent description or task name}`. Content = task result/output up to 2000 chars. files_modified = `[]`.

**notebook-edit.ts** — `extractNotebookEdit`: Title = `NotebookEdit: {cell identifier or change type}`. Content = cell changes up to 2000 chars. files_modified = notebook file path if available.

All extractors: non-throwing (return null on unexpected input shape). Use `truncateText` from text-utils.ts. Extract file paths from `input.file_path` or `input.filePath` (handle both conventions).

**src/extraction/extractor.ts** — The pipeline orchestrator. Takes a tool event, runs the full pipeline, stores if it passes.

```typescript
import type { Database } from 'better-sqlite3';

export interface ProcessToolObservationInput {
  db: Database;
  sessionId: string;
  project: string;
  toolName: string;
  toolInput: Record<string, unknown>;
  toolOutput?: Record<string, unknown>;
  projectRoot?: string;  // For path sanitization
}

export function processToolObservation(input: ProcessToolObservationInput): number | null
```

Pipeline steps (Architecture Section 5.1 flow):
1. **Dispatch** to per-tool extractor based on `toolName`. Use a `Record<string, ExtractorFn>` map. If tool not in map, return null (unknown tool, no extraction).
2. **Quality gate**: Call `passesQualityGate(toolName, toolInput, toolOutput)`. If fails, return null.
3. **Extract**: Call the matched extractor function. If returns null, return null.
4. **Redact**: Apply `redactContent(result.content)` to the extracted content. Apply `sanitizePath` to each entry in `files_modified` (using projectRoot if provided).
5. **Classify**: Call `classifyCategory(toolName, result.title, result.content)`.
6. **Score**: Call `scoreImportance(toolName, category, result.content)`.
7. **Dedup check** (Architecture Section 5.5 item 4): Query recent observations — if same tool_name + same first files_modified entry + same category exists within last 5 minutes (300 seconds), skip. Use a simple SQL query: `SELECT id FROM observations WHERE tool_name = ? AND category = ? AND timestamp_epoch > ? AND files_modified LIKE ? LIMIT 1`. If result exists, return null.
8. **Store**: Call `insertObservation(db, { session_id, project, tool_name: toolName, category, title, content, importance, files_modified })`. Return the observation id.

Non-throwing: entire function wrapped in try/catch returning null on error.
