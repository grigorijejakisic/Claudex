7. Inject a JSONL write event for the closed session (set `sessions.last_jsonl_write_ts = now`). Run third tick. Assert exactly 1 `re_opened` env event row, `sessions.status='active'`, cursor `last_close_event_id=NULL`.

**`cursor-replay.test.ts`** — crash mid-tick:
1. Open DB, seed 3 sessions (all idle_timeout candidates).
2. Begin a `runBoundaryTick` but inject a fault: monkey-patch `cursor.commitBoundaryTick` to throw on the SECOND session's commit (after the first commits successfully).
3. Catch the throw at the test boundary; verify session 1 has its `episode_closed` row + cursor advance, session 2 has NEITHER, session 3 was never reached.
4. Restart: call `runBoundaryTick` again with the SAME DB.
5. Assert: session 2 now has its `episode_closed` row, session 3 too. Session 1 has no DUPLICATE row (cursor short-circuit).
6. Assert telemetry contains an `episodic_write_failure` row from the simulated fault AND `episode_close_emitted` rows for sessions 1, 2, 3 (3 total, not 4 — no double-fire on session 1).

This test is the load-bearing proof of the "cursor + env event in single transaction" CONTEXT decision. Without atomicity, restart would either re-fire close on session 1 (cursor advanced but event missing) or never close session 2 (event written but cursor stale).

For the monkey-patch fault injection, use `vi.spyOn(cursorModule, 'commitBoundaryTick')` and have the second invocation throw. Restore after the test.
