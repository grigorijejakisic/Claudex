Two surgical edits in `src/retrieval/transcript-routing.ts`. Read the file first; line numbers below are approximate (verify via grep before editing).

**(a) Null-body coalescing (Gemini Routing #1):**

Locate the `query_text` assembly inside `routeFromArtifact` — the line that picks the text used for the bi-encoder embedding / cross-encoder query. From the Plan 10-01 implementation it looks like:

```ts
const queryText = artifact.query_text ?? candidates[0].body.substring(0, 500);
```

The bug: when `artifact.query_text` is absent AND the first candidate's `body` is NULL (a real possibility for `role='tool'` rows or for chunks where the chunker emitted a NULL body during a degraded ingest path), `.substring(0, 500)` throws.

**Fix — coalesce all the way through:**

```ts
const queryText = (artifact.query_text ?? candidates[0]?.body ?? '').substring(0, 500);
```

Three coalesces stacked: artifact's query_text, candidate's body, empty string. The empty-string fallback means the bi-encoder embedding is taken against `''` — which yields a degraded (zero-similarity) ranking. That's fine; the alternative (throwing) violates the non-throwing contract. The test below proves the path returns a well-formed degraded result.

If your read of the file shows a different shape (e.g., the substring is taken inside `rankWithBiEncoder`), apply the same coalesce-to-empty-string defense at every site that calls `.substring` / `.slice` / `.length` on a body or query_text.

**(b) Telemetry-bypass isolation (Gemini Routing #2):**

Locate the cross-encoder catch block — the section that runs when the `:7439/rerank` fetch fails (timeout, non-2xx, unreachable, empty response). The current shape (from Plan 10-01) likely looks like:

```ts
} catch (err) {
  const reason = classifyRerankerFailure(err);
  incrementRerankerFallbackCounter(db, callerSessionId, reason);
  // fall through to bi-encoder
  return rankWithBiEncoder(queryText, candidates);
}
```

The bug: if `incrementRerankerFallbackCounter` itself throws (DB locked during heavy ingest, telemetry table missing in some V32 fixture variant, etc.), the throw escapes this catch and the user-facing call sees the telemetry-write error as if the routing itself failed.

**Fix — isolate telemetry in its own try/catch:**

```ts
} catch (err) {
  const reason = classifyRerankerFailure(err);
  try {
    incrementRerankerFallbackCounter(db, callerSessionId, reason);
  } catch (telemetryErr) {
    // Telemetry failure must never block fallback. Log to stderr (non-blocking) per
    // hybrid-retrieval's discipline; future hardening can route to a structured logger.
    if (process.env.CLAUDEX_DEBUG === '1') {
      console.error('[transcript-routing] telemetry write failed:', telemetryErr);
    }
  }
  return rankWithBiEncoder(queryText, candidates);
}
```

The bi-encoder fall-through is now reachable on a telemetry failure. Reuse the same isolation if there are other telemetry sites in the file (search for `incrementRerankerFallbackCounter` — there should be exactly one site after this fix).

  <name>Task 2: Switch candidate-fetch SQL to absolute time-distance ordering</name>
  <files>src/retrieval/transcript-routing.ts</files>
  <action>
Locate the `cachedPrepare` SQL inside `routeFromArtifact` that does the candidate fetch. From Plan 10-01 it looks like:

```sql
SELECT id, session_id, turn_index, sub_index, role, body, created_at_epoch_ms
FROM transcript_chunk_v6
WHERE session_id = ?
  AND created_at_epoch_ms BETWEEN ? AND ?
ORDER BY turn_index ASC, sub_index ASC
LIMIT 20
```

**Bug:** When the time window contains more than 20 turn-indexed chunks, `ORDER BY turn_index ASC LIMIT 20` keeps the 20 *earliest* in the window and discards the trailing ones — even if those trailing chunks are temporally closer to the artifact's creation timestamp than the kept ones. For a 4h-wide window with the artifact at hour 2, the 20 closest in time should be those nearest hour 2, not those at hour 0.

**Fix:** Add the artifact's `created_at_epoch_ms` as a fourth bound parameter, change the ORDER BY to `ABS(created_at_epoch_ms - :artifact_ms) ASC`, keep `LIMIT 20`. Update the `cachedPrepare` parameter binding to match (4 binds instead of 3).

Approximate after-shape:

```ts
const stmt = cachedPrepare(
  db,
  `SELECT id, session_id, turn_index, sub_index, role, body, created_at_epoch_ms
   FROM transcript_chunk_v6
   WHERE session_id = ?
     AND created_at_epoch_ms BETWEEN ? AND ?
   ORDER BY ABS(created_at_epoch_ms - ?) ASC
   LIMIT 20`,
);
const rows = stmt.all(
  artifact.session_id,
  artifact.created_at_epoch_ms - windowMsBefore,
  artifact.created_at_epoch_ms + windowMsAfter,
  artifact.created_at_epoch_ms,
) as RawChunkRow[];
```

After the SELECT runs and `rows` is populated, **re-sort by `(turn_index, sub_index) ASC` in JS** before the ranking step. The SQL gets the right *set* of 20 candidates (the temporally-closest); the rerank ordering is what matters for downstream consumers, but if a downstream caller iterates over `spans` and assumes turn order, the in-memory re-sort preserves that ergonomics. Keep the re-sort tiny:

```ts
rows.sort((a, b) =>
  a.turn_index !== b.turn_index
    ? a.turn_index - b.turn_index
    : a.sub_index - b.sub_index,
);
```

**Cache-key concern:** `cachedPrepare` keys on the SQL string; the SQL string changed, so the prepared statement is a new entry. Good — no need to bust an old cache.

**Read the file to confirm there are no other sites that bind into the old 3-parameter SQL** (e.g., a duplicate fetch in `routeFromArtifacts` if the implementation didn't fully delegate to `routeFromArtifact`). If there is, apply the same fix — single source of truth.

  it('returns the 20 chunks closest to artifact.created_at_epoch_ms when window contains 30', async () => {
    const db = makeInMemoryV32Db();
    const artifactTs = 1_700_000_000_000;
    // Seed 30 chunks across a 4h window: 15 before (5min apart) + 15 after (5min apart).
    // Window is ±2h (default), so all 30 are inside the window.
    for (let i = 0; i < 30; i++) {
      const offsetMin = i < 15 ? -(15 - i) * 5 : (i - 14) * 5;
      const ts = artifactTs + offsetMin * 60_000;
      db.prepare(
        `INSERT INTO transcript_chunk_v6 (id, session_id, turn_index, sub_index, role, body, created_at_epoch_ms)
         VALUES (?, ?, ?, ?, ?, ?, ?)`

      db,
      { session_id: 'sess-time', created_at_epoch_ms: artifactTs, query_text: 'q' },
