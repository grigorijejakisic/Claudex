**(b) Native-async end-to-end (Gemini Assembly #2):**

Locate `assembleFullContext` (or whatever the parent assembler entry point is named). Plan 10-02's likely shape — the symptom Gemini caught:

```ts
function assembleFullContext(...): AssemblyPayload {
  // ... sync prep
  const surface = appendDeliberationSurfaceSync(payload, artifacts);
  return surface;
}

function appendDeliberationSurfaceSync(payload, artifacts) {
  // BUG: 'await' inside a sync function — the routing promise becomes fire-and-forget
  routeFromArtifacts(db, artifacts).then((spans) => {
    payload.content += renderSpans(spans);
  });
  return payload;
}
```

The bug: the `routeFromArtifacts` Promise resolves *after* `assembleFullContext` returns — the consumer sees a payload with no transcript surface, the surface mutation lands later (and may corrupt the next call's payload if the same object is reused).

**Fix — make the entire path async:**

```ts
export async function assembleFullContext(...): Promise<AssemblyPayload> {
  // ... sync prep
  const result = await routeFromArtifacts(db, artifacts, opts);
  return appendDeliberationSurfaceToPayload(payload, result, opts);
}
```

`appendDeliberationSurfaceToPayload` itself stays sync — it now receives the resolved `RoutingResult` rather than fetching it. Every caller of `assembleFullContext` must `await` (TypeScript will surface this at compile time when the return type changes from `AssemblyPayload` to `Promise<AssemblyPayload>`). Search for callers via:

```bash

```

Update each caller to `await`. If a caller is itself sync and there is no path to make it async (e.g., a hook that runs in a synchronous CC lifecycle), the caller must NOT call `assembleFullContext` — it should call a sync-bounded variant that skips the surface step. **Do not rebuild the broken async-inside-sync facade — Gemini's review is explicit that the natively-async path is the correct fix; the alternative ("split sync/async paths") is acceptable but only if a sync caller actually exists.** Audit every caller before deciding.

In the most likely case (CC hooks are the sync callers, but they don't actually call `assembleFullContext` — they emit events that Angel processes async), no sync caller exists and the simple fix is to flip everything to `async`. Document the audit result in the SUMMARY.

  <files>src/assembly/deliberation-surface.ts</files>

Locate the greedy-pack loop inside `appendDeliberationSurfaceToPayload`. Plan 10-02's likely shape:

```ts
const cap = Math.floor(assemblyWindowTokens * config.v6.routing.token_pct_cap / 100);
const budget = result.bi_encoder_only
  ? Math.floor(cap * config.v6.routing.bi_encoder_budget_pct / 100)
  : cap;

let used = 0;
const packed: RoutingSpan[] = [];
for (const span of result.spans) {
  const cost = countTokens(span.body);
  if (used + cost > budget) break;
  packed.push(span);
  used += cost;
}
```

The bug (Gemini Assembly #4): `budget` only constrains span content. The actual rendered surface is `header + (separator + spanRender) × packed.length`, all of which contribute tokens that are NOT deducted from `budget`. For a 15%-of-2000-token-window cap = 300 tokens, with a 12-token header and 6-token separator × 12 separators = 84 overhead tokens, the actual surface emits 384 tokens — 28% over the locked cap.

**Fix — pre-deduct overhead before the loop:**

```ts
const cap = Math.floor(assemblyWindowTokens * config.v6.routing.token_pct_cap / 100);
const rawBudget = result.bi_encoder_only
  ? Math.floor(cap * config.v6.routing.bi_encoder_budget_pct / 100)
  : cap;

// Pre-deduct header + separator overhead per Gemini Assembly Finding #4.
// The greedy pack loop must see the *content-available* budget, not the gross cap.
const headerText = result.bi_encoder_only
  ? '## Deliberation Surfaced (low-confidence retrieval)'
  : `## Deliberation Surfaced — ${result.spans.length} spans from ${distinctSessions(result.spans)} sessions`;
const headerTokens = countTokens(headerText);
const separatorTokens = countTokens('\n\n---\n\n'); // whatever existing separator is
// Worst-case overhead: header + N separators where N is the candidate count we'll attempt to pack
const overheadEstimate = headerTokens + separatorTokens * result.spans.length;
const packBudget = Math.max(0, rawBudget - overheadEstimate);

let used = 0;
const packed: RoutingSpan[] = [];
for (const span of result.spans) {
  const cost = countTokens(span.body);
  if (used + cost > packBudget) break;
  packed.push(span);
  used += cost;
}

// After the pack loop, the actual rendered overhead is headerTokens + separatorTokens × packed.length,
// which is ≤ overheadEstimate (since packed.length ≤ result.spans.length). The total surface tokens are:
//   headerTokens + separatorTokens × packed.length + used
// which is ≤ headerTokens + separatorTokens × result.spans.length + packBudget
//        = overheadEstimate + (rawBudget - overheadEstimate)
//        = rawBudget. ✓
```

**Three notes:**

1. The separator-token estimate uses `result.spans.length` (the candidate count, before packing). This is the *worst-case* overhead — packing fewer spans than the candidates implies the actual overhead is smaller, so the surface stays under cap. If the worst-case overhead exceeds `rawBudget` entirely (`rawBudget - overheadEstimate < 0`), `packBudget` clamps to 0, the pack loop returns an empty `packed[]`, and the assembly emits just the header. That's an acceptable degraded path.
2. `countTokens` should be the same util the rest of the assembler uses. If it doesn't exist, use a simple approximation (`text.length / 4`) — the locked default is 15% of an assembly window, the constant factors don't need GPT-grade tokenization to be correct within Gemini's tolerance.
3. Update any inline comment near the loop to cite Gemini Assembly Finding #4 and CONTEXT-decision-3 token_pct_cap (locked at 15%).
