<decisions>
## Implementation Decisions

### Task-pattern fingerprint storage

**Schema addition** to `artifact` table:
```sql
ALTER TABLE artifact ADD COLUMN task_pattern TEXT;
CREATE INDEX idx_artifact_task_pattern ON artifact(task_pattern) WHERE task_pattern IS NOT NULL;
```

**Population**:
- At write time (Angel segmentation), populate `task_pattern` for `kind ∈ {mental_model, learning, experience_pattern, workspace_fact, lesson}`
- Vocabulary is 4.1's `shape_vocabulary` table — Experience Tier doesn't introduce new vocabulary; it consumes the canonical one Angel curates
- Backfill for existing rows: heartbeat task scans existing artifacts and proposes `task_pattern` values; populated only when LLM confidence ≥0.85 (abstain-allowed, same pattern as 4.1)

### HYBRID cross-project content equivalence (LOCKED — design decision from 2026-04-29 session)

Two-stage approach:

**Stage 1 — Fast filter (telemetry-handle overlap):**
- For each candidate artifact pair across projects, count shared telemetry handles (tools_used, files_touched topology, user_framing_tokens, error_types)
- Threshold: ≥3 shared handles → candidate match (proceeds to Stage 2)
- < 3 shared handles → not a match, no further computation

**Stage 2 — Precision check (cosine embedding similarity):**
- For Stage-1 candidates: compute cosine similarity on salience text using existing snowflake-arctic-embed2 (1024d)
- Threshold: cosine ≥0.85 → confirmed equivalent
- 0.70 ≤ cosine < 0.85 → ambiguous; fall through (not surfaced, but logged for tuning)
- < 0.70 → false positive from Stage 1; reject

**Why hybrid:**
- Telemetry-handle alone misses semantic synonyms (`rate-limit` vs `throttling`)
- Embedding alone fires false positives on incidental overlap and is expensive per query
- Stage 1 narrows candidate set cheaply; Stage 2 confirms semantic match precisely

### Experience Tier scorer

**Architecture B (locked from 4.1):**
- Parallel to Critical Reminders Tier
- Shared infrastructure: turn-decay, Leitner advance/reset, variant rotation, budget cap pattern
- Different inputs and triggers
- Different budget (planner picks; recommendation: budget ≤ Critical Reminders budget so behavioral rules win on collision-shaped scoring)

**Scoring (analogous to CR Tier's `assembleCriticalReminders`):**
| Signal | Weight (recommendation, planner tunes) |
|---|---|
| Telemetry-handle overlap with incoming task ≥3 shared | +5 |
| Shape-vocabulary match between artifact's task_pattern and incoming-task-shape | +4 |
| Recency (last_used within 14d) | +2 |
| Helpfulness (Phase 5.5 `helpful_yn=true`) | +2 |
| Cross-project (artifact from different project than current session) | +1 (cross-context is itself a salience signal — kid-stove generalization) |
| Already-injected this session | -10 (no double-fire within session) |

**Top-K selection:**
- Score-rank, take top-K (recommendation: K=3 for Experience Tier; rules tier already takes 5)
- Render as observational context (advisory voice, Phase 7)
- Budget cap (planner specifies; recommendation: 200 tokens per Experience Tier injection)

### `claudex_search` query expansion

**Trigger detection:**
- Query is task-shaped if: contains a verb + domain noun (LLM-classified at MCP server)
- Cheaper alternative for 6.5 v1: regex heuristic on user query for verb-+-noun shape (planner picks)
- LLM-classification is more robust but adds latency; regex is faster but less accurate

**Expansion:**
- For task-shaped queries, fetch project-local results AS NORMAL
- Additionally fetch cross-project artifacts where task_pattern fingerprint matches via HYBRID equivalence
- Merge results: project-local boosted by recency; cross-project boosted by Experience Tier scoring
- Surface to user with project provenance (*"from Lacuna: ...; from Oracle: ...; from current project: ..."*)

### Cross-project surface (advisory voice — Phase 7 alignment)

**Template:**
```
Prior similar task in project {other_project}: {salience_line}.
Decision was {decision}; outcome was {outcome}.
```

**NOT:**
```
WARNING: from Lacuna — always do X.
```

**Reasoning:** cross-project lessons are observations, not commands. The agent reasons WITH them, not against them.

### Default-ON cross-project search (Q10 locked)

- Default behavior: cross-project search active for all projects
- Opt-out: CLAUDE.md flag `claudex.cross_project_search: false` (planner picks exact key syntax)
- When opt-out is set: query expansion skips cross-project fetch; project-local only
- Per-user: between Grigorije and the agent, no secrets — methodology and knowledge are not secret (per locked Q10 rationale from 2026-04-27)
- For projects with confidential content: opt-out available

### Vesna probe coverage (≥3 cross-project lesson-application probes)

**Canonical probes:**
1. **Shadowban from Lacuna → big-mozzy-v2** (the canonical example):
   - Setup: `project_mozzart_cloudflare_429.md` exists in Lacuna with rich telemetry+shape handles
   - Probe: fresh session in big-mozzy-v2, user prompt: *"investigate another backend for intel gathering"*
   - Pass: Mozzart 429 lesson surfaces in agent's working context within first 2 turns; agent narrates *"prior similar task in Lacuna found per-IP rate limit ..."*

2. **Auth-token-expiry across projects:**
   - Setup: feedback/project lessons in 2+ projects about session token expiry behaviors
   - Probe: fresh session in third project, user prompt: *"users keep getting kicked out, can you check"*
   - Pass: cross-project token-expiry lessons surface

3. **Schema-migration patterns across projects:**
   - Setup: lessons about migration safety patterns in claudex-v3 + Lacuna
   - Probe: fresh session in Oracle, user prompt: *"adding a new column to a high-traffic table"*
   - Pass: cross-project migration-safety lesson surfaces; advisory voice

**Lexical-similarity check:**
- For each probe, the user prompt must contain ZERO of the lexical surface tokens from the relevant lesson (no "rate", "limit", "Mozzart", "429", "shadowban", "Cloudflare" in shadowban probe)
- Match must fire on perceptual handles + shape vocabulary, not surface text overlap

<specifics>
## Specific Ideas

### HYBRID equivalence answers two failure modes at once

- Telemetry-only (cheap) misses semantic synonyms across projects — kid stove → oven generalization fails
- Embedding-only (expensive, false-positive-prone) is too noisy at scale
- HYBRID uses each where it's strongest: Stage 1 narrows the search space cheaply; Stage 2 confirms semantically
- This was the locked answer to the deferred question from 4.1

### Cross-project as kid-stove generalization

- 4.1 ships project-scoped substrate. 6.5 ships the cross-project generalization mechanism.
- The kid's burn memory transfers from stove → oven because the abstraction (radiates heat) is project-agnostic
- Telemetry handles are project-agnostic (tools_used, error_types, framing tokens are session-derived not project-derived)
- Shape vocabulary is project-agnostic (canonical vocabulary, Angel curates globally)
- Phase 6.5 surfaces this generalization at retrieval time

### Architecture B applied: parallel tiers stay clean

- Critical Reminders Tier (4.1 + existing) handles RULES from `critical_rules` table
- Experience Tier (6.5) handles EPISODES from `project_*`/`process_*` lessons + cross-project artifacts
- They share infrastructure (TTL, jitter, variants) but compete on nothing
- Each has its own budget; rules don't crowd out lessons or vice versa

### The probe set authored in 4.1 hands forward

- Phase 4.1 deliverable: substrate-validation probe set (perceptual-similarity probes run as unit tests on substrate)
- Phase 6.5 deliverable: same probe set runs as **live-fire test of the Experience Tier**
- This is the substrate-mechanism handoff working as designed

### Encoding-density-matches-salience extends across projects

- Cross-project surface only fires when the incoming task triggers handle/shape overlap
- Routine incoming tasks won't fire cross-project recall — that's the principle
- Salient incoming tasks (genuinely shaped like a past surprise) trigger; mamma's voice from another room when the kid approaches a hot thing

</specifics>
