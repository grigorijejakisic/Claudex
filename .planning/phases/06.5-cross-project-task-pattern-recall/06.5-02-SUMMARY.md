## Task-by-task

### Task 1 — HYBRID cross-project equivalence (commit 66fe3cb, part 1)

`src/core/cross-project-equivalence.ts`:

- **Stage 1** — `stageOneHandleOverlap(a, b)`: total intersect-size across all four handle dimensions (`tools_used`, `files_touched` normalized to basename + parent dir, `user_framing_tokens`, `errors_encountered`). Threshold ≥ 3. Pure function, ~3μs/call.
- **Stage 2** — `stageTwoCosine(salienceA, salienceB, embedder?)`: cosine via injectable embedder (default: snowflake-arctic-embed2 on Ollama /api/embed, 1s timeout). Returns `null` on any failure mode (timeout / non-2xx / empty response / network).
- **Orchestration** — `isCrossProjectEquivalent(a, b, db, sessionId, embedder?)`:
  - Stage 1 fail (`<3 shared`) → `band: 'stage1-fail'`, no Stage 2 call.
  - Stage 2 cosine ≥ 0.85 → `band: 'match'`.
  - 0.70 ≤ cosine < 0.85 → `band: 'ambiguous'`, writes V21 `cross_project_ambiguous` telemetry row via `logAmbiguous`.
  - cosine < 0.70 → `band: 'reject'`.
  - embedder fail (cosine null) → `band: 'reject'`, increments existing `reranker_fallback` telemetry counter (RETR-08 surface, reason='unreachable').
- **Constants exported**: `STAGE_1_THRESHOLD = 3`, `STAGE_2_MATCH_THRESHOLD = 0.85`, `STAGE_2_AMBIGUOUS_FLOOR = 0.70`.

17 unit tests covering Stage 1, Stage 2, orchestration, and exact boundary conditions (cosine = 0.85 → match, cosine = 0.70 → ambiguous).

### Task 2 — tier-utils.ts extraction + Experience Tier + assembler wire-in (commit 66fe3cb, part 2)

`src/intelligence/tier-utils.ts`:

- `shouldInjectArtifact(artifactId, lastInjected, currentTurn, baseTtl, currentTtl, jitterKey?)` — generic TTL+jitter helper using `id * 13 + currentTurn` deterministic dispersion.
- `advanceTTL(currentTtl, baseTtl)` and `resetTTL(baseTtl)` — pure TTL math (no SQL).
- `renderObservationalVariant(variants, idx, fallback)` — modulo-rotation with empty-array fallback.

`src/intelligence/critical-reminders.ts`:

- `shouldInjectRule(rule, turnNumber)` is now a thin wrapper around `shouldInjectArtifact`. Identical algorithm — same dispersion constant (13), same per-drift-risk JITTER_RANGES values now centralized in tier-utils.
- `renderRuleVariant(rule, count)` delegates rotation to `renderObservationalVariant`. JSON parsing remains here (variants are stored as JSON in `critical_rules.variants`).
- SQL-level `advanceTTL(db, ruleId)` / `resetTTL(db, ruleId)` retain their critical_rules-specific UPDATE logic; the math in tier-utils is unused by them but exposed for Experience Tier.
- 50/50 existing critical-reminders tests still pass (refactor-no-regression).

`src/intelligence/experience-tier.ts`:

- `assembleExperienceTier(db, sessionId, turn, project, incomingHandles, ctx?)`:
  - **Candidate query**: artifacts of relevant kinds (`learning`, `observation`, `memory_file`, `flow`, `milestone`) JOINed to `artifact_task_pattern` where `task_pattern != '__abstain__'` AND `project != currentProject`. Bounded pool of 200 ordered by recency.
  - **Scoring** per LOCKED weight matrix (CONTEXT.md):
    
    | Signal | Weight |
    |---|---|
    | Stage-1 telemetry-handle overlap ≥3 with current incoming | +5 |
    | Shape-vocab task_pattern match against inferred incoming | +4 |
    | Recent (within 14 days) | +2 |
    | Helpful (Phase 5.5 `helpful_yn = 1`) | +2 |
    | Cross-project (always +1) | +1 |
    | Already injected this session (`session_events.experience_tier_injected`) | -10 |
  - **Top-K = 3**; tie-break `(score DESC, id ASC)` for cache stability.
  - **Budget cap**: `scaleBudget(200, contextWindowTokens)`; trim from bottom; return null if even one candidate exceeds.
  - **Deferred `applyEffects`**: writes `session_events` rows for each injected artifact_id at commit time, not at scoring time. Cache stability preserved.

`src/assembly/sections.ts`:

- `formatExperienceTierSection(items)` — LOCKED template `"## Experience\n- Prior similar task in project X: salience. Decision was D; outcome was O."`. Advisory voice; helpers `extractSalienceLine` / `extractDecisionLine` / `extractOutcomeLine` parse explicit `Decision:` / `Outcome:` lines from artifact body, fall back to `(decision unavailable)` / `(outcome unavailable)`.

`src/assembly/assembler.ts`:

- **P4.06 wire-in** between Critical Reminders (4a.5) and Codebase Index (4a.7) in `assembleRegularPrompt`. Calls `assembleExperienceTier`, gates on budget, composes with prior `commitFn` so both tiers' `applyEffects` fire together.

## Deviations from Plan

**[Rule 4 — Architectural avoidance, kept implicit] Embedder failure telemetry**

- Plan called for `'embedder_unreachable_for_equivalence'` reason on the existing `reranker_fallback` event_kind. The existing `RerankerFallbackReason` union is `'unreachable' | 'non_2xx' | 'timeout' | 'empty_response'` — no `'embedder_unreachable_for_equivalence'` value.
- Decision: reuse `'unreachable'` since the equivalence-path embedder failures (timeout, non-2xx, network) all collapse to the same operational signal (reranker degraded path). The detail-field-encoded discriminator that was implied by `'embedder_unreachable_for_equivalence'` would have required either widening the type union (adding a fifth value) or adding a sub-detail JSON key. Both options were architecturally larger than the plan implied.
- Action taken: reused existing `'unreachable'` reason value and added an inline comment explaining the choice. No code-shape change required.
- Verification: `cross-project-equivalence.test.ts` "embedder failure → reject band; logs reranker_fallback telemetry" passes.

**Total deviations:** 1 (Rule 4-shape, kept inline). **Impact:** zero correctness loss; preserves type-system tightness. The widening to a dedicated equivalence-failure reason is a Phase 8 follow-up if the bi-encoder fallback path needs per-call-site discrimination.
