Walk `~/.claude/projects/**/*.jsonl`, enumerate every session JSONL across every project, and enqueue each one via `enqueueSessionIngestion` from plan 08-03. 2. **Reranker fitness check** (CONTEXT decision 4). Sample 50 transcript chunks; for each: pick a query (use the chunk's session topic or a representative shape from the surrounding sessions), score the cross-encoder top-3 vs bi-encoder top-3, compute overlap. Pass criterion: ≥60% mean top-3 overlap. Below threshold = NOT a ship blocker — it informs P9's reranker default. Write one row to `telemetry` with `event_kind='reranker_fitness_check_completed'` and a markdown report under `context/measurements/2026-XX-XX-reranker-fitness.md` for the operator to inspect.

Both CLIs are operator gestures — Angel does NOT auto-run them. Backfill is multi-hour, expensive Ollama load; the operator chooses the moment. Fitness check needs ingested chunks to sample from — it's run after backfill seeds the corpus.

```ts
import type { Database } from 'better-sqlite3';
import { EmbeddingProvider } from '../embeddings/embedding-provider.js';
// reuse the BGE cross-encoder client used by hybrid-retrieval. Path:
// inspect src/intelligence/hybrid-retrieval.ts to find the existing
// fetch wrapper around port 7439 (RerankerSupervisor + cross-encoder
// scoring). Extract or duplicate the smallest possible interface —
// scoreCrossEncoder(query, candidates) → number[] in [0,1].

export interface FitnessReport {
  sample_size: number;
  mean_top3_overlap: number;          // 0..1 — fraction of cross-encoder top-3 also in bi-encoder top-3
  pass: boolean;                       // true if mean_top3_overlap >= 0.60
  reranker_url: string;
  reranker_reachable: boolean;         // false → fitness check skipped, fallback recommended
  per_query: Array<{
    query: string;
    cross_top3: string[];              // chunk ids
    bi_top3: string[];
    overlap: number;                   // |intersection| / 3
  }>;
}

export async function computeRerankerFitness(
  db: Database,
  sampleSize?: number,                 // default 50 per CONTEXT decision 4
): Promise<FitnessReport> {
  // 1. Pick `sampleSize` chunks at random from transcript_chunk_v6
  //    (use ORDER BY RANDOM() LIMIT N — rare enough at 50 to be cheap).
  // 2. For each chunk, derive a query: use the chunk body's first
  //    sentence (up to 200 chars) as a synthetic query. Cheap. Better
  //    queries are P9's job; this is sanity-only.
  // 3. Build candidate pool of 20 chunks per query: 1 truth chunk
  //    (source) + 19 random other chunks.
  // 4. bi_top3 = arctic-embed2 cosine (use sqlite-vec KNN; fall back to
  //    JS cosine if vec0 KNN is the wrong granularity for 20 candidates)
  // 5. cross_top3 = BGE-v2-m3 scores (use existing reranker client)
  // 6. overlap = |intersection of cross_top3 and bi_top3| / 3
  // 7. Return FitnessReport with mean_top3_overlap, pass = mean >= 0.60.
  // 8. Write one telemetry row of event_kind='reranker_fitness_check_completed'
  //    with detail = { sample_size, mean_top3_overlap, pass }.
}
```

Reachability: if the BGE cross-encoder service is unavailable (3s timeout — same shape as `hybrid-retrieval.ts`'s fallback path), set `reranker_reachable=false` and return a degenerate report (no per_query data). Print a clear message to stderr in the CLI: "Reranker unreachable — fitness check skipped. P9 should default to bi-encoder-only retrieval per CONTEXT decision 4."

Pass-criterion behavior: report it, don't gate. The 60% threshold is the empirical guidepost — below threshold means P9 uses bi-encoder-only as baseline, NOT that the substrate fails.
