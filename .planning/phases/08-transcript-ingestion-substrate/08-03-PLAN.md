<objective>
Wire the substrate from plan 08-02 into the live boundary-close pipeline (Phase 6's atomic `clean_endsession` close marker) so that every clean session close — and every Angel-promoted crash-killed session — triggers transcript ingestion. CONTEXT decision 5 lock: ingestion fires only on `clean_endsession` events. Crash-killed sessions still ingest, but only after Phase 6's idle-sweep has promoted them via `emitCleanEndsessionClose` — partial ingestion is rejected to keep the P9 measurement corpus clean.

Per CLAUDE.md hook safety rules, the CC hook MUST NOT do any LLM/embedding work synchronously. The pattern matches Phase 4.1's `transcript-chunker.ts` design where the heavy work runs from Angel's heartbeat. Two-step:

1. **Enqueue at boundary close** — the hook (or Angel boundary-detector) inserts a `session_events` row of type `transcript_ingestion_pending` with the session_id + project + jsonl_path. The enqueue is fast (single SQLite INSERT, no I/O beyond DB), so awaiting it does not block the hook's return path.
2. **Drain in Angel's heartbeatTick** — heartbeat picks up pending rows (LIMIT N per tick), runs `ingestSession` synchronously per session inside the tick, and marks the row processed when done. Per-session try/catch — one bad session never blocks others.

`ingestSession` does the work: parse the JSONL into JsonlTurn[], call `chunkTranscript` (08-02), for each chunk call `EmbeddingProvider.embed(body)` to get the 1024-dim arctic-embed2 vector, call `upsertChunk` (08-02) to land the metadata row, then INSERT into `vec_transcript_chunks_v6` keyed by the metadata row's rowid. The `setVectorStoreDb` + sqlite-vec-backend pattern at `src/embeddings/sqlite-vec-backend.ts` is the model.

Output: enqueueSessionIngestion + ingestSession exported from `src/ingestion/ingest-session.ts`; SessionEnd hook calls enqueue immediately after `emitCleanEndsessionClose` returns; Angel boundary-detector calls enqueue in its clean_endsession-promoted branch; Angel heartbeat consumes the queue. End-to-end integration test asserts all four legs.

```ts
// Phase 8 — drain transcript ingestion queue
try {
  const pending = cachedPrepare(ctx.db,
    `SELECT id, session_id, project, detail
       FROM session_events
      WHERE event_type = 'transcript_ingestion_pending'
        AND (json_extract(detail, '$.processed') IS NULL
             OR json_extract(detail, '$.processed') != json('true'))
      ORDER BY id ASC
      LIMIT 5`
  ).all() as Array<{ id: number; session_id: string; project: string; detail: string }>;

  for (const row of pending) {
    try {
      const detail = JSON.parse(row.detail);
      const jsonlPath = detail.jsonl_path ?? resolveJsonlPath(row.session_id, row.project);
      if (!jsonlPath) continue; // skip silently — Phase 6 idle-sweep eventually retries
      const result = await ingestSession(ctx.db, row.session_id, row.project, jsonlPath);
      result.transcripts_ingested = (result.transcripts_ingested ?? 0) + 1;
      // Mark processed in the queue row
      cachedPrepare(ctx.db,
        `UPDATE session_events
            SET detail = json_set(detail, '$.processed', json('true'),
                                  '$.chunks_written', ?,
                                  '$.embeddings_written', ?)
          WHERE id = ?`
      ).run(result.chunksWritten, result.embeddingsWritten, row.id);
    } catch (err) {
      // Per-session try/catch — one bad session never blocks others
      emitErrorTelemetry(ctx.db, row.session_id, 'heartbeat/ingest-session', err);
    }
  }
} catch {
  // Non-critical — ingestion drain failure does not break heartbeat
}
```

LIMIT 5 — same conservative budget the existing pattern-extraction phase uses. Per-session try/catch is the existing heartbeat discipline. Mark `processed: true` in the JSON detail to avoid re-picking the same row.
