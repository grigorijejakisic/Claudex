<objective>
Canonicalize all epoch shapes to **milliseconds** across the substrate. Today three shapes are in active use (`*_epoch_ms`, `*_epoch`, ISO 8601), and Phase 13.1 Fix #6 (the freshness floor) reads ms but converts to seconds for the checkpoint loader because checkpoint_meta uses seconds. The mix invites silent bugs (one was caught during this session's Fix #6 implementation when checkpoint_meta.created_at_epoch (sec) was passed as ms to the loader, off by 1000×). One canonical unit eliminates the conversion-error class entirely.

Deliverables:
- DB migration that renames every `*_epoch` column to `*_epoch_ms` and scales values by 1000.
- New `src/core/epoch.ts` with typed conversion helpers.
- Caller sweep across the touched files.
- Lesson-frontmatter migration tool for the on-disk Phase 4.1 lesson files.

This is the **largest plan in Wave 1** by file count. The migration itself is one transactional step but the caller sweep crosses many files.

| What this plan provides | Why |
|---|---|
| All-ms DB schema | One canonical unit; no off-by-1000 bugs |
| `epoch.ts` typed helpers | Replaces ad-hoc Math.floor(x/1000) idioms |
| Lesson-file migration tool | On-disk lesson frontmatter aligns with DB |
| Reverse migration | Rollback path |
| Comprehensive caller sweep | Production code uses one shape |
</objective>

Create the new helper module. Public API:

```typescript
export function nowMs(): number;
export function nowSec(): number;
export function toMs(value: number, fromUnit: 'ms' | 'sec'): number;
export function toSec(value: number, fromUnit: 'ms' | 'sec'): number;
export function fromIso(iso: string): number;          // returns ms

export function isMs(value: number): boolean;          // heuristic: value >= 1e12
```

All helpers throw on invalid input:
- NaN, Infinity, negative numbers throw `RangeError`
- Non-string in fromIso throws `TypeError`
- Unparseable ISO throws `RangeError`

The `isMs` / `isSec` heuristics are for guarding callers that consume potentially-mixed data during the migration window. Both throw on values < 1e9 (pre-2001) since no production data is that old.

2. UPDATE table SET <new>_ms = <new>_ms * 1000 WHERE <new>_ms IS NOT NULL AND <new>_ms < 1e12 (the WHERE guard prevents double-scaling if a row already has ms-precision)

Wrap the entire migration in a transaction. If any table fails, roll back the whole migration (DDL operations in SQLite are transactional except for some catalog ops; document the limit).

Reverse migration `migrateV35toV34`:
1. ALTER TABLE ... RENAME COLUMN <new>_ms TO <old>
2. UPDATE table SET <old> = <old> / 1000
3. Drop + recreate indexes/triggers in opposite direction
4. Defaults reverted to unixepoch()
