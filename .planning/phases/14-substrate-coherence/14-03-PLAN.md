<objective>
Centralize the "is this artifact substantive?" question into one predicate (`isSubstantive`) used at every site that asks. Replace experience-tier's permissive observation-allowing candidate query with the new SQL clause. Re-measure the cross-project hit-rate to confirm the 84% noise rate measured today drops below 20%.

The need: today's `2026-05-15-cross-project-equivalence-hit-rate.md` measurement showed N=100 samples produced 83 noise injections (`Read: file.ts`-shaped tool-call observations) and 17 substantive but-irrelevant (claudex-v3 self-knowledge). 0 of 100 surfaced anything domain-relevant to the target session. Root cause: `fetchCandidatePool` in `experience-tier.ts` includes `artifact_type='observation'` rows because observations have a `task_pattern` classification regardless of substance.

Fix shape:
- Pure predicate `isSubstantive(artifact)` + matching SQL clause `substantiveSqlClause(tableAlias)`
- Lockstep test ensures JS + SQL agree on every fixture row
- Apply to experience-tier candidate pool first; sweep other ad-hoc filters
- Re-measure to verify the noise drops

| What this plan provides | Why |
|---|---|
| One predicate, one SQL clause | No more N ad-hoc "is this noise?" checks across the substrate |
| JS ↔ SQL lockstep enforced by tests | Drift becomes a test failure, not a silent retrieval mistake |
| Re-measurement attached to AC-3 | The fix is gated on observable noise reduction, not on code review |
</objective>

Create the new module. Public exports:

```typescript
export interface ArtifactSubstanceShape {
  artifact_type?: string;  // legacy artifacts table
  kind?: string;            // V17 artifact table
  summary?: string;
  importance?: number;
}

export const SUBSTANTIVE_TYPES_LEGACY: ReadonlySet<string>;
export const SUBSTANTIVE_KINDS_V17: ReadonlySet<string>;
export const NOISE_PREFIX_REGEX: RegExp;

export function isSubstantive(artifact: ArtifactSubstanceShape): boolean;
export function substantiveSqlClause(tableAlias: string): string;
```

JSDoc with the rule list from must_haves. Make NOISE_PREFIX_REGEX exported so callers can compose it with their own filters if needed.

`isSubstantive` returns true iff:
1. artifact_type IS in SUBSTANTIVE_TYPES_LEGACY (learning, decision, memory_file, flow, milestone, entity_summary, handoff) OR kind is in SUBSTANTIVE_KINDS_V17 (matching set + mental_model, directive_rule, critical_rule, angel_opinion, experience_pattern, learning, decision)
2. OR (artifact_type === 'observation' OR kind === 'observation') AND importance >= 4 AND (summary?.length ?? 0) >= 60
3. AND summary does NOT match NOISE_PREFIX_REGEX

For unknown artifact_type/kind: returns false (conservative default).

`substantiveSqlClause(tableAlias)` returns a string SQL fragment that produces the same boolean WHERE-clause result, bound to the supplied alias. Use parameterless SQL only — no values to bind. Documented in JSDoc that callers are responsible for the parens nesting in their query.

<risks>
- **Risk 1: JS ↔ SQL drift.** The two implementations of the predicate must agree exactly. Mitigation: lockstep test in Task 3 enforces equivalence on every fixture row. Adding new substantive types requires updating both sides + a fixture row.
- **Risk 2: Noise rate doesn't drop below 20%.** Could mean the predicate is too permissive, the lockstep is broken, OR there's another candidate path bypassing the filter. Mitigation: AC-3 gates ship; failure mode is a PM-escalation, not a fix-the-test workaround.
- **Risk 3: Loosening retention-sweep's filter accidentally.** If retention-sweep currently has a stricter filter and the worker mistakenly weakens it, low-importance noise survives retention. Mitigation: truth #6 + AC-9 require documenting any stricter filter explicitly.
- **Risk 4: experience-tier scoring depends on the noisy observations being present.** Possible if the scoring algorithm normalizes against pool size. Mitigation: Task 4 verification includes manual trace; if scoring breaks, surface in SUMMARY.md with a follow-up plan.
- **Risk 5: NOISE_PREFIX_REGEX is too aggressive.** A legitimate artifact summary that happens to start with "Read: " (e.g., a learning titled "Read: how to interpret deprecation warnings") would be misclassified. Mitigation: the regex requires `:` immediately after the verb (no space variant) — narrow false-positive surface. Document in JSDoc.
</risks>
