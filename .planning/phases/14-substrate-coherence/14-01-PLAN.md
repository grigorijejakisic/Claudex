<objective>
Two deliverables in one plan:

1. **`src/scripts/migrate-handoff.ts`** — operator-driven CLI that takes any project's handoff file (canonical, claudex/handoff v1, or other shape) and rewrites it as the canonical schema, preserving operator body content verbatim and embedding legacy frontmatter as comments. Idempotent on canonical input. Refuses on ambiguity rather than guessing.

2. **`parseHandoffHeader` telemetry-on-rejection** — when the parser returns null, a `handoff_parse_failed` telemetry row records WHY. Today the parser fails silently; the substrate-readout test couldn't tell whether a missing handoff line in MEMORY.md meant "no handoff exists" or "handoff exists but parse rejected it." This makes that distinction observable.

Together: when an operator opts in via the migrator, every project's handoff becomes visible to the assembler (P2.5), the regenerator (MEMORY.md `## Handoff`), the prime (INJ-06), and Fix #6's freshness floor. When they don't, they get an explicit telemetry signal explaining why their handoff isn't surfacing — instead of silent loss.

| What this plan provides | Why |
|---|---|
| Canonical schema enforced at single read site (`parseHandoffHeader`) | One contract, not pluggable schemas |
| Migration tool with body-preserving inference | Existing operators don't lose work |
| Telemetry on rejection | Silent failure becomes observable |
| big-mozzy-v2 ACTIVE.md proven migratable | Cross-project case validated |
</objective>

  <name>Task 1: Add telemetry-on-rejection to parseHandoffHeader</name>
  <files>src/angel/handoff-writer.ts</files>
  <action>
Wrap the existing `parseHandoffHeader` so its null-return paths optionally emit a telemetry row. Two design constraints:

1. Existing callers must not change. The exported `parseHandoffHeader(raw: string): HandoffHeader | null` signature stays. Callers that don't pass a db get the current behavior (silent null).

2. Add an overload `parseHandoffHeader(raw: string, opts: { db?: Database; sessionId?: string; sourcePath?: string }): HandoffHeader | null`. When opts.db is supplied, every null-return path emits one telemetry row before returning null:
   - `event_kind='handoff_parse_failed'`
   - `detail` JSON: `{ reason, source_path }` where reason is one of:
     - `no_frontmatter` — no `---\n...\n---\n` block
     - `missing_status` — frontmatter present but no status field
     - `invalid_status` — status present but not in {active, archived, paused}
     - `missing_phase` — frontmatter present but no phase field
   - `session_id` from opts.sessionId (or empty string)
   - `adapter='handoff-parser'`

Implementation: extract the parsing logic into a non-exported helper `parseHandoffHeaderInner(raw): { header: HandoffHeader | null; reason?: string }` that returns both the header AND the reason on failure. The exported overload then conditionally writes telemetry.

Telemetry write is wrapped in try/catch; failure to write is non-fatal (the parse return value is unaffected).
  </action>

- Existing single-arg callers compile and behave identically.
- The overloaded form with db emits a telemetry row on each rejection reason.
- The reason field is correct per failure mode.
- A passing parse emits NO telemetry row.

<task type="auto">
  <name>Task 2: Build src/scripts/migrate-handoff.ts CLI</name>
  <files>src/scripts/migrate-handoff.ts</files>
  <action>
Create a new CLI script. Top-level shape:

```typescript
/**
 * Phase 14 Plan 14-01 — handoff schema migrator.
 *
 * Reads <projectDir>/context/handoffs/ACTIVE.md and rewrites it as the
 * canonical handoff-writer.ts schema. Idempotent on canonical input.
 * Refuses on inference ambiguity. Operator-invoked.
 *
 * Usage:
 *   bun src/scripts/migrate-handoff.ts <projectDir> [--dry-run] [--phase <p>] [--epoch-ms <ms>] [--file <name>]
 *
 * Exit codes:
 *   0 — migrated OR idempotent_noop OR dry-run-success
 *   1 — inference failed, missing required input, or refused
 *   2 — IO error (file unreadable, write failed)
 */
```

Function decomposition:

- `parseArgs(argv: string[]): MigratorArgs` — strict; rejects unknown flags.
- `readInput(filePath: string): string` — fs.readFileSync, throws on missing.
- `extractFrontmatter(raw: string): { fm: Record<string, string>; body: string; bounds: [number, number] | null }` — uses the same shape as handoff-writer.ts L100-138 but returns ALL frontmatter fields, not just canonical ones.
- `inferCanonicalFields(fm, body, args): { status; phase; summary?; topic?; createdAtEpochMs }` — applies the inference rules from must_haves.truths. Throws on inference failure with explicit reason.
- `extractCanonicalBody(body: string): { whatWeFound; whatWeDecided; whatsNext; whereToLook }` — looks for the locked schema markers (`**What we found:**` etc.). When absent, falls back to a single best-effort placeholder pulling from H1 + first paragraph; the rest of the body is preserved as a `## Preserved Body` section appended to the canonical body.
- `serializeLegacyComments(fm: Record<string, string>): string` — emits non-canonical frontmatter fields as `<!-- legacy-frontmatter: <key>: <value> -->` lines.
- `renderMigrated(canonical, legacyComments, preservedBody): string` — invokes handoff-writer.ts `renderHandoffMarkdown`, then injects the legacy comments and preserved body section.
- `atomicWrite(filePath: string, content: string): void` — tmp + renameSync, same pattern as handoff-writer.writeHandoff.
- `main(): Promise<number>` — dispatcher. Returns exit code.

The `--file` flag overrides the default filename `ACTIVE.md` (so operator can run on `ACTIVE-agent2.md`).

Verbose stderr output for each refusal reason. Single-line summary on success: `migrated: <path> (phase=X, epoch_ms=Y)` or `idempotent_noop: <path>`.
  </action>
  <verification>
- CLI exits 0 on idempotent input.
- CLI exits 0 on successful migration.
- CLI exits 1 on inference failure.
- CLI exits 2 on IO error.
- Migrated output round-trips through `parseHandoffHeader` cleanly.
- Body content preserved byte-for-byte (modulo the canonical wrapping).
  </verification>

- **Risk 2: Body preservation drift.** "Verbatim" is hard to define when the canonical body is rewritten with new section markers. Mitigation: `## Preserved Body` section is the dump-everything-original sink; the canonical fields are best-effort fillers, not lossy transforms.
- **Risk 3: Telemetry write failure cascades into parser failure.** Mitigation: try/catch wrapping; null/header return is decided BEFORE the telemetry write.
- **Risk 4: Operator runs migrator against the wrong project.** Mitigation: dry-run is the default mode in the documentation; live mode requires operator-supplied path. No auto-run.
- **Risk 5: claudex-v3's own ACTIVE.md is already canonical and the migrator should be a no-op there.** Mitigation: idempotency test with claudex-v3-shaped fixture; AC-3 enforces.
