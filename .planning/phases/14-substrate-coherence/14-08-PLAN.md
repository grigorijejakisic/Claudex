<objective>
Make `renderSessionContinuity` enumerate every `ACTIVE*.md` file in the project's handoffs directory and render each as its own Session Continuity block, tagged by agent. The operator's multi-agent work (e.g. big-mozzy-v2's `ACTIVE.md` + `ACTIVE-agent2.md`) is currently invisible at session-start because the assembler reads only `ACTIVE.md`.

This is the smallest Wave 1 plan. Pure code, single file, single function. No schema changes. No new dependencies. Back-compat is the load-bearing constraint — single-file ACTIVE.md projects (claudex-v3 today) must produce byte-identical output to before.

| What this plan provides | Why |
|---|---|
| `renderSessionContinuity` reads `ACTIVE*.md` glob | Multi-agent operators get all handoffs surfaced |
| `### Agent <id>` block prefix | Distinguishable in injection |
| Filename-derived agent tag | Zero new schema; operator just names files `ACTIVE-foo.md` |
| Oldest-first truncation when over budget | Stable behavior; deterministic across runs |
| Byte-identical single-file path | No regression for existing projects |
</objective>

<task type="auto">
  <name>Task 1: Add file enumeration helper to sections.ts</name>
  <files>src/assembly/sections.ts</files>
  <action>
Add a private helper `listHandoffFiles(handoffsDir: string): Array<{ path: string; agentId: string | null; createdAt: number }>` near the top of the existing `renderSessionContinuity` block. The helper:

- Returns empty array if `handoffsDir` doesn't exist (non-throwing).
- Uses `fs.readdirSync(handoffsDir)` and filters by the regex `^ACTIVE(?:-([a-z0-9][a-z0-9_-]*))?\.md$`.
- For each match, reads the file via `fs.readFileSync` + `normalizeText`, parses via `parseHandoffHeader`. Files that fail to parse are skipped (returns nothing for them).
- For each parsed file, returns:
  - `path`: absolute path
  - `agentId`: the regex capture group, or `null` for the literal `ACTIVE.md`
  - `createdAt`: `header.created_at_epoch_ms ?? 0`
- Sort order: untagged (`agentId === null`) first; remainder sorted by `agentId` ASC.

The helper is non-exported (file-local). Tests reach it indirectly through `renderSessionContinuity`.
  </action>
  <verification>
- Helper compiles.
- A directory with `ACTIVE.md`, `ACTIVE-agent2.md`, `ACTIVE-frontend.md` returns 3 entries in order: untagged, agent2, frontend.
- A directory with `ACTIVE-Foo.md` (uppercase agent) returns 0 entries.
- A directory with `ACTIVE-.md` (empty agent) returns 0 entries.
- A directory that doesn't exist returns 0 entries (non-throwing).
  </verification>
</task>

<task type="auto">
  <name>Task 2: Rewrite renderSessionContinuity to render multi-block</name>
  <files>src/assembly/sections.ts</files>
  <action>
Restructure `renderSessionContinuity` so the file-read happens via the new helper, then iterate:

1. If the helper returns 0 entries → return null (back-compat with current "no handoff" behavior).
2. If the helper returns 1 entry:
   - If `agentId === null` (the literal `ACTIVE.md`): render exactly as today. Output is byte-identical to the pre-change path.
   - If `agentId !== null` (somehow the only handoff is agent-tagged): render with the agent header `### Agent <id>` prefix.
3. If the helper returns N > 1 entries:
   - Render each as a separate block. Each block starts with `### Agent <agentId>` (untagged renders without the header — back-compat for the primary handoff).
   - Each block contains: status line, topic, summary, what's-next, where-to-look, operator gates — exactly as today's single-file path renders.
   - Concatenate blocks with `\n\n` between.
   - Wrap the whole thing in the single `## Session Continuity` heading at the top (one heading, multiple `### Agent` sub-blocks).

Truncation when over the 1200-char cap (post-wrap):
- If 1 block over cap: existing truncation behavior (truncate the block's text).
- If N > 1 blocks over cap: drop the oldest-by-`created_at_epoch_ms` block, retry. Repeat until under cap or only 1 block remains. The remaining single block then truncates if still over cap.

Keep the existing `wrapFileContent` data-boundary wrapper. Only the `source` label changes from `'session-continuity (ACTIVE.md)'` to `'session-continuity (ACTIVE*.md)'`.
  </action>
  <verification>
- Single-file ACTIVE.md renders byte-identical to current behavior (regression test must pass).
- Two handoffs render two `### Agent` sub-blocks under one `## Session Continuity` heading.
- Order: untagged first, then sorted by agentId ASC.
- Over-cap with 3 handoffs drops the oldest (lowest `created_at_epoch_ms`) first.
- Operator Gates from each handoff render under that handoff's block, never cross.
  </verification>
</task>

<risks>
- **Risk 1: Cache stability (CACH-02) regression.** The new file-enumeration is filesystem-order-dependent on some platforms. Mitigation: explicit sort by `agentId` ASC after the untagged-first promotion. Test coverage required.
- **Risk 2: Single-file path drift.** Refactoring the function risks subtle output changes for the single-file case. Mitigation: AC-5 byte-identical regression test against a hardcoded expected string.
- **Risk 3: Over-budget logic edge case when N=1 and still over cap.** Existing in-block truncation must apply. Mitigation: explicit test case, code path traced.
- **Risk 4: Filename regex too permissive on Windows.** NTFS is case-insensitive at the FS layer; `ACTIVE-Foo.md` may resolve to the same file as `ACTIVE-foo.md`. Mitigation: regex check on the literal filename string returned from readdir; treat as filter, not as filesystem assertion.
</risks>
