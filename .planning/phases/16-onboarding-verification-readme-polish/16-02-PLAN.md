# Plan 16-02: Onboarding fixture runbooks — macOS + Linux

## Objective

Create two operator-runnable runbooks at `docs/onboarding/macos.md` and `docs/onboarding/linux.md`. Each lists every step a stranger executes from a fresh VM through a working Claudex session, with autonomous content for everything we can ship without operator presence (commands shipped in Phase 14 / 15, upstream installer URLs, expected post-install state) and `[OPERATOR FILL-IN]` placeholders for everything that requires running the install on a real Mac / Ubuntu VM (friction, elapsed time, exact CLI output).

This is the structural autonomous half of VER-01 and VER-02. Plans PLAT-06 and PLAT-07 (the actual fresh-VM runs) are HITL-deferred and gate the full close — they do NOT block Phase 16's structural close (per `16-CONTEXT.md` plan_authorization, same pattern as Phase 11 SC#4 cold-start trials).

## Why this comes after 16-01

Both fixtures cross-link to README §Troubleshooting (anchor created by Plan 16-01) for friction triage. Authoring fixtures first would mean a forward-link to a section that doesn't exist yet. Plan 16-01 lands the anchor; Plan 16-02 references it.

## Step-by-step

### 1. Install Bun

**Command (autonomous):**
```bash
curl -fsSL https://bun.sh/install | bash
```
Then restart your shell or `source ~/.zshrc` (or `~/.bash_profile`) so `bun` lands on `PATH`.

**Expected (autonomous):** `bun --version` prints a version `>=1.3`.

**Friction:** [OPERATOR FILL-IN: any prompts, PATH issues, certificate errors, did you have to install Xcode CLI tools first?]

**Elapsed:** [OPERATOR FILL-IN: MM:SS]

### 2. Install Ollama

**Command (autonomous):**
Download the `Ollama-darwin.zip` from https://ollama.com/download/mac, unzip, drag `Ollama.app` to `/Applications`, launch once. The app runs as a menu-bar agent and starts the daemon automatically. CLI alternative:
```bash
brew install ollama
brew services start ollama
```

**Expected (autonomous):** `ollama --version` prints something like `ollama version is X.Y.Z`. `curl -s http://127.0.0.1:11434/api/tags` returns JSON (the model list, possibly empty).

**Friction:** [OPERATOR FILL-IN: did the daemon start automatically? Any firewall prompt for port 11434? Did you need to grant the app accessibility permissions?]

**Elapsed:** [OPERATOR FILL-IN: MM:SS]

### 3. Install Python 3.11+

**Command (autonomous):**
```bash

```
Verify the binary is on PATH: `python3.11 --version` should print `Python 3.11.x`.

**Expected (autonomous):** `python3.11 --version` prints `Python 3.11.x` (or higher minor — Phase 14's `reranker-bootstrap` step accepts 3.11+, so 3.12 / 3.13 are fine).

**Friction:** [OPERATOR FILL-IN: was Homebrew already installed? Did you need to add Apple Silicon Homebrew prefix to PATH? Did `python3.11` collide with an existing system Python?]

**Elapsed:** [OPERATOR FILL-IN: MM:SS]

**Expected (autonomous):** `git status` shows `On branch master`, working tree clean. `ls install.sh` resolves; `cat install.sh | head -3` shows the POSIX shebang and "Claudex first-touch installer" banner.

**Friction:** [OPERATOR FILL-IN: clone speed? Any LFS prompts? Did `install.sh` arrive with execute permission? (It should — Phase 14 set the bit via `git update-index --chmod=+x`.)]

**Command (autonomous):**

The wrapper pre-flights Bun, then runs `bun install --frozen-lockfile && bun run build && bun run setup`. The `bun run setup` step is the substantive bootstrap (Phase 14): Bun version → Ollama detect → model pull (`snowflake-arctic-embed2`) → reranker venv at `services/.venv` → projects-dir scaffold → DB at `~/.claudex/db/claudex.db` → hooks at `~/.claude/settings.json`.

**Expected (autonomous):** install.sh exits 0. `bun run setup` prints 8 numbered steps; idempotent on re-run.

**Friction:** [OPERATOR FILL-IN: which steps were slow (model pull is usually the longest — ~1-2GB download)? Did the BGE reranker venv install cleanly via `pip install -r services/requirements.txt`? **Elapsed:** [OPERATOR FILL-IN: MM:SS — note the model pull is bandwidth-bound; record total wall-clock]

<task id="03-write-linux-fixture">
**Write `docs/onboarding/linux.md`** with the same structure as macos.md but Ubuntu 24.04 LTS specifics.

Differences from macos.md:

| Field | macOS | Ubuntu 24.04 LTS |
|-------|-------|------------------|
| Bun install | `curl -fsSL https://bun.sh/install \| bash` | same |
| Ollama install | brew or .zip from ollama.com | `curl -fsSL https://ollama.com/install.sh \| sh` (per https://ollama.com/download/linux) |
| Python install | `brew install python@3.11` | `sudo apt install -y python3.11 python3.11-venv` |
| Daemon start | menu-bar agent or `brew services start ollama` | `systemctl --user start ollama` (per Ollama Linux install script's systemd unit) — or `ollama serve &` if running headless |
| Title | "Onboarding Fixture: macOS" | "Onboarding Fixture: Linux (Ubuntu 24.04 LTS)" |
| VM image example | `macOS 14.5 Sonoma fresh, Apple Silicon` | `Ubuntu 24.04 LTS Server minimal, x86_64` |
| Friction prompts | "Did you need Xcode CLI tools?" | "Did `apt install` need `sudo apt update` first? Did the Ollama systemd unit install correctly? Did Python 3.11 conflict with `python3` (3.12 by default in 24.04)?" |
| Cross-references | links to ./linux.md become ./macos.md | symmetric |

Honest note up front (under Status header):

> **Distro scope:** This fixture targets Ubuntu 24.04 LTS specifically. Other distros (Debian 12, Fedora, Arch) are not in v4.1 scope; PLAT-07 success criterion is Ubuntu 24.04 only. Operators on other distros are welcome to fork this fixture but should not block PLAT-07 close on it.

The systemd / `systemctl --user` line is upstream-provided by Ollama's official Linux installer; it is fact-checkable from https://ollama.com/install.sh's source. If the operator's VM is headless or runs without a user systemd session, the fallback is `ollama serve &` — both should be listed.

Hard authoring rules: same as macos.md (no fabricated output, no emoji, status header HITL-PENDING). Length should be similar — ~140-180 lines.
</task>
