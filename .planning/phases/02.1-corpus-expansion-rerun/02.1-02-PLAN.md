<objective>
Implement the threshold-tested pair labeler from CONTEXT.md decision 2 — two independent labelers (strict ≥3 frames, relaxed ≥2 frames) that run in parallel against the same fingerprint corpus, producing two bound experiences per measurement (CONTEXT.md decision 2a verbatim: "Two bound experiences > one. Not a fallback.").

The threshold is a parameter to `labelPairs`. The harness gains a new entrypoint `runHarnessTiered` that runs the full A/B/C measurement pipeline twice (once per tier) and returns `{ strict_3frame: HarnessRunResult, relaxed_2frame: HarnessRunResult }`. There is **NO combined verdict and NO winning tier** — each tier produces its own bound experience under its own conditions; downstream (Plan 02.1-04's runner) calls `computeVerdict` exactly twice with distinct labeler inputs.

CONTEXT.md decision 2b binding: ≥2 is the hard floor; never go below. ≥1 is too noisy a signal — same exception type + one shared frame is a coincidence rate the auto-labeler can't reliably distinguish from genuine match.

CONTEXT.md decision 2c binding: both labelers ALWAYS run regardless of strict's n. If strict reaches n=200 we still run relaxed — two bound experiences. If strict doesn't reach n=200 we report what it reached AND run relaxed in parallel.

CONTEXT.md decision 6 / item 7 binding: if neither tier reaches floor (`FLOOR_FINGERPRINTED`, `FLOOR_PROJECTS`), the corpus-too-sparse finding is the primary outcome, NOT a blocker — `runHarnessTiered` must surface this as a structured per-tier sentinel that the verdict runner translates into BLOCKED, while the OTHER tier still runs to completion.

This plan does NOT touch the verdict module — the verdict logic is invariant per CONTEXT.md decision 5. Plan 02.1-04 calls the verdict module twice with the two tiers' decision_rule_inputs.

```typescript
export async function runHarnessTiered(db: Database, opts?: { seed?: number }): Promise<TieredHarnessResult> {
  const seed = opts?.seed ?? 42;

  // Load corpus ONCE — shared across both tiers (same fingerprint corpus).
  const events: IndexedEvent[] = loadEvents(db);
  // Floor check is per-tier in case one tier runs but the other doesn't —
  // for the corpus floor itself (≥ FLOOR_FINGERPRINTED events, ≥ FLOOR_PROJECTS
  // distinct projects), both tiers share the same answer because the
  // corpus is the same; if floor fails, both tiers produce blocked-shape
  // results and the caller (Plan 02.1-04 runner) sees TWO BLOCKED verdicts.
  // If floor passes for the corpus but a particular tier produces zero
  // pairs, that tier produces a non-throwing HarnessRunResult with
  // pairs.total = 0 and metrics filled with zero-n CIs — Plan 02.1-04's
  // verdict runner translates pairs.total = 0 into BLOCKED for that tier
  // specifically.

  // Strict tier
  const strictPairs = labelPairsByTier(events, 'strict_3frame');
  const strictResult = await runHarnessForTier(db, events, strictPairs, seed);

  // Relaxed tier — uses SAME seed deliberately; per-tier pair lists are
  // independent inputs to splitTrainTest, so each tier's test set is its
  // own bound experience. The relaxed pair set is a strict superset of
  // strict's by construction (frame_overlap >= 2 implied by >= 3).
  const relaxedPairs = labelPairsByTier(events, 'relaxed_2frame');
  const relaxedResult = await runHarnessForTier(db, events, relaxedPairs, seed);

  return {
    ts_epoch: Math.floor(Date.now() / 1000),
    strict_3frame: strictResult,
    relaxed_2frame: relaxedResult,
  };
}
```
