# Phase 2.1 Plan 03: Stratified-sampling spot-check audit (descriptive)

CONTEXT.md decision 3 implemented: 20-pair stratified spot-check audit per tier, **descriptive-only** (auto-labeler precision is a measured CONDITION of the bound experience, not a pass/fail gate).

**Duration:** 12 min  **Completed:** 2026-05-05  **Tasks:** 5  **Files:** 8 (4 new code, 4 audit artifacts)

## What changed

- **`audit.ts`** — pure stratification math + markdown/JSON renderers + DB-attached runner.
  - `planAudit(pairs, tier, opts?)` — pure: proportional allocation across single-origin strata using floor + descending-fractional-remainder distribution; population-capped per stratum; mixed pairs descriptive only.
  - `renderAuditMarkdown(plan, rawContentByEventId)` / `renderAuditJson(plan, ...)` — pure renderers.
  - `runAudit(db, events, tier, opts?)` — end-to-end: labels pairs at the tier, plans, fetches raw content for sampled events, atomic-writes the markdown + JSON sidecar.
  - All four functions exported.
- **`cli.ts`** — new `audit [--tier strict_3frame|relaxed_2frame|both] [--seed N]` subcommand. Default `--tier both` runs the two tiers in parallel via `Promise.all` (CONTEXT.md decision 3d binding). Prints a per-tier summary: tier name, sample size, allocation breakdown, output paths.
- **`harness.ts`** — `buildCorpus` is now `export`ed so the audit subcommand can reuse the same loader without duplicating SQL.
- **`audit-stratified-sampling.test.ts`** — 9 test cases covering proportional allocation correctness, rounding-remainder distribution, mixed-stratum exclusion, under-target downsizing, single-origin tier, determinism on fixed seed, purity (Date.now spy + byte-equal cross-call output).

## Per-pair judgment methodology

The audit applied a deterministic rubric over each pair's `Error: ...` line:

- Identical missing-module path → VALID (same recurring install/path issue).
- Both events in the Claudex CLI install family (`~/.claudex/dist/cli/*.cjs` or npm-resolved `@claudex/cli/dist/cli/*.cjs`) → VALID (same fix: rebuild/install Claudex CLI).
- Different exception family (one `ENOENT no such file or directory`, the other `Cannot find module`) → INVALID (different fix path).
- Either event is `[REDACTED]` → INVALID (cannot confirm root cause).
- Otherwise different missing-module roots (e.g. `'canvas'` vs Claudex CLI; `Kompas` vs Claudex CLI) → INVALID.

The rubric is reproducible: the JSON sidecars contain the deterministic seed=4321 sampled pair list; an operator manually re-auditing applies the same heuristic over the same input.
