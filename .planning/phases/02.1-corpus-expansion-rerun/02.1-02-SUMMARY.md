# Phase 2.1 Plan 02: Threshold-tested labeler + dual-tier harness

CONTEXT.md decision 2 implemented: two parallel labelers (strict ≥3 frames, relaxed ≥2 frames) running independently against the same corpus, producing two bound experiences per measurement. NO combined verdict, NO winning tier — Plan 02.1-04 will call the verdict module exactly twice (once per tier).

**Duration:** 5 min  **Completed:** 2026-05-05  **Tasks:** 4  **Files:** 4 (1 new test)

## What changed

- **types.ts:** added `LabelerTier = 'strict_3frame' | 'relaxed_2frame'` and `LABELER_TIER_FRAME_MIN` map (3 / 2). CONTEXT.md decision 2b binding documented in JSDoc — adding `relaxed_1frame` requires CONTEXT amendment + user-approval gate.
- **pair-labeling.ts:** `labelPairs(events, opts?)` now accepts `{ frame_overlap_min }`; defaults to 3; throws on values < 2 with the specific decision-2b error message. Zero-arg `labelPairs(events)` preserved; Phase 2's existing tests still pass byte-equal. `labelPairsByTier(events, tier)` convenience exported.
- **harness.ts:**
  - Factored existing `runHarness` body into a private `runHarnessForTier(db, corpus, projectSet, allPairs, density, seed)` taking a pre-loaded pair list as input.
  - `runHarness(db, opts)` is now a thin wrapper that loads corpus, throws on floor miss, calls `runHarnessForTier` with the strict (default-3) pair set. Phase 2 backwards-compat preserved.
  - `runHarnessTiered(db, opts)` exported — loads corpus once, computes density once (shared), calls `runHarnessForTier` twice (strict then relaxed) with same seed but per-tier pair lists.
  - `TieredHarnessResult = { ts_epoch, strict_3frame, relaxed_2frame }` — exactly three top-level keys; no `combined`/`winning`/`primary`.
  - n=0 sentinel: `runHarnessForTier` short-circuits to a zero-n `HarnessRunResult` via `emptyTierResult` helper when the pair list is empty (CONTEXT.md decision 6 — corpus-too-sparse is the primary outcome of that bound experience).
- **pair-labeling-tiered.test.ts:** 11 new test cases covering threshold respect, hard-floor throw, superset invariant, no-combined-key shape, n=0 sentinel, runHarness backwards-compat, density-signal-shared-across-tiers, decision_rule_inputs populated for both tiers.
