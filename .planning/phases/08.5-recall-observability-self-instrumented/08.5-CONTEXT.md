# Phase 8.5: Recall Observability + Self-Instrumented Agent — Context

**Gathered:** 2026-04-29
**Status:** Ready for planning
**Generative axiom:** Visible token cost forces discipline. The agent narrating its retrieval surfaces the kid-stove organic recall in a way that's debuggable — *"checking shadowban research from Lacuna … found, applying"* makes the recall mechanism observable. Silent retrieval can fail invisibly; narrated retrieval is auditable.

---

<domain>
## Phase Boundary

This phase delivers four things and only these four things:

1. **Per-session retrieval log** — every `claudex_search` / `claudex_recall` / pointer-surfacing invocation captured with `(query, top_k_results, used_in_output_yn, token_cost, retrieved_at_epoch_ms)`
2. **Agent self-narration** (advisory voice, gated default-on, `/silent` toggle off): when retrieval returns nothing useful, agent narrates *"no prior experience on this — going in cold."* When retrieval returns gold, agent narrates *"checking shadowban research from Lacuna … found, applying."*
3. **Visible token cost at `/endsession`**: *"session-start spent N tokens; recall added M tokens; total memory cost X tokens."*
4. **Slash command `/claudex-why`** (or equivalent) showing retrieval log for the current session

**Out of scope:**
- Cross-session retrieval analytics (per-session is the unit)
- Cost optimization recommendations from the log (just exposure, not action)
- Replacing existing telemetry (additive, not replacement)

**Hard gates:**
- Vesna probes verify self-instrumentation behavior (when agent had relevant prior experience, did it surface during framing? — SC#1 alignment)
- Token cost numbers must be accurate, not estimated (use real tokenizer counts at the surface)

</domain>

<decisions>
## Implementation Decisions

### Retrieval log schema

```sql
CREATE TABLE retrieval_log (
  id INTEGER PRIMARY KEY,
  session_id TEXT NOT NULL,
  invoked_at_epoch_ms INTEGER NOT NULL,
  surface TEXT NOT NULL,             -- 'claudex_search' | 'claudex_recall' | 'pointer_surface' | 'mcp_other'
  query TEXT,                        -- user query or trigger context
  top_k_results TEXT,                -- JSON array of result IDs + scores
  used_in_output INTEGER,            -- 0/1 whether agent used in subsequent output (best-effort heuristic)
  token_cost INTEGER NOT NULL        -- real tokenizer count of returned content
);
CREATE INDEX idx_retrieval_log_session ON retrieval_log(session_id, invoked_at_epoch_ms DESC);
```

### `used_in_output` heuristic

- Best-effort, not strict: after agent completes a turn, scan agent output for substantial overlap with retrieval results (keyword/embedding match)
- Heuristic gates: if ≥2 distinctive tokens from retrieved content appear in agent output within 5 turns of retrieval → mark `used_in_output=1`
- Acceptable false-negative rate: agent might paraphrase heavily, missing overlap. This is a signal, not ground truth.

### Self-narration content

- Default voice: advisory (Phase 7 alignment)
- Templates:
  - **Empty result**: *"No prior experience on {query_topic} — going in cold."*
  - **Gold result**: *"Checking {topic} from {project} ({date}) — applying."*
  - **Ambiguous result**: *"Some prior context on {topic} but not directly relevant — proceeding with caution."*
- Narration fires once per substantial retrieval, not per result (avoid noise)
- `/silent` toggle disables narration for the session (off-by-default; user opts out if narration becomes noise)

### Visible token cost at /endsession

- Display format:
  ```
  Memory cost this session:
    session-start: N tokens
    UPS turns: M tokens (avg P/turn × Q turns)
    explicit retrieval: R tokens (X invocations)
    total: T tokens
  ```
- Numbers from real tokenizer counts (cl100k_base via tiktoken — same as Phase 5 token budget)
- Not gated; always displays at /endsession unless suppressed via flag

### `/claudex-why` slash command

- Reads `retrieval_log` for current session
- Renders chronological list: `[T+0:23] claudex_search("rate limit") → 3 results, 2 used, 487 tokens`
- One-line per invocation; expand-on-click pattern (or full list if slash command doesn't support interactive)
- Shows aggregate at end: total invocations, hit rate (used / surfaced), token sum

### Vesna probe coverage

- At least 2 probes verifying self-instrumentation behavior:
  1. **Gap detection probe**: agent has relevant past experience for current task; expect narration *"checking ... applying"* in output
  2. **Empty surface probe**: agent has no relevant prior experience; expect narration *"going in cold"* in output
- Probes run as part of Phase 10's central validation suite

### Claude's Discretion (planner free to decide)

- Exact location of retrieval_log instrumentation (recommendation: at MCP server level in `src/mcp/recall-server.ts` so all surfaces hit it)
- Heuristic thresholds for `used_in_output` (recommendation: planner tunes from real session data; start with 2-distinctive-tokens, 5-turn-window)
- Narration template wording past the locked shape
- Whether `/claudex-why` is interactive (planner picks based on slash command capabilities)
- Token cost display format details (single line vs multi-line; user preference unknown)

</decisions>

<specifics>
## Specific Ideas

- **Visibility forces discipline** — when token cost is invisible, retrieval is "free" and over-fetching is hidden. Visibility incentivizes frugality without imposing a hard cap.
- **Narration is the human-readable retrieval log** — `/claudex-why` is the structured form; in-session narration is the streaming form. Both serve auditability.
- **`used_in_output` is a signal, not a verdict** — best-effort heuristic; the value is trend over time, not per-event accuracy. Combined with `pointer_recall_log.helpful_yn` (Phase 5.5), produces a real picture of retrieval value.

</specifics>

<deferred>
## Deferred Ideas

- **Cross-session retrieval analytics** — "in the last 30 days you've retrieved X type Y times" — adds value but expands scope; per-session is the unit for 8.5
- **Automatic cost-optimization recommendations** — "you over-retrieved here, consider X" — over-engineering at this stage; expose data first
- **Replacing existing telemetry** — 8.5 is additive; existing telemetry tables (e.g., from Phase 4) untouched

</deferred>
