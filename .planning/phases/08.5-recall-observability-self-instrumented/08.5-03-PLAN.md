# Plan 08.5-03 — MCP server instrumentation

## Goal

Wire `claudex_search` and `claudex_recall` in `src/mcp/recall-server.ts` to
emit one `retrieval_log` row per invocation via the helper module from
Plan 08.5-01. This is the live data source for `/endsession` cost and
`/claudex-why`.

Logging is fire-and-forget at the surface level — a logging failure must
NEVER block the retrieval response. The helper's `recordRetrieval` is
already non-throwing; the MCP-side wiring still wraps the call in a
try/catch as defense in depth.

## Scope (what changes)

| File | Change | Why |
|------|--------|-----|
| `src/mcp/recall-server.ts` | EXTEND `claudex_search` + `claudex_recall` handlers | Single instrumentation point per CONTEXT.md |
| `src/tests/mcp/recall-server-retrieval-log.test.ts` | NEW | Asserts the rows land with correct shape |

No other tools instrumented (`claudex_store`, `claudex_session`,
`claudex_curated_context`, `claudex_message`, `claudex_events` —
out of scope per CONTEXT.md).

`pointer_surface` rows continue to be logged via the Phase 5.5
`pointer_recall_log` table — Plan 08.5-04 unifies them in the
aggregator, not here.

## Wiring shape

### claudex_search

Locate the handler (`src/mcp/recall-server.ts` line 135 — the `async ({...})` body).
Find the existing return at the bottom (the JSON.stringify block after
RRF fusion).

Before the `return { content: [...] }` line, build:

```typescript
try {
  const responseText = JSON.stringify(merged, null, 2);  // exact body returned
  const topK = merged.slice(0, 50).map(r => ({
    id: r.id,
    source: r.source,
    score: r.score,
  }));
  recordRetrieval(getDb(), {
    sessionId: activeSessionId,
    surface: 'claudex_search',
    query,
    topKResults: topK,
    responseText,
  });
} catch { /* logging must never break retrieval */ }
```

`activeSessionId` is the same variable already constructed for reranker
telemetry attribution (lines 165-178). If `merged` is the variable name
in the file, use it; if not, find whichever variable holds the final
RRF-fused list right before serialization. Use `JSON.stringify(...)`
matching whatever the handler currently returns to the agent.

The `responseText` MUST be the literal text the agent receives so
`token_cost` reflects the actual context cost. If the handler builds
its return text via a builder, log the same string.

### claudex_recall

Handler at line 572. Currently calls `logLessonRecallIfApplicable` at
line 593. Add a second log call (the new retrieval log) — these are NOT
duplicates: pointer_recall_log tracks lesson pointers specifically;
retrieval_log tracks ALL recall events.

After resolving `row` and BEFORE returning:

```typescript
try {
  const responseText = JSON.stringify({
    id: row.id,
    type: row.artifact_type,
    summary: row.summary,
    content: row.content,
    provenance: row.artifact_ref ?? `artifact #${row.id}`,
    project: row.project,
    importance: row.importance,
  }, null, 2);
  recordRetrieval(getDb(), {
    sessionId: `mcp:${defaultProject}`,
    surface: 'claudex_recall',
    query: ref ?? (validId ? `id:${validId}` : null),
    topKResults: [{ id: row.id, source: 'artifacts', score: 1.0 }],
    responseText,
  });
} catch { /* logging must never break retrieval */ }
```

**Do NOT log the not-found case.** A `claudex_recall` with no resolution
returns an `error` payload — there's no retrieval to attribute, no
content the agent uses for framing. The instruments-the-actual-recall
intent is preserved.

For `query` field: if the caller passed `artifact_ref`, use that string;
if they passed `id`, use `id:<n>`. Null is acceptable per the schema.

### session_id resolution

Use the **existing** active-session lookup pattern. `claudex_search`
already resolves `activeSessionId` (lines 165-178). If
`claudex_recall` doesn't have an equivalent today, factor a small
internal `_resolveActiveSessionId(db: Database, project: string): string`
helper at the top of the file (NOT exported) that mirrors the search
handler's lookup logic and returns `mcp:${project}` on miss.

This avoids two divergent active-session resolution paths in the same file.

```typescript
function _resolveActiveSessionId(db: Database.Database, project: string): string {
  try {
    const active = cachedPrepare(db,
      `SELECT s.session_id FROM sessions s
         LEFT JOIN (
           SELECT session_id, MAX(timestamp_epoch) as last_activity
             FROM session_events GROUP BY session_id
         ) e ON e.session_id = s.session_id
        WHERE s.project = ? AND s.status = 'active'
        ORDER BY COALESCE(e.last_activity, s.created_at_epoch) DESC LIMIT 1`,
    ).get(project) as { session_id: string } | undefined;
    if (active?.session_id) return active.session_id;
  } catch { /* fall through */ }
  return `mcp:${project}`;
}
```
