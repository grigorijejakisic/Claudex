# Plan 08.5-02 — Self-narration directive + /silent toggle

## Goal

OBS-02: when retrieval returns nothing useful, agent narrates *"no prior
experience on this — going in cold."*; when retrieval returns gold, agent
narrates *"checking shadowban research from Lacuna … found, applying."*

We deliver this as **system-prompt-level guidance**, not as a runtime
formatter. The MCP server's `instructions` payload already injects a
shared prompt block into CC; Phase 8.5 extends that block with the
narration directive in advisory voice (Phase 7 alignment). A `/silent`
toggle stores a per-session flag the agent reads — runtime suppression
is via the agent honoring the directive (advisory-voice spirit), not via
a separate suppression code path.

## Locked content (CONTEXT.md, restated)

The directive is one Markdown block appended to `CLAUDEX_INSTRUCTIONS`:

```markdown
## When You Recall — Narrate (advisory)

Visibility is the curative for invisible recall: when memory tools fire,
a one-line narration in the agent's voice surfaces what surfaced (or
didn't) and what it's being applied to. Phase 7's advisory voice applies.

**When retrieval returns nothing useful** — narrate "no prior experience on {topic} — going in cold."

**When retrieval returns gold (clearly relevant prior result)** — narrate "checking {topic} from {project} ({date}) — applying."

**When retrieval returns something ambiguous** — narrate "some prior context on {topic} but not directly relevant — proceeding with caution."

Once per substantial retrieval, not per result. If the user has set
`/silent` for this session, suppress narration; the retrieval log still
records the event for `/claudex-why`.
```

The block ALWAYS appears in `instructions` when narration is on
(default). When the user has explicitly toggled `/silent` on for the
current session, the block is replaced with `''` (suppressed entirely
so a re-cached prompt doesn't carry stale directive).

  <description>
Module exports three named symbols + a `NARRATION_DIRECTIVE_BODY` constant
that holds the locked directive content (above) verbatim:

```typescript
import type { Database } from 'better-sqlite3';
import { cachedPrepare } from '../core/stmt-cache.js';

/** Locked directive content (CONTEXT.md). Exported for tests. */
export const NARRATION_DIRECTIVE_BODY: string;

/**
 * Build the narration directive block to append to CLAUDEX_INSTRUCTIONS.
 * Returns NARRATION_DIRECTIVE_BODY when silent=false; empty string otherwise.
 *
 * Caller is the MCP server which constructs the static instructions payload
 * once at module load — production passes silent=false. Per-session silent
 * state is checked by the agent reading session_signals when it sees the
 * directive say "if /silent is set, suppress". The boolean parameter exists
 * so tests can exercise both branches.
 */
export function buildNarrationDirective(silent: boolean): string;

/** Read the per-session narration_silent flag from session_signals. */
export function isNarrationSilent(db: Database, sessionId: string): boolean;

/** Set / clear the per-session narration_silent flag in session_signals. */
export function setNarrationSilent(db: Database, sessionId: string, silent: boolean): void;
```

`session_signals` schema confirmation: see `src/core/schema.ts` for the
exact column names. Use the existing helpers if there's a generic
`createSignal`/`clearSignal` API; otherwise raw INSERT/DELETE on the
table is fine. The signal type to use: `narration_silent` (new but
allowed — `session_signals` accepts arbitrary type strings).

Implementation note for `buildNarrationDirective`: the static directive
block IS cache-stable. The dispatch on `silent` here is technically only
exercised by tests (the production path always passes `false` since CC
caches the system prompt at session start, before any /silent toggle
runs). It exists to keep the helper symmetric and to support the
behavioral probe in Wave 4.

**Runtime /silent suppression model (v1):** the directive itself contains
the suppression rule — the agent reads "if `/silent` is set for this
session, suppress narration; the retrieval log still records." There is
no separate per-turn reminder code path in v1. The agent honors the
directive by checking session state (which it can do via
`claudex_session` queries when in doubt). This is consistent with the
advisory-voice spirit (Phase 7) — directives are guidance the agent
internalizes, not commands the runtime enforces. If session experience
shows the toggle is ineffective, a per-turn reminder lands as a Phase
8.5 follow-up; not in v1 scope.
