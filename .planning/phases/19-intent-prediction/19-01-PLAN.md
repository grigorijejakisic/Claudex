# Plan 19-01: Intent Prediction at Session-Start

## Goal
Predict what the user will need BEFORE their first prompt. Pre-materialize artifacts based on prediction. Confidence-gated injection. The proactive leap.

## Tasks

### Task 1: Create intent predictor module
**File:** NEW `src/intelligence/intent-predictor.ts`

Export `predictSessionIntent(db, project, sessionId)`:

**Layer 0 — Strong Anticipation (coupling, no model, ~70% of sessions):**
1. Check for active thread with unfinished work: `SELECT * FROM thread_state WHERE project = ? ORDER BY rowid DESC LIMIT 1` — if thread has no summary/conclusion, predict continuation of that topic
2. Check for active handoff: look for recent `session_messages` with `message_type = 'advisory'` from Angel
3. If either found → return `{ intent: 'continuation', topic: thread.topic, confidence: 0.8, artifacts: [...thread_artifact_ids] }`

**Layer 1 — Weak Anticipation (simple features):**
1. Compute: `hours_since_last_session` from `sessions` table
2. Get current `hour_of_day` and `day_of_week`
3. Query `temporal_profile` for what user typically does at this time/day
4. If `hours_since_last_session < 2` → high continuation probability (confidence 0.7)
5. If `hours_since_last_session > 24` → likely new topic (confidence 0.4)
6. Return prediction with confidence based on temporal match strength

**Layer 2 — Weak Anticipation (pattern matching):**
1. Query `action_transitions` for most likely first action given last session's final actions
2. Query recent `session_events` for patterns (what topics recur at this time)
3. Return prediction with confidence 0.3 (lowest layer)

**Selection:** Return the highest-confidence prediction across all layers.

Also export `recordPredictionAccuracy(db, sessionId, predictedIntent, actualIntent)` for feedback loop.

### Task 2: Update temporal profile and action transitions at session close
**File:** `src/adapters/cc-hooks/stop.ts`

At session end, update the temporal tables:
1. `temporal_profile`: INSERT OR UPDATE for this session's (hour_bucket, day_of_week) with incremented session_count
2. `action_transitions`: INSERT OR UPDATE counts for (from_action, to_action) pairs observed in this session's session_events
3. Hour bucket: divide 24 hours into 6 buckets of 4 hours (0-3, 4-7, 8-11, 12-15, 16-19, 20-23)

### Task 3: Wire into session-start hook
**File:** `src/adapters/cc-hooks/session-start.ts`

After checkpoint recovery, before assembly:
1. Call `predictSessionIntent(db, project, sessionId)`
2. If prediction confidence >= threshold (0.4 initially):
   - Pre-materialize predicted artifacts
   - Pass predicted artifacts + intent to `assembleFullContext()` as new `predictedContext` option
3. Store prediction in session_events for later accuracy tracking
4. If prediction confidence < threshold: proceed with normal assembly (no prediction)

### Task 4: Confidence-gated assembly section
**File:** `src/assembly/assembler.ts` or `src/assembly/sections.ts`

Add a new assembly section type `'predicted_context'`:
- Only included when prediction confidence >= threshold
- Format: brief header "Predicted context (confidence: X%)" followed by artifact summaries
- Budget: max 2000 tokens for predicted context
- Below main context sections in priority (predictions should augment, not replace)

### Task 5: Prediction accuracy feedback in stop hook
**File:** `src/adapters/cc-hooks/stop.ts`

At session end:
1. Retrieve the prediction that was made at session-start (from session_events)
2. Determine actual session intent from conversation_turns and session_events
3. Call `recordPredictionAccuracy(db, sessionId, predicted, actual)`
4. Track accuracy over time — use this to auto-tune the confidence threshold

### Task 6: Tests
**File:** NEW `src/tests/intelligence/intent-predictor.test.ts`

Tests:
1. Layer 0: active thread → continuation predicted with confidence 0.8
2. Layer 0: no active thread → falls through to Layer 1
3. Layer 1: short session gap → continuation with 0.7 confidence
4. Layer 1: long session gap → lower confidence
5. Layer 2: matching temporal profile → prediction based on historical pattern
6. Highest confidence wins across layers
7. Below threshold → returns null (no prediction)
8. Temporal profile update works correctly
9. Action transitions update works correctly
10. Prediction accuracy recording works
11. Empty DB → graceful null prediction (non-throwing)
