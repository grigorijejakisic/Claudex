# Plan 09-08 — Delete RL stack (sub-phase 9.8)

## Goal

Phase 8 verdict: **DELETE_ALLOWED** (`context/specs/V4_RL_ABLATION.md`,
locked 2026-04-29, aggregate Δ = 0pp). This plan executes the deletion that
Phase 8 cleared.

Delete the seven RL stack modules, the qMultiplier branch in
`computeArtifactScore`, the `qvalue` member from `MultiplierName`, the
`CLAUDEX_DISABLE_RL_SCORING` env-var gate (its absence is the permanent
state once the surface is gone), the `rl-scoring-disabled-counter` module
+ test (Phase-8-only sanity-check infrastructure), and the heartbeat
RL-trainer + temporal-decay blocks. Drop the `policy_weights` table and
`q_value` columns via a new V23 migration.

Per V4_RL_ABLATION.md `## Implications.### REALIZED`, estimated LOC delta:
**−700 to −1100 lines net**.

## Why this is one sub-phase, not several

CONTEXT.md sub-phase 9.8 lists 7 code files + the schema drop. They form
a single logical unit: deleting one without the others leaves a non-compiling
or schema-inconsistent state. The bisectability discipline is preserved by
keeping 9.8 as a single atomic commit covering a coherent subsystem (RL is
*one* subsystem with multiple files); the prior 9.1-9.7 commits give bisect
the granularity needed to attribute regressions to *which subsystem*, and
9.8 is the RL subsystem whole.

If Vesna fails at 9.8, the verdict was wrong (or the cross-cycle write/read
behavior the Phase 8 evidence couldn't fully exercise — see V4_RL_ABLATION.md
`## Confound disclosure` — was load-bearing). In that case revert 9.8 and
reopen Phase 8 with a richer probe set per CONTEXT.md `<decisions>.### 9.8
conditional logic`.
