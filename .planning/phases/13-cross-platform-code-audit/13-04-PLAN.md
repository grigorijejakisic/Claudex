**Fix patterns (from CONTEXT.md `<decisions>`):**

PLAT-01 path handling:
- `dir + '\\' + file` → `path.join(dir, file)`
- `dir + '/' + file` (in code) → `path.join(dir, file)` (only if it's filesystem path; URL paths stay)
- `__dirname + '/../config.json'` → `path.resolve(__dirname, '..', 'config.json')`
- `path.normalize(dir + '\\' + file)` → `path.join(dir, file)` (normalize was a workaround)
- Regex `\\\\` matching paths in code that processes user paths → `[\\\\/]` (or use `path.sep` for dynamic patterns)

PLAT-02 hook portability:
- PowerShell-only cmdlet in spawn args → replace with cross-platform Node API or platform-branched call
- `cmd /c` chains in hook code → replace with direct binary call
- File-permission assumptions — if any `fs.chmod` calls exist with Windows-only intent, document and likely remove (Windows ignores POSIX modes anyway)

PLAT-04 subprocess portability:
- `cmd /c` chains → direct binary call or platform-branched spawn
- `exec('cd dir && cmd')` → `spawn('cmd', ['arg'], { cwd: dir })`
- Windows-only utility (`rmdir /s /q`, `del`) in `build.ts` / `package.json` → use `fs.rmSync(dir, { recursive: true, force: true })` or the `rimraf` package or Bun's built-ins
- Implicit shell that needs explicit selection → `shell: process.platform === 'win32' ? 'cmd' : 'sh'`

**Authority (per CONTEXT.md `<plan_authorization>`):**

Document the rationale in the commit message and append a `## Downgraded findings` section to the relevant audit file.
- The executor cannot expand scope — if a fix exposes an unrelated bug, file it as a discovery for a later phase, do not fix it here.

**Commit strategy:**
- One atomic commit per fix-cluster. A cluster is either:
  - A single file with multiple related fixes (one commit covering the file), OR
  - A small group of files where one logical change ripples (e.g., a function signature change with its callers — commit together so bisect doesn't land on a half-broken state)
- Commit message convention: `phase(13-04): PLAT-XX — <what changed>` where XX is the requirement(s) addressed
- After each commit, `bun run build` must exit 0. Test suite need not be run after every commit, but should be run after every 5-10 commits and at the end (final task verifies the full suite + vesna)

**Out of scope:**
- Any taskkill callsite (13-03 handles)
- Any new abstractions beyond the targeted fixes — scope lock applies
- Refactoring "while we're here" — even if a touched function would benefit from cleanup, leave it
- `services/reranker.py` — Python, separate concern

**Hard gates:**
