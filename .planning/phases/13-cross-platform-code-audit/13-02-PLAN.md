<execution_context>
**PLAT-02 — what to look for in `src/adapters/cc-hooks/`:**
- PowerShell-only cmdlets in spawned commands: `Get-Process`, `Stop-Process`, `Test-Path`, `New-Item`, etc. (none expected since hooks are Node.cjs, but verify)
- `cmd /c` chains in spawned commands inside hook code
- `.ps1` scripts invoked from a hook (would only run on Windows)
- File-permission assumptions (hooks read with `fs.readFileSync` / write with `fs.writeFileSync` — already cross-platform; flag any `chmod` calls or octal-mode literals that may need attention)
- Shebangs on `.cjs` files — none should be needed (CC invokes Node explicitly), but note if any `.sh` files exist in the directory

**PLAT-04 — what to look for in all `src/`:**
- `taskkill` literal — Windows-only command; flag for 13-03 to migrate to `terminateProcess` abstraction
- `cmd /c` literal — Windows-only shell wrapper; replace with direct binary call or platform-branched spawn
- `spawn`, `exec`, `execSync`, `spawnSync`, `Bun.spawn`, `Bun.$` callsites — inspect each:
  - **Direct binary call** (e.g., `spawn('ollama', ['list'])`) → already-portable, leave alone
  - **Shell string with chaining** (e.g., `exec('cd dir && command')`) → fix-needed, refactor
  - **Shell string with env-var expansion** that genuinely needs a shell → fix-needed, add explicit shell selection (`process.platform === 'win32' ? 'cmd' : 'sh'`)
  - **Bun's `$` template** (e.g., `await $\`bun run build\``) → already-portable but flag any embedded shell idioms (pipe chains, env-var syntax)
- `build.ts` and `package.json` scripts — audit for `rmdir /s /q`, `del /q`, `copy`, or other Windows-only commands; flag for cross-platform replacement (e.g., `rimraf` package, Bun's `--rm`, Node's `fs.rmSync({ recursive: true, force: true })`)

**Out of scope here:**
- `services/reranker.py` (Python; separate concern per CONTEXT.md `<plan_authorization>`)
- `node_modules/`, `dist/`, `.git/`
- Test fixtures that intentionally exercise platform-specific spawn behavior — keep them, document the rationale

**Deliverable shape:**
A markdown document with two main sections:
- **PLAT-02 findings** — hooks portability audit (likely empty or near-empty; document the verification regardless)
- **PLAT-04 findings** — subprocess portability audit, classified per row

Plus summary lists at the bottom:
- `taskkill` callsites (consumed by 13-03)

- already-portable callsites (no action; documented for completeness)
