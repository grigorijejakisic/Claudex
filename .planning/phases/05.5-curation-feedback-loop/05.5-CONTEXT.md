# Phase 5.5: Curation Feedback Loop — Context

**Gathered:** 2026-04-29
**Status:** Ready for planning
**Generative axiom:** Pointers earn their place by use, not by extraction. Pattern density (kid-stove principle: repetition strengthens, neglect demotes) is the curation signal.

---

<domain>
## Phase Boundary

This phase delivers four things and only these four things:

1. **`pointer_recall_log` table** capturing retrieval events: `(pointer_id, session_id, retrieved_at_epoch_ms, helpful_yn, query)`. Written automatically when retrieval surfaces a `## Lessons` or `## User Notes` pointer.
2. **`helpful_yn` capture at `/endsession`**: light-tap UX showing pointers retrieved this session, asks user to mark helpful/unhelpful/skip. Default on skip = null.
3. **Auto-archive** (Angel heartbeat sweep): pointers with 0 retrievals in 90 days AND `helpful_yn=null` move out of MEMORY.md index. Artifact preserved in DB; only the foreground pointer demotes to background tier.
4. **Auto-promote** (Angel heartbeat sweep): pointers with ≥3 retrievals AND any `helpful_yn=true` move to high-salience top of section.

**Out of scope (deferred):**
- Cross-project pointer recall correlation (Phase 6.5)
- Quantitative scoring beyond binary helpful_yn (later phase or dropped — over-engineering)
- LLM-judged helpfulness inference from session outcome (later — adds cost; user-tap is cheap and trustworthy)
- Proactive "this pointer hasn't been used in 60 days, archive it?" prompts during sessions (out — adds friction)

**Hard gates:**
- Pointer archival is a UI demotion only; underlying artifact stays in DB queryable
- helpful_yn capture must be skippable (default null on enter); never blocks /endsession completion
- Auto-promote and auto-archive run on heartbeat; never inline with retrieval (no latency cost to retrieval path)

</domain>

<decisions>
## Implementation Decisions

### `pointer_recall_log` write surface

- Hook the retrieval path (`claudex_search`, `claudex_recall`, MEMORY.md pointer-line surfacing) to write a row per retrieval event
- Schema: `pointer_id INTEGER, session_id TEXT, retrieved_at_epoch_ms INTEGER, helpful_yn INTEGER NULL, query TEXT`
- Index on `(pointer_id, retrieved_at_epoch_ms DESC)` for fast lookup of recent activity per pointer
- Index on `(session_id)` for /endsession UX
- Write is fire-and-forget from Angel/MCP server — no retrieval latency cost

### `helpful_yn` UX at /endsession

- Render: *"This session retrieved N pointers: [pointer 1], [pointer 2], ... — any helpful? (yes-list / skip)"*
- Input pattern: comma-separated indices for helpful, blank for skip, `all` shorthand if all helpful
- Stores `helpful_yn=1` for indicated, leaves null for the rest (NOT 0 — distinguishes "actively unhelpful" from "didn't say")
- For "actively unhelpful": ignored in Phase 5.5; future phase may add explicit -1 marker. Keeping it binary helpful-or-null avoids friction.

### Auto-archive policy

- Sweep runs on Angel heartbeat (interval: planner discretion, recommendation: daily)
- Conditions: `pointer.last_retrieved_at < now - 90d` AND no `helpful_yn=1` row exists for pointer
- Action: move pointer line out of `## Lessons` foreground in MEMORY.md to background tier (4.1's foreground/background split)
- Underlying artifact stays in DB; pointer is recoverable via `claudex_search` if surfaced again

### Auto-promote policy

- Sweep runs on Angel heartbeat (recommendation: weekly is enough; pattern density takes time to stabilize)
- Conditions: pointer has ≥3 retrievals total AND ≥1 `helpful_yn=1` row
- Action: move pointer to top of `## Lessons` section (high-salience tier within foreground)
- Demotion from top occurs naturally if retrievals slow (heartbeat re-evaluates; not a separate demotion-from-top sweep)

### Connection to Phase 4.1's foreground/background tier

- 4.1 designed the tier infrastructure; 5.5 ships the *signals* that drive it
- Without 5.5, 4.1's promotion/demotion logic has no data to act on (every pointer stays static)
- 5.5 ships 4.1's tier into actually being dynamic

### Vesna probe (per ROADMAP SC#5)

- Lifecycle simulation: synthesize 30 days of activity for two test pointers — one with steady retrievals + helpful=true (must auto-promote), one with zero activity (must auto-archive after 90d)
- Run as automated test in `tests/intelligence/curation-feedback-loop.test.ts` with time-mocking — not a real 30-day soak

### Claude's Discretion (planner free to decide)

- Exact `claudex_search`/`claudex_recall` instrumentation point (where in the retrieval pipeline the log row writes)
- Heartbeat sweep frequency past the recommendations (daily archive, weekly promote)
- /endsession UX wording (light-tap principle locked; exact phrasing planner picks)
- Whether pointer demotion-from-foreground also has a cooldown (e.g., demoted pointer cannot re-promote for 14d) — recommendation: no cooldown; let signals drive
- Whether helpful_yn supports an explicit "no" (binary helpful-or-null is locked for 5.5)

</decisions>

<specifics>
## Specific Ideas

- **Density-driven, not extraction-driven** — pointers don't earn promotion by being important-looking at write time; they earn promotion by being retrieved + marked helpful at use time. Mirrors 4.1's vocabulary growth protocol (Angel curates by observed density, not by guessing what should be canonical).
- **Light tap, not heavy survey** — UX is intentionally low-friction. Skipping is the default outcome for routine sessions. Don't punish skip; null is a valid signal (means "not actively helpful but not actively unhelpful either").
- **Archival is demotion, not deletion** — pointers move out of MEMORY.md index to background tier. Underlying artifact persists. If user later asks something that would have matched the archived pointer, retrieval surfaces it from DB and the recall_log fires again — natural rehabilitation path.

</specifics>

<deferred>
## Deferred Ideas

- **Quantitative helpfulness scoring** (5-point Likert or numeric weight) — over-engineering for a phase whose value comes from low-friction signal. Binary is enough.
- **LLM-judged helpfulness from session outcome** — automatic inference of whether the retrieved pointer led to good outcome. Cost + ambiguity; user-tap is cheaper and trustworthy.
- **Cross-project pointer correlation** — "this pointer in Lacuna correlates with that pointer in Oracle" — Phase 6.5 territory.
- **Mid-session "archive this?" prompts** — adds friction; sweep approach is silent and good.

</deferred>
