## 1. The thing being measured: a "pointer"

Phase 4.1 ships pointer lines in MEMORY.md. Each pointer line corresponds to **one lesson file** under `~/.claude/projects/<slug>/memory/`:

```
- [<salience>](feedback_check-deps.md) — task-pattern: <task_shape>
```

- A pointer's identity = `(project, lesson filename)`. Lessons do not have numeric IDs in the DB — the canonical handle is the path/filename.
- Lesson files are filesystem-backed (read by `src/angel/lesson-reader.ts → listLessonsForProject`). Frontmatter carries `tier: 'foreground' | 'background'` + `last_fired_at_epoch`.
- `## User Notes` is a separate section in MEMORY.md, byte-preserved by `wrapLegacyUserContent`. User-Notes "pointers" are individual user-authored bullet lines; they do not have a filesystem-backed lesson file.

**Implication for `pointer_id` (CONTEXT.md schema):** Storing `pointer_id INTEGER` against a filesystem-keyed lesson file requires either (a) a stable hash of `(project, filename)` or (b) a `lesson_pointer` registry table that auto-assigns INTEGER ids. **Recommendation: option (b) — a thin `lesson_pointer` registry**:

```sql
CREATE TABLE IF NOT EXISTS lesson_pointer (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project TEXT NOT NULL,
  filename TEXT NOT NULL,           -- e.g., 'feedback_check-deps.md'
  source TEXT NOT NULL,             -- 'lesson' | 'user_note'
  first_seen_epoch_ms INTEGER NOT NULL,
  UNIQUE(project, filename, source)
);
```

This:
- Gives `pointer_recall_log.pointer_id` a real foreign-key target.
- Lets User-Notes pointer lines (CONTEXT says "Lessons OR User-Notes") share the same machinery — `source='user_note'`, `filename` = a stable token derived from the bullet text (e.g., sha1 of normalized text, first 16 hex).
- Survives lesson rename if we treat `filename` as the canonical key (planner discretion: rename → new pointer_id; lesson lifecycle is otherwise rare).

**Alternative considered:** drop the auto-increment and key directly by `(project, filename)`. Rejected: CONTEXT.md locks `pointer_id INTEGER` and INTEGER joins are cheaper than text-tuple joins for the heartbeat sweeps.

## 2. Schema landscape

- **Current `user_version`:** 18 (`src/core/migrations.ts:79`, `TARGET_VERSION = 18`).
- **Phase 5.5 introduces V19.**
- **Migration step pattern:** `migrateV<N>toV<N+1>(db: Database): void` in `src/core/migration-steps.ts`, registered in the `migrations` array in `src/core/migrations.ts:90`. Body uses `db.exec(SCHEMA_STRING)` with `IF NOT EXISTS` everywhere.
- **Existing analogue table:** `retrieval_events` (`src/core/schema.ts:472`) already exists but is keyed on `artifact_id` and used for general artifact retrieval analytics. **Do NOT reuse it for pointer recall** — its semantics (artifact-id, was_referenced) don't fit pointer lines, and overloading would muddy retention sweeps. Ship a new `pointer_recall_log` table.

**Proposed V19 schema:**

```sql
-- V19: Curation feedback loop (Phase 5.5)

CREATE TABLE IF NOT EXISTS lesson_pointer (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project TEXT NOT NULL,
  filename TEXT NOT NULL,
  source TEXT NOT NULL CHECK(source IN ('lesson','user_note')),
  first_seen_epoch_ms INTEGER NOT NULL,
  UNIQUE(project, filename, source)
);
CREATE INDEX IF NOT EXISTS idx_lesson_pointer_project ON lesson_pointer(project);

CREATE TABLE IF NOT EXISTS pointer_recall_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pointer_id INTEGER NOT NULL REFERENCES lesson_pointer(id),
  session_id TEXT NOT NULL,
  retrieved_at_epoch_ms INTEGER NOT NULL,
  helpful_yn INTEGER NULL,           -- NULL = not marked, 1 = helpful; -1 reserved future
  query TEXT NULL                    -- nullable: organic surfacing has no query string
);
CREATE INDEX IF NOT EXISTS idx_pointer_recall_pointer
  ON pointer_recall_log(pointer_id, retrieved_at_epoch_ms DESC);
CREATE INDEX IF NOT EXISTS idx_pointer_recall_session
  ON pointer_recall_log(session_id);
CREATE INDEX IF NOT EXISTS idx_pointer_recall_helpful
  ON pointer_recall_log(pointer_id, helpful_yn) WHERE helpful_yn = 1;
```

CONTEXT.md says "epoch_ms" — keep millisecond precision for parity with `created_at_epoch` on lessons (also ms). `query` is nullable because pointer surfacing in MEMORY.md is not a search query — only `claudex_search` retrievals carry one.

Path (2) ships if Plan 02's audit finds a clean instrumentation point; otherwise it's deferred — CONTEXT.md is satisfied with "retrieval surfaces a pointer", and an explicit `claudex_recall` is the cleanest definition of that.

## 5. Auto-archive + auto-promote sweeps (heartbeat)

**Insertion point:** `src/angel/heartbeat.ts:543` — directly inside the existing "Phase 5c: Phase 4.1 bridge sweeps" outer try block, OR more cleanly as a new "Phase 5d: Curation feedback sweeps" block right after Phase 5c. The latter is cleaner: 5c is named for Phase 4.1's bridge sweeps; 5.5 should not reuse that name.

**Recommended layout (matches existing per-operation try/catch pattern from Plan 04-06-02):**

```ts
// Phase 5d: Curation feedback sweeps (Phase 5.5)
//
// Sequencing rationale:
//   - Runs AFTER Phase 5c (so any vocab promotions this tick are visible to
//     the archive/promote logic — pointers don't depend on vocab, but the
//     ordering keeps "lesson-substrate sweeps" all in one block).
//   - Runs BEFORE Phase 6 (artifact linking) — same reason as 5c.
//
// Two operations, each with its own try/catch:
//   5d-1: Auto-archive (daily cadence)
//   5d-2: Auto-promote (weekly cadence)
try {
  try {
    if (shouldRunArchiveSweep(now)) {
      const archived = sweepArchivePointers(ctx.db, now);
      if (archived > 0) result.pointers_archived = archived;
      markArchiveSweepRan(now);
    }
  } catch { result.curation_errors = (result.curation_errors ?? 0) + 1; }

  try {
    if (shouldRunPromoteSweep(now)) {
      const promoted = sweepPromotePointers(ctx.db, now);
      if (promoted > 0) result.pointers_promoted = promoted;
      markPromoteSweepRan(now);
    }
  } catch { result.curation_errors = (result.curation_errors ?? 0) + 1; }
} catch { /* unreachable */ }
```

**Cadence implementation:** time-gate via simple module-level epoch markers (same pattern as `shouldConsolidate / markConsolidationRan` already in heartbeat.ts). Defaults:
- `shouldRunArchiveSweep`: 24h since last run.
- `shouldRunPromoteSweep`: 7d since last run.

**Module to ship:** `src/angel/curation-sweep.ts`:

```ts
export interface ArchiveResult { archived: number; }
export interface PromoteResult { promoted: number; }

export function sweepArchivePointers(db: Database, nowEpochMs: number, opts?: { ageMs?: number }): number;
export function sweepPromotePointers(db: Database, nowEpochMs: number, opts?: { minRecalls?: number }): number;

export function shouldRunArchiveSweep(nowEpochMs: number): boolean;   // 24h gate
export function markArchiveSweepRan(nowEpochMs: number): void;
export function shouldRunPromoteSweep(nowEpochMs: number): boolean;   // 7d gate
export function markPromoteSweepRan(nowEpochMs: number): void;
```

**Archive logic (CUR-17):**

```sql
-- Pointers eligible for demotion: 0 retrievals in last 90d AND no helpful_yn=1 EVER
SELECT lp.id, lp.project, lp.filename
FROM lesson_pointer lp
WHERE lp.source = 'lesson'
  AND NOT EXISTS (
    SELECT 1 FROM pointer_recall_log prl
    WHERE prl.pointer_id = lp.id
      AND prl.retrieved_at_epoch_ms > :cutoff_90d
  )
  AND NOT EXISTS (
    SELECT 1 FROM pointer_recall_log prl
    WHERE prl.pointer_id = lp.id AND prl.helpful_yn = 1
  );
```

For each row: read the lesson file, write back with `tier: background` in frontmatter. Use existing `parseLessonFile` + a new helper `setLessonTier(filePath, 'background')` (or extend `lesson-writer.ts` with a tier-only updater that re-emits frontmatter without rebuilding body). MEMORY.md's `renderLessons` (`memory-md-writer.ts:465`) already filters `(tier ?? 'foreground') === 'foreground'`, so flipping the field is enough — the next MEMORY.md rebuild surfaces the change.

**Promote logic (CUR-18):**

```sql
-- Pointers eligible for promotion: ≥3 retrievals AND ≥1 helpful_yn=1
SELECT lp.id, lp.project, lp.filename, COUNT(*) AS recall_count, MAX(prl.retrieved_at_epoch_ms) AS last_recall
FROM lesson_pointer lp
JOIN pointer_recall_log prl ON prl.pointer_id = lp.id
WHERE lp.source = 'lesson'
GROUP BY lp.id
HAVING recall_count >= 3
   AND SUM(CASE WHEN prl.helpful_yn = 1 THEN 1 ELSE 0 END) >= 1;
```

For each row: bump `last_fired_at_epoch` on the lesson frontmatter to now (this puts it at top of `## Lessons` since `renderLessons` sorts foreground entries by `last_fired_at_epoch DESC`). The "high-salience top of section" requirement is already met by 4.1's existing sort order — promotion is just an `last_fired_at_epoch` write.

**No demotion-from-top sweep needed.** As CONTEXT.md says: "Demotion from top occurs naturally if retrievals slow." `last_fired_at_epoch` ages naturally; other lessons get newer timestamps and outrank.

**Idempotency:**
- Archive: skipped if `tier === 'background'` already.
- Promote: skipped if `last_fired_at_epoch` is within last 24h (avoids a promoted pointer rewriting itself every weekly tick when it earned promotion last tick).

## 7. Connection to Phase 4.1's foreground/background tier

- The renderLessons foreground filter `(tier ?? 'foreground') === 'foreground'` is already correct; no changes needed there.
- The lesson-writer needs a partial-update mode (rewrite frontmatter only, preserve body byte-for-byte). Today it has `writeLesson(LessonWriteParams)` which takes the full body.

**Recommended ship:** add `updateLessonFrontmatter(filePath, partial: Partial<LessonFrontmatter>): void` to `src/angel/lesson-writer.ts`. Reads file via `parseLessonFile`, merges `partial` into frontmatter, re-renders, atomic-writes. Idempotent on no-op merges.

## 8. Risks + edge cases

1. **Cross-project pointers:** A pointer's `project` lives on `lesson_pointer.project`. The archive/promote sweeps must respect project boundaries — never cross-pollinate. The proposed SQL is project-agnostic (selects across all projects); the per-row file path is `~/.claude/projects/<encoded-project>/memory/<filename>`. Encoding follows the convention used by `lesson-writer` already; reuse it (don't re-derive).
2. **User-Notes pointers (`source='user_note'`):** CONTEXT.md says "## Lessons or ## User Notes". `## User Notes` is byte-preserved (`memory-md-writer.ts:583`). We CANNOT auto-archive a user-note line — that would require rewriting user-authored content, which violates the byte-preservation contract. **Recommendation:** for v1 (Phase 5.5), restrict archive + promote sweeps to `source='lesson'`. Log user-note recalls but do NOT mutate user-notes. Document this as a known scope cut in the SUMMARY. CONTEXT.md doesn't lock user-note auto-archive specifically; it's an edge case.
3. **`claudex_recall` artifact_ref → lesson detection:** `artifact_ref` is a free-form string. The recognition predicate must be tight: path-normalize, check if it matches `^.+[\\/]projects[\\/].+[\\/]memory[\\/](feedback|project|process)_[A-Za-z0-9-]+\.md$`. Pull the project segment from the path. Skip on non-match (no false positives).
4. **Race: archive sweep mid-write of a lesson.** Lesson writer uses tmp+rename (`writeLesson`). If sweep reads a lesson during a rename window, it sees either the old or new content — both safe. The reverse (sweep writes while another process reads) is also safe because of tmp+rename. **Action: ensure `updateLessonFrontmatter` also uses tmp+rename.**
5. **Schema migration on existing DBs:** V19 is additive — `lesson_pointer` and `pointer_recall_log` are both new. No data migration needed. Existing V18 DBs upgrade silently on next session-start.
6. **Heartbeat may race itself:** if a tick is slow, the next scheduled tick can overlap. Existing 5c sweeps tolerate this via SQL idempotency. The 5d sweeps are also idempotent (archive: skips if already background; promote: skips if recently bumped). Safe.
7. **Pointer-id stability across rename:** if a lesson file is renamed, it becomes a new pointer_id. Phase 5.5 does not rename lessons, but a future feature could. **Recommendation: leave this unsolved for Phase 5.5; document as known limitation.**
8. **Empty session at /endsession:** if no pointers retrieved, the list CLI emits nothing and the agent skips Step 1d silently. No "you had zero pointers, sorry" prompt — that adds friction.
