## Skill wire-up status: DEFERRED TO OPERATOR

Per CONTEXT.md authorization ("Plan 08 task 3's /endsession proposer skill-side wire-up may defer to operator if UX needs more design"), the CLI entry-point + /endsession skill changes are deferred. The library is shipped and ready for consumption:
- `proposeLessonsForSession(db, sessionId)` returns LessonProposal[] for the proposer to render
- `evaluateProcessTriggers(db, sessionId)` returns the trigger set for explainability
- `harvestTelemetry(db, sessionId)` is the deterministic telemetry surface

When the /endsession skill is wired up in a follow-up:
- Skill calls a CLI that invokes `proposeLessonsForSession`
- Output is JSON for the skill to render as a checklist
- User accept → skill calls `writeLesson` (Plan 04)
- User reject → skill records `lesson_proposal_declined` event so proposer skips the same content next session

## Decline tracking: DESIGNED

The proposer's output includes `proposed_slug`. A follow-up wire-up will SELECT `lesson_proposal_declined` events and filter out matching proposed_slug values. The lesson-types.ts schema already accommodates this; no DB migration needed.
