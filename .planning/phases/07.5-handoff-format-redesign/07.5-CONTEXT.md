# Phase 7.5: Handoff Format Redesign — Context

**Gathered:** 2026-04-29
**Status:** Ready for planning
**Generative axiom:** Handoff is the trajectory bridge between sessions. Format must be machine-queryable AND human-readable; current 372-line schema fails on both. Hybrid YAML status header + ADR body achieves both.

---

<domain>
## Phase Boundary

This phase delivers three things and only these three things:

1. **New handoff schema** — hybrid YAML status header (`status`, `phase`) + Markdown ADR body. ~15 lines target (down from 372). Format:
   ```yaml
   ---
   status: active
   phase: <N>
   ---
   # <date> — <topic>

   **What we found:** ...
   **What we decided:** ...
   **What's next:** ...
   **Where to look:** ...
   ```
2. **Writer in `src/angel/handoff-writer.ts`** (or equivalent) outputting the new shape. Phase 4.1's MEMORY.md `## Handoff` section consumes the YAML header for programmatic queryability.
3. **Migration** of existing handoff (`context/handoffs/ACTIVE.md`) to new shape. Old content preserved in archive subdirectory (`context/handoffs/archive/`).

**Out of scope:**
- Multi-handoff support (per-task or per-feature handoffs alongside ACTIVE.md) — current design is single-active
- Handoff search/query infrastructure beyond YAML frontmatter (later phase)
- Handoff conflict resolution (multiple writers — Angel doesn't have this problem today)

**Hard gates:**
- Vesna handoff-pickup probes pass against new format (SC#1)
- One-turn handoff pickup test (SC#4) verifies cold-start session resumes work without exploratory glob/grep
- Existing handoff content preserved in archive — no data loss during migration

</domain>

<decisions>
## Implementation Decisions

### Schema fields

YAML header (machine-queryable):
- `status: active | archived | paused` — required
- `phase: <N>` — required, integer or decimal phase identifier (matches ROADMAP)
- `created_at_epoch_ms: <ms>` — optional, auto-set by writer
- `topic: <slug>` — optional, short identifier for the handoff scope

Body (human-readable):
- `# <date> — <topic>` — title line (date in YYYY-MM-DD format)
- `**What we found:**` — discoveries / state observations
- `**What we decided:**` — locked decisions with rationale
- `**What's next:**` — concrete next-action(s) for pickup session
- `**Where to look:**` — file/artifact pointers

### Length target

- ~15 lines body (excluding YAML header + title) is the target for routine handoffs
- Exceptions allowed when context demands it (today's audit-rebind handoff was deliberately long because the trajectory was substantive)
- No hard cap; the principle is "no longer than necessary" not "no longer than 15"

### Writer responsibilities

- Live in `src/angel/handoff-writer.ts` (or planner-chosen equivalent)
- Triggered by `/handoff` skill or programmatic `pause-work`
- Writes valid YAML frontmatter + body
- Validates required fields (status, phase) before write — refuse on missing
- Atomic write (rename pattern) — never half-written handoff

### Migration of existing ACTIVE.md

- Read existing `context/handoffs/ACTIVE.md`
- If it has the new YAML shape: leave alone
- If it has the old 372-line schema: extract status + phase from existing fields, distill body content into the four `**What ...**` sections, archive original to `context/handoffs/archive/<date>-<topic>.md`
- Preserve original verbatim in archive — no destructive transformation

### MEMORY.md `## Handoff` section consumption

- 4.1's writer reads `ACTIVE.md` YAML header → renders `## Handoff` section in MEMORY.md
- If `status: archived`: render `No active handoff.`
- If `status: active`: render *"Active handoff at phase {phase}: {topic}. See: context/handoffs/ACTIVE.md"*
- If `status: paused`: render *"Handoff paused at phase {phase}. See: context/handoffs/ACTIVE.md"*
- One-line summary, NEVER the full body — body lives in ACTIVE.md only

### Vesna handoff-pickup probes

- Probes verify: a fresh session starts, reads new-format ACTIVE.md, picks up the next-action without exploratory tool use
- Per ROADMAP SC#4: ≥3 probes across ≥3 different projects covering active / paused / archived states

### Claude's Discretion (planner free to decide)

- Exact YAML field name conventions (`created_at_epoch_ms` vs `created` vs `ts` — recommendation: `created_at_epoch_ms` for symmetry with rest of v4 schema)
- Optional fields beyond `topic` (e.g., `assignee`, `priority` — recommendation: skip in 7.5; add only if Phase 8.5 observability needs them)
- Body section order (`What we found` → `What we decided` → `What's next` → `Where to look` is locked; nothing else)
- Migration script vs manual migration (recommendation: scripted for the conversion; planner reviews each migration before commit)

</decisions>

<specifics>
## Specific Ideas

- **YAML for machines, Markdown for humans** — hybrid avoids the trap of choosing one. Header carries programmatic state; body carries human reasoning. Both are first-class.
- **372 → 15 is not arbitrary** — 372 lines required template-fitting that produced cargo-culted handoffs. 15 lines forces distillation. Forcing function for clarity.
- **Single-active design is intentional** — Claudex tracks one active handoff per project. Multi-handoff opens coordination complexity that doesn't pay for itself at current scale. Revisit if user explicitly needs it.

</specifics>

<deferred>
## Deferred Ideas

- **Multi-handoff (per-task / per-feature)** — current design is single ACTIVE.md per project. Defer until concrete need.
- **Handoff search/query infrastructure** beyond frontmatter parsing — later phase or never.
- **Cross-project handoff correlation** ("this Lacuna handoff is similar to that Oracle one") — Phase 6.5 territory partially; defer the surfacing logic.

</deferred>
