# Phase 7.5 — Handoff Format Redesign — Closed 2026-04-29

Hybrid YAML status header + ADR Markdown body. Replaces the 372-line frontmatter-rigid schema with ~15 lines body. Writer + parser + validator landed; live `context/handoffs/ACTIVE.md` migrated with verbatim archive; MEMORY.md `## Handoff` rewired to one-line summary; 3 Vesna probes pass; baseline probes from Phase 6.5/Phase 7 still pass.

## What shipped

- **Hybrid YAML+ADR schema** (CONTEXT.md spec):
  - YAML header: `status` (active|archived|paused) + `phase` (string, supports decimals) + optional `summary`, `topic`, `created_at_epoch_ms`.
  - ADR body: `# <YYYY-MM-DD> — <topic>` then four locked sections in fixed order (`What we found`, `What we decided`, `What's next`, `Where to look`).
- **`src/angel/handoff-writer.ts`** — `writeHandoff` (atomic tmp+rename, throws on validation failure), `parseHandoffHeader` (returns null on shape failure), `validateHandoffHeader`, `renderHandoffMarkdown`, plus types `HandoffStatus | HandoffHeader | HandoffInput | HandoffValidationError`.
- **`src/angel/memory-md-writer.ts:renderHandoff`** rewritten — consumes `parseHandoffHeader`, emits one-line summary per status branch (`Active handoff at phase N: topic.\nSee: …` / `Handoff paused at phase N.\nSee: …` / `No active handoff.`). Body never leaked into MEMORY.md.
- **`distillHandoffBody` + `MAX_HANDOFF_LINES` deleted** (~50 LOC).
- **`context/handoffs/ACTIVE.md`** — migrated to new shape (status: active, phase: "4.1", summary present and contains "Phase 4.1"). Pre-migration ACTIVE.md (372-line transitional shape) preserved verbatim at **`context/handoffs/archive/2026-04-27-phase-4-1-design-discussion.md`**.
- **`scripts/migrate-handoff.ts`** — re-runnable migration tool. Three branches (already-new / transitional / legacy); idempotent; archives original verbatim before writing. Slug-derived archive filenames for general-purpose use.
- **3 Vesna probe contracts** at `src/benchmark/vesna/probes/handoff-pickup-{active,paused,archived}.json` documenting setup, user_prompt, assert/fail-signals.
- **Runtime Vesna gate** at `src/tests/integration/phase-7-5-handoff-pickup.test.ts` (5 tests across 4 describe blocks: active / paused / archived / SC#1 verdict).

## Vesna probe schema

Discovery (Plan 03 Task 01): the existing harness in this repo runs probes as vitest integration tests (`phase-6-5-cross-project-vesna.test.ts`, `phase-7-advisory-voice.test.ts`). There is **no JSON-driven probe runner** at `src/benchmark/vesna/`. Plan 03's decision rule said: "If the harness change is more than ~15 lines, defer it to Phase 11 and tag-via-existing-category instead."

Chosen approach: ship JSON probe contracts AS specification documents (machine-readable, auditable, future-runner-compatible) AND ship the actual probe execution as a vitest integration test. The JSON `.runtime` field points at the test file. This satisfies CONTEXT.md's behavioral spec (the probe runs end-to-end against the new format) while preserving the harness conventions Phase 6.5/Phase 7 established.

Future Phase 10 ("Vesna probe suite as central validation") can promote these into a JSON-driven runner if/when the broader Vesna harness lands. The contracts will compose forward.
