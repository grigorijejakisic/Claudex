**src/intelligence/decision-capture.ts** — Pure extraction logic + DB storage. Non-throwing.

```typescript
export interface CapturedDecision {
  content: string;
  source: 'confirmation' | 'direction' | 'rejection' | 'explicit';
  tier: 1 | 2 | 3 | 4;
}
```

`captureDecisions(params: { db: Database; sessionId: string; project: string; userText?: string; assistantText?: string; mode: 'after_turn' | 'after_tool' }): CapturedDecision[]` — Main entry point:

1. If `mode === 'after_tool'`, only check Tier 1 (user confirmations) and Tier 4 (explicit markers). Skip Tiers 2 and 3 (they need full-turn context).
2. If `mode === 'after_turn'`, check all 4 tiers.
3. Run extraction on appropriate text sources (userText for Tier 1/3/4, assistantText for Tier 2).
4. For each candidate: apply filler rejection, code fence skip, length check.
5. Dedup against existing session decisions: `getDecisionsBySession(db, sessionId)` then `isDuplicate(candidate, existing.content)` for each. Skip if duplicate found.
6. Store via `insertDecision(db, { session_id, project, content, source, fingerprint: normalizeForDedup(content) })`.
7. Return array of captured decisions (may be empty).

**Tier 1 — Explicit confirmation** (check userText):
- Pattern: `^(yes|yeah|yep|ok|okay|go|approved|confirmed|do it|proceed|looks good|lgtm|ship it|agreed|correct|exactly|perfect|that works)\b` (case-insensitive)
- When matched: the captured decision content is the LAST assistant message (assistantText) — the thing being confirmed
- If no assistantText available, use the user's confirmation text itself
- Source: `'confirmation'`

**Tier 2 — Direction-setting** (check assistantText):
- Structural patterns (case-insensitive, test each line of assistantText):
  - Line starts with imperative/future verb: `^(use|implement|create|add|remove|replace|switch|migrate|keep|drop|split|merge|deploy|configure|set|enable|disable)\b`
  - Contains comparison resolution: `\b(instead of|rather than)\b` or `\bnot\s+\w+\s+but\b`
  - Contains commitment: `\bwill\s+(use|implement|do|create|go with)\b` or `\bgoing to\b` or `\bthe\s+(plan|approach|strategy|design)\s+is\b`
  - Contains recommendation: `\b(should|recommend|suggest|propose|best to|better to|prefer)\b`
- Quality gate: candidate line must be >= 20 chars, not a filler phrase
- Capture: the matching line (trimmed)
- Source: `'direction'`

**Tier 3 — Rejection** (check userText):
- Pattern: user message contains `\b(no,|don't|actually,|instead\b|not that|wrong|stop|revert|undo|that's not|scratch that)\b` (case-insensitive)
- Capture: the user's rejection text (full userText, trimmed)
- Source: `'rejection'`

**Tier 4 — Explicit decision markers** (check both userText and assistantText):
- Pattern: `(DECISION:|decided:|we agreed|final answer|conclusion:|verdict:|going with:|chosen approach:)` (case-insensitive)
- Capture: the sentence containing the marker
- Source: `'explicit'`

**Filler rejection** — Drop any candidate matching (case-insensitive):
- `^(let me|looking at|checking|I see|examining|opening|searching|running|reading)\b`
- `^(hi|hello|hey|thanks|thank you|sure|ok|great|nice|good|alright)\b` (standalone greetings/acks — only if the ENTIRE message is <= 15 chars)
- Any candidate under 15 chars total

**Code fence skip** — Before extraction, strip content between ``` markers from the text being analyzed. Decisions inside code blocks are not real decisions.

**src/intelligence/thread-tracker.ts** — Stateful class (holds in-memory buffer between after_tool calls). Non-throwing.

```typescript
export class ThreadTracker {
  private db: Database;
  private sessionId: string;
  private pendingExchanges: Array<{ role: string; raw: string }>;
  private topic: string | null;
  private keyExchanges: Array<{ role: string; gist: string }>;
  private summary: string | null;

  constructor(db: Database, sessionId: string)
}
```

`constructor(db, sessionId)` — Load existing thread state from DB via `getThreadState(db, sessionId)`. If exists, restore topic, keyExchanges, summary. Otherwise start fresh. Initialize pendingExchanges as empty.

`onAfterTool(userText: string | undefined, toolName: string, toolInput: Record<string, unknown>): void` — Called during after_tool event:
- If userText provided and no pending user exchange yet this turn, add `{ role: 'user', raw: userText }`
- Add `{ role: 'tool', raw: toolName + ': ' + summarizeToolInput(toolName, toolInput) }`
- Do NOT flush or persist — just accumulate

`onAfterTurn(userText: string | undefined, assistantText: string | undefined): void` — Called during after_turn event:
- If userText and no user exchange in pending buffer, add user entry
- If assistantText, add agent entry
- Flush pending buffer → extract gists → append to keyExchanges
- Update topic if not yet set (first substantive message)
- Update summary
- Persist to DB via `upsertThreadState`
- Clear pending buffer

**Gist extraction** — `extractGist(role: string, raw: string): string`:
- If raw length <= 120: return raw as-is
- If raw length > 120: find last sentence boundary (`.`, `!`, `?`) before char 120. If found, truncate there. Otherwise truncate at 120 with "..."
- For agent messages that look like tool-call-only (no prose — heuristic: starts with `[` or contains only tool references): format as `[called {toolNames} on {files}]`
- Max 120 chars always

**Topic extraction** — `extractTopic(text: string): string`:
- Skip if text is a greeting or short confirmation (< 20 chars, or matches greeting pattern)
- Take first sentence (up to first `.`, `!`, `?`, or end of string)
- Remove stop words (reuse STOP_WORDS from semantic-dedup or define locally)
- Trim to 5-15 words
- If result is too short (< 3 words), use original first sentence truncated to 60 chars

**Summary construction** — `buildSummary(): string`:
- Format: `"{topic}. {last 2-3 agent gists joined with '. '}."`
- If no topic: omit topic prefix
- Select last 2-3 entries from keyExchanges where role === 'agent'
- If no agent gists: return topic alone (or empty string)

**Key exchanges window** — Rolling window of 8:
- When appending, if keyExchanges.length >= 8, shift (remove oldest) before pushing
- Collapse pending buffer into gisted user/agent pairs before appending

**Persist** — `persist(): void`:
- `upsertThreadState(db, { session_id: sessionId, topic, summary, key_exchanges: keyExchanges })`
- Called at end of onAfterTurn, and can be called externally for checkpoint writes

Helper `summarizeToolInput(toolName: string, input: Record<string, unknown>): string`:
- Extract key field for each tool: file_path/filePath for Read/Edit/Write, command for Bash, pattern for Grep/Glob, url for WebFetch, query for WebSearch
- Return as short string, max 80 chars

**src/intelligence/learnings-promoter.ts** — Pure functions with DB. Non-throwing.

`promoteLearnings(params: { db: Database; project: string; agentId?: string; sessionLearnings: string[] }): { promoted: number; inserted: number; pruned: number }` — Main entry point:

For each learning in sessionLearnings:
1. **Fingerprint**: `normalizeForDedup(learning)` from semantic-dedup
2. **Dedup check**: `getLearningsByProject(db, project, { limit: 50 })` to get existing learnings. Call `findDuplicate(learning, existingLearnings)` (matching on content field).
3. **If duplicate found**: The existing learning's fingerprint is used for the upsert. `upsertLearning(db, { project, agent_id: agentId ?? 'default', fingerprint: existingLearning.fingerprint, content: existingLearning.content })` — this triggers the ON CONFLICT DO UPDATE path, incrementing promotion_count. Count as "promoted".
4. **If no duplicate**: `upsertLearning(db, { project, agent_id: agentId ?? 'default', fingerprint: normalizeForDedup(learning), content: learning })` — this inserts a new learning with promotion_count=1. Count as "inserted".
5. **Cap enforcement**: After all inserts/promotions, check count. Query `getLearningsByProject(db, project, { limit: 100 })`. If count > 50, delete the excess rows (lowest promotion_count, oldest last_promoted_epoch). Use direct SQL: `DELETE FROM learnings WHERE id IN (SELECT id FROM learnings WHERE project = ? AND agent_id = ? ORDER BY promotion_count ASC, last_promoted_epoch ASC LIMIT ?)` where limit = count - 50. Count as "pruned".
6. Return `{ promoted, inserted, pruned }`.

Non-throwing: wrap entire function in try/catch, return `{ promoted: 0, inserted: 0, pruned: 0 }` on error.
