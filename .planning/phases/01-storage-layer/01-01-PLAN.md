  <action>
**src/core/storage.ts** — Plain functions, `db: Database` as first param (per user decision).

`openDatabase(path: string): Database` — Creates/opens SQLite database at path. Sets 4 PRAGMAs exactly as Architecture Section 4.1:
- `journal_mode = WAL`
- `synchronous = NORMAL`
- `cache_size = 10000`
- `foreign_keys = ON`

Returns the Database instance. No lazy init, no singleton.

`closeDatabase(db: Database): void` — Calls `db.close()`. Defensive: wrap in try/catch, non-throwing.

Export the `Database` type from `better-sqlite3` for downstream consumers.

**src/core/migrations.ts** — Three exported functions:

`initializeSchema(db: Database): void` — Executes ALL DDL from Architecture Section 4.2 schema (9 tables + FTS5 virtual table + 3 FTS triggers + all indexes) PLUS the telemetry table from Section 10c (table + 2 indexes). Records schema version: `INSERT OR IGNORE INTO schema_versions (version) VALUES (300)`.

The SQL should be stored as template literal constants (SCHEMA_V3 and TELEMETRY_SCHEMA) for readability. Include:
- observations (with category CHECK constraint, json_valid on files_modified, soft delete)
- observations_fts (FTS5 with porter unicode61 tokenizer)
- 3 FTS sync triggers (observations_ai, observations_ad, observations_au)
- 5 observation indexes (session, project, timestamp, importance, deleted)
- sessions (with status CHECK constraint)
- pressure_scores (composite PK on file_path+project, temperature CHECK)
- learnings (with UNIQUE on project+agent_id+fingerprint)
- learnings index (project+agent_id+promotion_count DESC)
- decisions (with source CHECK, UNIQUE on session_id+fingerprint)
- decisions index (session_id+timestamp_epoch DESC)
- thread_state (json_valid on key_exchanges)
- checkpoint_tracking (json_valid on thresholds_hit)
- schema_versions
- checkpoint_meta (with trigger CHECK, status CHECK)
- 2 checkpoint_meta indexes (session+created_at DESC, status+updated_at)
- telemetry (with event_kind CHECK for 10 kinds, json_valid on detail)
- 2 telemetry indexes (session+timestamp DESC, kind+timestamp DESC)

All CREATE statements use `IF NOT EXISTS` for idempotency.

`migrateFromV2(db: Database, v2DbPath: string): void` — Implements Architecture Section 4.3.2 migration SQL:
1. ATTACH v2 database
2. Create new v3 tables (CREATE IF NOT EXISTS — safe re-run)
3. Copy observations, sessions, pressure_scores from v2 (INSERT OR IGNORE to avoid dupes)
4. Archive unused v2 tables (ALTER TABLE ... RENAME TO _archived_...)
5. Simplify pressure_scores (UPDATE temperature SET 'COLD' WHERE 'WARM')
6. Migrate checkpoint_state to checkpoint_tracking
7. Fix files_modified from comma-separated to JSON array
8. Record schema version 300
9. DETACH v2 database
Wrap entire migration in a transaction for atomicity.

`detectV2Database(): string | null` — Check `~/.claudex/claudex.db` and `~/.claudex/db/claudex.db`. If found and schema version < 300, return path. Use `getClaudexHome()` from shared/paths.ts. Non-throwing.
