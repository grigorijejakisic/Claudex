<objective>
Build the explicit one-time backfill (re-runnable, idempotent) that populates `episodic_events.metadata_json.error_fingerprint` and the `episodic_index_error_fingerprint` sidecar from two sources:

1. **Phase 1 organic** — `episodic_events` rows where `provenance='tool_result'` AND `ts_epoch >= 2026-05-04 00:00 UTC` (Phase 1 ship commit `9434ab9`). Fingerprint computed; written to both `metadata_json` AND sidecar; sidecar tagged `corpus_origin='phase1_organic'`.
2. **v4 artifact observations** — rows in the legacy `artifacts` table (per CONTEXT item 2 "v4 `artifact` rows where `kind='observation'` and content matches typical stack-trace shapes"). Fingerprints computed; written to sidecar ONLY (v4 artifacts retain their original storage; we DO NOT mutate them); sidecar tagged `corpus_origin='v4_backfill'`. The sidecar's `episode_event_id` for v4 rows points to a synthetic episodic_events shadow row with `provenance='environmental'` and `source='backfill/v4-artifact'` so the FK resolves and the harness has a stable handle (the shadow row pattern keeps the sidecar schema consistent without inventing a parallel index for v4-only rows).

Purpose: Per CONTEXT item 6 "Explicit one-time pass during Phase 2 setup. Not opportunistic at query time." Without this backfill, the corpus is too small to clear the 50-event floor and the measurement harness has nothing to score.

Output: A re-runnable backfill module + CLI; a corpus audit report; the sidecar table populated to ≥50 fingerprinted events spanning ≥3 projects; legacy `conversation_turns` untouched.
</objective>

Create `src/benchmark/episodic-density/backfill.ts` exporting `runBackfill(db: Database, opts?: { dryRun?: boolean }): Promise<BackfillSummary>`. The module must:

1. **Phase 1 organic backfill (`backfillPhase1Organic`)**:
   - SELECT `id, project, ts_epoch, content, metadata_json` FROM episodic_events WHERE `provenance='tool_result'` AND `ts_epoch >= ?` (PHASE1_SHIP_TS_EPOCH).
   - For each row: call `computeErrorFingerprint(content)`. If null, skip. Otherwise:
     - Parse existing `metadata_json` (or `{}` if null), splice in `error_fingerprint: fp`, write back via `UPDATE episodic_events SET metadata_json = ? WHERE id = ?`. This is the ONLY column on episodic_events the backfill mutates.
     - For each shingle in `fp.shingles`, write a sidecar row: `INSERT OR IGNORE INTO episodic_index_error_fingerprint (shingle_hash, episode_event_id, ts_epoch, project, corpus_origin) VALUES (?, ?, ?, ?, 'phase1_organic')`. The OR IGNORE makes re-runs idempotent if a uniqueness path is added later (none today, but the discipline costs nothing and matches the v4 backfill pattern in this codebase).
   - Wrap each row's writes in a per-row `db.transaction(() => ...)()` so a single bad row can't corrupt the run.

2. **v4 artifact backfill (`backfillV4Artifacts`)**:
   - First confirm the table and column shape via `pragma('table_info(artifacts)')`. Per CONTEXT item 2 the source filter is "rows whose content matches typical stack-trace shapes." Implement as: SELECT all rows where the artifact_type / kind column indicates an observation (the audit doc — Task 4 — must specify the exact column/value pair you used; CONTEXT discretion: "heuristic regex is fine; the corpus_origin tag means a sloppy heuristic only contaminates one slice, doesn't destroy the corpus").
   - For each row: call `looksLikeStackTrace(content)` then `computeErrorFingerprint(content)`. If null, skip.
   - For each fingerprinted v4 row, INSERT a shadow `episodic_events` row: `provenance='environmental'`, `source='backfill/v4-artifact'`, `type='backfill_v4_artifact'`, `content=<original artifact content>`, `metadata_json=JSON.stringify({ error_fingerprint: fp, source_table: 'artifacts', source_row_id: <id>, corpus_origin: 'v4_backfill' })`. Use `writeEnvironmentalEvent` from `src/core/episodic-events.ts` to keep the writer surface consistent with Phase 1.
   - For each shingle, write a sidecar row tagged `corpus_origin='v4_backfill'` with `episode_event_id` pointing to the shadow row.
   - Idempotency: before inserting, check if a shadow row with `metadata_json` containing `source_table='artifacts'` AND `source_row_id=<id>` already exists; if so, skip. Cheap secondary index: `SELECT id FROM episodic_events WHERE source='backfill/v4-artifact' AND json_extract(metadata_json, '$.source_row_id') = ?`.

3. **Floor check** at end of backfill: count distinct fingerprinted events and distinct projects in the sidecar. Set `floor_met = total_fingerprinted >= FLOOR_FINGERPRINTED && total_projects >= FLOOR_PROJECTS`. Return BackfillSummary; do NOT throw if the floor isn't met (the CLI in Task 3 handles exit code).

4. **`runBackfill(db, opts)`** orchestrates: open a single read transaction (to enumerate rows), then runs the two backfills serially (organic first, v4 second), assembles BackfillSummary, returns it. Honor `opts.dryRun` (default false): when true, every write path is skipped but counts are reported as if it ran (useful for the audit doc generation).

5. **Logging**: minimal stderr progress (`console.error('backfill: scanned X organic rows, Y fingerprinted')`) — no telemetry, no DB writes for status.

**Avoid:**
- Reading `conversation_turns` — explicitly forbidden by CONTEXT specifics ("Backfill is forbidden for legacy conversation_turns").
- Mutating any column on `episodic_events` other than `metadata_json` for organic rows. Provenance, content, ts_epoch must stay byte-identical.
- Writing to `legacy` v4 tables (artifacts, observations, learning) — backfill READS v4, never writes to it.
- Calling out to Ollama, the reranker, or any network service — fingerprinter is pure CPU and that's the point.
- Computing fingerprints in parallel — single-threaded, deterministic order. (Concurrency is not a measurement need.)
- Producing duplicate shadow rows on re-run — the json_extract idempotency check is non-optional.
