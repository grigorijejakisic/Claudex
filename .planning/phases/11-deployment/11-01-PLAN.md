**# Claudex v3 Deployment Guide**

Brief intro: Claudex v3 runs as CC lifecycle hooks or an OpenClaw bridge plugin. This guide covers fresh install, optional v2 migration, monitoring, and predecessor archiving.

---

**## Prerequisites**

Common requirements:
- Node.js 20+ (runtime for hooks and setup CLI)
- bun 1.3+ (build toolchain)
- Git (to clone the repository)

CC-specific:
- Claude Code installed with hooks support
- `~/.claude/settings.json` writable

OpenClaw-specific:
- OpenClaw gateway with plugin support
- Plugin directory accessible

Optional:
- Ollama with `nomic-embed-text` model (for embedding-enhanced topic-shift detection and enrichment; system works without it via Jaccard fallback)

---

**## CC Hook Adapter — Fresh Install**

Step-by-step:
1. Clone repository: `git clone <repo-url> CLAUDEXv3 && cd CLAUDEXv3`
2. Install dependencies: `bun install`
3. Build: `bun run build`
4. Run setup: `node dist/setup.js`

What setup does (reference setup.ts):
- Creates `~/.claudex/` directory structure (`db/`, `identity/`)
- Initializes SQLite database at `~/.claudex/db/claudex.db` with full v3 schema
- Writes default `~/.claudex/config.json` (if not present)
- Patches `~/.claude/settings.json` with 6 hook entries (preserves existing hooks)

Expected output:
```
Claudex v3 Setup
================

[OK] Directory structure created: C:\Users\<user>\.claudex
[OK] Database initialized: C:\Users\<user>\.claudex\db\claudex.db
[OK] Config written: C:\Users\<user>\.claudex\config.json
[OK] Hook paths registered in: C:\Users\<user>\.claude\settings.json
```

Verification:
- `~/.claudex/db/claudex.db` exists (non-empty)
- `~/.claude/settings.json` contains 6 Claudex hook entries (SessionStart, UserPromptSubmit, PostToolUse, Stop, PreCompact, SessionEnd)
- Start a new Claude Code session — Claudex should initialize silently (no errors in terminal)

---

**## OpenClaw Bridge Adapter — Plugin Install**

Build target: `dist/plugin-entry.js`

Steps:
1. Build the project: `bun run build` (if not already done)
2. Copy or reference `dist/plugin-entry.js` in OpenClaw's plugin configuration
3. Ensure `better-sqlite3` native binding is accessible from the OpenClaw runtime
4. Plugin activates via `globalThis[Symbol.for('claudex.bridge')]` registration

Verification:
- OpenClaw gateway loads without errors
- Plugin registers on `globalThis` and receives callbacks (onInit, onContext, onToolResult, onTurnEnd, onCompact)
- Context injection appears at session start

Note: OpenClaw is a separate project. Detailed plugin installation depends on the OpenClaw version and configuration format.

---

**## Optional v2 Migration**

For existing Claudex v2 users who want to preserve observation history:

Prerequisites:
- Existing v2 database at `~/.claudex/db/claudex.db` (or `~/.claudex/claudex.db`)
- v2 schema version < 300

Process:
1. Run `node dist/setup.js` — setup detects v2 database automatically
2. Setup displays v2 statistics (observation count, session count, pressure scores)
3. Prompt: `Migrate v2 data? [y/N]`
4. If accepted: backup created at `~/.claudex/db/claudex.db.v2-backup`, then migration runs

Migration actions (from Architecture Section 4.3.2):
- New v3 tables added (learnings, decisions, thread_state, checkpoint_tracking, checkpoint_meta, telemetry)
- Unused v2 tables archived (renamed with `_archived_` prefix)
- WARM pressure tier converted to COLD
- `files_modified` converted from comma-separated to JSON array
- Schema version set to 300

Rollback:
- Swap hook paths in `~/.claude/settings.json` back to v2 hook locations
- v2 ignores `_archived_` tables and new v3 tables
- Or restore from backup: copy `claudex.db.v2-backup` to `claudex.db`

Non-interactive mode:
- If stdin is not a TTY (e.g., CI), migration prompt is auto-declined
- Setup proceeds with fresh v3 schema alongside existing data

**## Monitoring Checklist**

After deployment, monitor for 1 week using these telemetry queries against `~/.claudex/db/claudex.db`:

**Error events (should be zero or near-zero):**
```sql
SELECT kind, detail, created_at
FROM telemetry
WHERE kind = 'error'
ORDER BY created_at DESC
LIMIT 20;
```

**Observation capture rate (should show steady accumulation):**
```sql
SELECT DATE(timestamp) as day, COUNT(*) as obs_count
FROM observations
WHERE deleted = 0
GROUP BY DATE(timestamp)
ORDER BY day DESC
LIMIT 7;
```

**Checkpoint write success (should show regular writes):**
```sql
SELECT status, COUNT(*) as count
FROM checkpoint_meta
GROUP BY status;
-- Expected: mostly 'mirrored', few or zero 'pending'
```

**Assembly latency distribution:**
```sql
SELECT kind, AVG(latency_ms) as avg_ms, MAX(latency_ms) as max_ms, COUNT(*) as count
FROM telemetry
WHERE kind IN ('assembly_full', 'assembly_regular', 'assembly_pivot')
GROUP BY kind;
-- Expected: assembly_regular avg < 100ms, assembly_full avg < 500ms
```

**Session lifecycle completeness:**
```sql
SELECT status, COUNT(*) as count
FROM sessions
GROUP BY status;
-- Expected: mostly 'completed', few 'active' (current session only)
```

**Learnings promotion (should accumulate over sessions):**
```sql
SELECT content, promotion_count, created_at
FROM learnings
ORDER BY promotion_count DESC
LIMIT 10;
```

**Hot files tracking:**
```sql
SELECT file_path, score, temperature
FROM pressure_scores
WHERE temperature = 'HOT'
ORDER BY score DESC
LIMIT 10;
```

Success indicators:
- Zero crash-level errors in telemetry
- Observations accumulating daily
- Checkpoints writing and reaching 'mirrored' status
- Assembly latencies within SLA (regular < 100ms, full < 500ms, aggregate < 600ms)
- Sessions completing normally
- Learnings promoting across sessions

**## Troubleshooting**

**better-sqlite3 binding mismatch:**
- Symptom: `Error: The module was compiled against a different Node.js version`
- Fix: `npm rebuild better-sqlite3` or `bun install` to recompile for current Node version

**settings.json format errors:**
- Symptom: Claude Code reports hook configuration error
- Fix: Verify `~/.claude/settings.json` has valid JSON. Run `node dist/setup.js` again (idempotent).
- Expected hook format:
  ```json
  {
    "hooks": {
      "SessionStart": [
        { "matcher": "", "hooks": [{ "type": "command", "command": "node /path/to/CLAUDEXv3/dist/session-start.js" }] }
      ]
    }
  }
  ```

**Database lock errors:**
- Symptom: `SQLITE_BUSY` or `database is locked`
- Cause: Multiple processes accessing DB simultaneously without WAL mode
- Fix: Verify DB opened with WAL mode (`PRAGMA journal_mode` should return 'wal')

**Ollama not running (non-critical):**
- Symptom: Telemetry shows `embedding_unavailable` events
- Impact: Topic-shift detection falls back to Jaccard similarity, enrichment uses heuristic-only path. System works correctly without Ollama.
- Fix: Install Ollama, run `ollama pull nomic-embed-text`, start Ollama service

**Setup fails with permission error:**
- Symptom: `[ERROR] Setup failed: EACCES` or `EPERM`
- Fix: Ensure write permissions to `~/.claudex/` and `~/.claude/` directories

**Hook not firing:**
- Symptom: No observations being captured, context not injecting
- Debug: Check `~/.claude/settings.json` hook paths point to existing files in `dist/`
- Verify: `node dist/session-start.js < /dev/null` should exit without error (may print empty output)
