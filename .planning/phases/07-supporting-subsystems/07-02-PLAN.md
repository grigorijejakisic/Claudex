**src/gsd/types.ts** — GSD state interfaces.

```typescript
export interface GsdState {
  phase: number;
  plan: number;
  status: string;
  goal: string;
  success_criteria: string[];
  completion: string;  // e.g. "4/6 requirements met"
}

export interface GsdPhaseInfo {
  phase: number;
  name: string;
  goal: string;
  success_criteria: string[];
  status: string;  // 'Complete', 'Not started', 'In progress'
}
```

**src/gsd/state-reader.ts** — Read-only .planning/ filesystem reader. Non-throwing.

Import `fs` and `path`. Import types from `./types.js`.

`readGsdState(projectDir: string): GsdState | null`:
- Check if `.planning/STATE.md` exists in projectDir. If not, return null.
- Read STATE.md content
- Parse with regex:
  - Phase number: `/Phase:\s*(\d+)/` (look for "Phase: N" pattern)
  - Plan number: `/Plan:\s*(\d+)/` (look for "Plan: N" pattern)
  - Status: `/Status:\s*(.+)/` (look for "Status: ..." pattern, trim result)
- Read ROADMAP.md (if exists) to get the goal and success criteria for the current phase:
  - Find the phase section by matching `### Phase {N}:` header
  - Extract **Goal**: line after the header
  - Extract **Success Criteria**: lines starting with numbered items under Success Criteria heading
- Count requirements completion from ROADMAP.md progress table or from plan files:
  - Look for `- [x]` and `- [ ]` checkboxes in the current phase's plan files
  - Scan `.planning/phases/` for directory matching current phase number
  - Read all `*.md` files (plan files) in that directory, count checkboxes
  - Format as "N/M requirements met"
- Construct and return GsdState
- Non-throwing (return null on any parse/read error)

`getPhaseFiles(projectDir: string, phase: number): string[]`:
- Scan `.planning/phases/` for directory matching the phase number
  - Directory naming convention: directories contain the zero-padded phase number (e.g., `00-repository-setup`, `07-supporting-subsystems`)
  - Match by checking if directory name starts with zero-padded phase number
- Read all `*-PLAN.md` files in the matched directory
- Extract file paths mentioned in `files_modified:` YAML frontmatter sections
  - Parse lines after `files_modified:` that start with `  - ` until next non-indented line
- Return array of unique file paths (relative to project)
- These are the files that get +0.10 pressure boost when GSD is active
- Non-throwing (return empty array on error)

Internal helper `parseStateMd(content: string): { phase: number; plan: number; status: string } | null`:
- Apply regex patterns to extract phase, plan, status
- Return null if any required field cannot be parsed
- Also handle "Phase: N of M" format (extract just the first number)

Internal helper `parsePhaseFromRoadmap(content: string, phase: number): { goal: string; successCriteria: string[] } | null`:
- Find the section for the given phase number
- Extract goal from the **Goal**: line
- Extract success criteria from numbered list items under **Success Criteria**
- Return null if phase section not found

Internal helper `countCheckboxes(dir: string): { checked: number; total: number }`:
- Read all .md files in the directory
- Count `- [x]` patterns (checked) and `- [ ]` patterns (unchecked)
- total = checked + unchecked
- Return counts
