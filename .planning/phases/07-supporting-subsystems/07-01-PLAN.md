Token gauge, window detector, decay engine, and stratified pressure decay: the runtime engines that track utilization, manage data lifecycle, and maintain pressure freshness.

Purpose: The token gauge enables context-aware injection decisions (gauge at >= 70%, checkpoint thresholds). The decay engine prevents unbounded data growth by computing effective importance and pruning stale observations. **src/gauge/token-gauge.ts** — Capability-aware token utilization gauge. Non-throwing.

Import `TokenUsage`, `RuntimeCapabilities` from `../shared/types.js`. Import `detectWindowSize` from `./window-detector.js`. Import `fs` for file reading.

```typescript
export interface GetTokenGaugeParams {
  capabilities: RuntimeCapabilities;
  transcriptPath?: string;
  nativeUsage?: TokenUsage;
  model?: string;
}
```

`getTokenGauge(params: GetTokenGaugeParams): TokenUsage | null`:
- Path 1 (OpenClaw native): If `capabilities.hasNativeContextUsage` is true AND `nativeUsage` is provided:
  - Return `nativeUsage` directly (zero-cost path)
- Path 2 (CC transcript): If `capabilities.hasTranscriptAccess` is true AND `transcriptPath` is provided:
  - Call `readTranscriptTail(transcriptPath, model)` internal helper
  - Return result or null
- If neither capability applies: return null
- Non-throwing (return null on error)

Internal helper `readTranscriptTail(transcriptPath: string, model?: string): TokenUsage | null`:
- Read the tail of the file: open file, seek to max(0, fileSize - 8192), read to end
- On Windows, use `fs.openSync` + `fs.readSync` with position parameter for efficient tail reading
- Split content by newlines, filter non-empty lines
- Iterate lines in **reverse** order (most recent first)
- For each line: try `JSON.parse(line)`, look for `message.usage.input_tokens` field
  - Also check for `message.usage.output_tokens` if available
  - CC transcript JSONL format: each line is a JSON object with potentially nested `message.usage` field
  - Also check root-level `usage.input_tokens` as an alternative shape
- Once found: compute utilization and return TokenUsage:
  - `inputTokens`: from parsed usage
  - `outputTokens`: from parsed usage (or 0 if not present)
  - `contextWindowTokens`: from `detectWindowSize({ model, observedTokens: inputTokens })`
  - `utilization`: `inputTokens / contextWindowTokens`
- If no usage found after scanning all tail lines: return null
- Non-throwing (return null on any read/parse error)

**src/decay/decay-engine.ts** — EI computation, observation pruning, and retention policy. Non-throwing public API.

Import `Database` from `better-sqlite3`. Import `ObservationRow` from `../core/observations.js`.

Constants (exported for testing):
```typescript
export const BASE_WEIGHTS: Record<number, number> = { 1: 0.2, 2: 0.4, 3: 0.6, 4: 0.8, 5: 1.0 };
export const HALF_LIVES: Record<number, number> = { 1: 7, 2: 14, 3: 60, 4: 90, 5: 365 };
export const IMMUNITY_ACCESS_COUNT = 3;
export const IMMUNITY_ACCESS_DAYS = 180;
```

`computeEI(obs: { importance: number; accessCount: number; lastAccessedAtEpoch: number | null; timestampEpoch: number; coOccurrences: number }): number` — Pure function, no DB access:
- `baseWeight` = `BASE_WEIGHTS[obs.importance]` (default 0.2 if unknown)
- `accessFactor` = `1 + Math.log2(1 + obs.accessCount)`
- `ageDays` = `(Date.now() / 1000 - obs.timestampEpoch) / 86400` (clamp to 0 minimum)
- `halfLife` = `HALF_LIVES[obs.importance]` (default 7)
- `effectiveHL` = `halfLife * (1 + 0.15 * obs.accessCount)`
- `decayFactor` = `Math.pow(2, -ageDays / effectiveHL)`
- `connectivityBonus` = `1.0 + 0.1 * Math.min(obs.coOccurrences, 5)`
- Return `baseWeight * accessFactor * decayFactor * connectivityBonus`

`getCoOccurrences(db: Database, observationId: number, filesModified: string): number` — Count co-occurring observations:
- Parse `filesModified` JSON array
- If empty or parse fails: return 0
- For each file in the array: count distinct observations sharing that file via `SELECT COUNT(DISTINCT id) FROM observations WHERE id != ? AND deleted_at_epoch IS NULL AND files_modified LIKE ?`
  - Use `%"filepath"%` LIKE pattern (per 02-02 decision)
- Sum and cap at 5 (the formula already caps, but limit the query cost)
- Timeout guard: track elapsed time, if > 100ms return partial result (or 0)
- Non-throwing (return 0 on error)

`pruneObservations(db: Database, project: string, opts?: { pruneThreshold?: number; pruneCount?: number }): number` — Prune lowest-EI observations:
- Count non-deleted observations: `SELECT COUNT(*) FROM observations WHERE project = ? AND deleted_at_epoch IS NULL`
- If count <= pruneThreshold (default 1000): return 0 (nothing to prune)
- Query all non-deleted, non-immune observations:
  - Immune if: `importance >= 5`
  - Immune if: `access_count >= 3 AND last_accessed_at_epoch IS NOT NULL AND last_accessed_at_epoch > unixepoch() - (180 * 86400)`
  - Query: `SELECT id, importance, access_count, last_accessed_at_epoch, timestamp_epoch, files_modified FROM observations WHERE project = ? AND deleted_at_epoch IS NULL AND importance < 5 AND NOT (access_count >= 3 AND last_accessed_at_epoch IS NOT NULL AND last_accessed_at_epoch > unixepoch() - ?)`
- For each: compute EI (with co-occurrence lookup)
- Sort by EI ascending (lowest first)
- Soft-delete the lowest `pruneCount` (default 50) by setting `deleted_at_epoch = unixepoch()`
- Return count of pruned observations
- Non-throwing (return 0 on error)

`applyRetentionPolicy(db: Database, project: string, retentionDays?: number): number` — Hard-delete old observations:
- Default retentionDays: 90
- Statement 1: Delete soft-deleted observations older than retentionDays:
  ```sql
  DELETE FROM observations
  WHERE project = ? AND deleted_at_epoch IS NOT NULL
    AND deleted_at_epoch < unixepoch() - (? * 86400)
  ```
- Statement 2: Delete non-deleted observations older than retentionDays with importance < 5:
  ```sql
  DELETE FROM observations
  WHERE project = ? AND deleted_at_epoch IS NULL
    AND timestamp_epoch < unixepoch() - (? * 86400)
    AND importance < 5
  ```
- Return total rows deleted
- Non-throwing (return 0 on error)

**src/decay/pressure-decay.ts** — Stratified half-life pressure decay. Non-throwing.

Import `Database` from `better-sqlite3`.

`decayPressureStratified(db: Database): number` — Replaces Phase 1's `decayPressure`:
- Execute the Architecture Section 9.3 SQL directly:
  ```sql
  UPDATE pressure_scores
  SET raw_pressure = raw_pressure * POWER(2, -1.0 / (CASE
    WHEN temperature = 'HOT' THEN 7
    ELSE 3
  END)),
  temperature = CASE
    WHEN raw_pressure * POWER(2, -1.0 / (CASE WHEN temperature = 'HOT' THEN 7 ELSE 3 END)) >= 0.851 THEN 'HOT'
    ELSE 'COLD'
  END
  ```
  Note: The UPDATE sets raw_pressure first, then temperature uses the NEW raw_pressure value. In a single UPDATE, SQLite evaluates SET expressions using the OLD row values, so the temperature CASE must re-compute the decayed value inline (as shown above).
- Cleanup: `DELETE FROM pressure_scores WHERE raw_pressure < 0.01`
- Return total rows affected (updated + deleted)
- Non-throwing (return 0 on error)
