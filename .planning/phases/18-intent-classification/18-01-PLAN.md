# Plan 18-01: Intent Classification at Prompt-Submit

## Goal
Classify user prompt intent and route to different retrieval strategies.

## Tasks

### Task 1: Create intent classifier
**File:** NEW `src/intelligence/intent-classifier.ts`

Export `classifyIntent(prompt: string, recentActions?: string[]): IntentType`

Intent types: `'continuation' | 'investigation' | 'implementation' | 'planning' | 'recall'`

Rule-based classifier (no ML — research shows this works well enough):
1. Check for recall keywords (`last time`, `remember`, `we discussed`, `you said`, `previous session`) → `recall`
2. Check for question patterns (`?`, `why`, `how does`, `what is`, `explain`) → `investigation`
3. Check for imperative + file/code patterns (`add`, `create`, `fix`, `implement`, `update`, file paths, function names) → `implementation`
4. Check for architecture/design keywords (`should we`, `approach`, `design`, `architecture`, `tradeoff`, `strategy`) → `planning`
5. Default → `continuation`

Also export `getRetrievalConfigForIntent(intent: IntentType): RetrievalConfig`:
```typescript
interface RetrievalConfig {
  artifactTypes?: string[];    // filter by type
  recencyWeight: number;       // adjust recency in scoring
  limit: number;               // how many results
  includeConversationTurns: boolean;  // search dialogue history
}
```

Configs per intent:
- continuation: recencyWeight=1.5, limit=5, types=null (default)
- investigation: recencyWeight=0.5, limit=15, includeConversationTurns=true, types=['observation', 'learning', 'decision']
- implementation: recencyWeight=1.0, limit=10, types=['observation', 'hot_file']
- planning: recencyWeight=0.3, limit=10, types=['decision', 'learning']
- recall: recencyWeight=0.0, limit=20, includeConversationTurns=true

### Task 2: Wire into user-prompt-submit hook
**File:** `src/adapters/cc-hooks/user-prompt-submit.ts`

Early in the hook, before retrieval:
1. Call `classifyIntent(prompt)` to get the intent type
2. Call `getRetrievalConfigForIntent(intent)` to get config
3. Pass config to the hybrid search call (may need to add options to existing search call)
4. Store intent classification in session_events for future analysis

### Task 3: Extend hybrid search to accept intent config
**File:** `src/core/hybrid-retrieval.ts`

Modify `HybridSearchOptions` to accept optional intent-driven overrides:
- `artifactTypeFilter?: string[]`
- `recencyWeight?: number`
- `searchLimit?: number`

Apply these in the search functions when provided. Default behavior unchanged when not provided.

### Task 4: Tests
**File:** NEW `src/tests/intelligence/intent-classifier.test.ts`

Tests:
1. "Why is the test failing?" → investigation
2. "Add rate limiting to the API" → implementation
3. "What did we decide about the schema?" → recall
4. "Should we use Qdrant or sqlite-vec?" → planning
5. "yes" → continuation
6. "Fix the bug in auth.ts" → implementation
7. "How does the assembly pipeline work?" → investigation
8. "Last time we discussed the V9 migration" → recall
9. Empty string → continuation
10. getRetrievalConfigForIntent returns correct config for each type
