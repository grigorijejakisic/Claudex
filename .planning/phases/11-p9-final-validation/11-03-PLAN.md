**Cold-start procedure (Phase 11 ship-gate evidence — must be reproducible):**

For each trial:
1. In a NEW Claude Code session in that project's CWD (no prior conversation, no inherited context window — `/clear` first if reusing the harness):
2. Wait for the session-start banner to render (this fires the assembler with handoff-pointer load).
3. Send the pre-committed user prompt from Task 1.
4. Capture the agent's COMPLETE first response — every tool call, every Write/Edit/Bash/Glob/Grep, in sequence — until the agent emits user-visible text or claims it's awaiting input.
5. Record:
   - Tool calls in order: `Bash`, `Glob`, `Grep`, `Read`, `Write`, `Edit`, MCP calls.
   - For each Read tool call: was the file path referenced explicitly in ACTIVE.md? (If yes, it's "handoff-referenced" and ALLOWED. If no, it's exploratory and FAILS the trial.)
   - For each Bash/Glob/Grep: is it exploratory (looking around) or load-bearing for the answer (e.g. running a test the user implicitly asked for)? Glob/Grep/Bash before the first text response = exploratory unless explicitly part of the asked-for action. Apply CONTEXT line 70 strictly.

**How to "run a cold-start session" inside this Phase 11 plan**: Phase 11's executor is itself a Claude session. Two options:

(a) **Sub-process via Claude Code CLI** (preferred — true cold-start): document the command (e.g. `claude --new --cwd <project-cwd> "$PROMPT"`) and have the operator run it manually if Claude Code CLI doesn't support `--new` programmatically. Capture stdout to the trial file.

(b) **Operator-driven trial** (fallback): the executing agent flags this plan as "needs human-in-the-loop"; the operator opens 3 fresh CC sessions, runs the prompts, and pastes the transcripts into the three trial files. The plan stays open until the trial files are populated.
