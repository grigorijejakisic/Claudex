# Plan 16-01: Observation Consolidation (Angel Heartbeat)

## Goal
Reduce 22K observations to ~5K high-density records using Mem0's ADD/UPDATE/DELETE/NOOP model in Angel's heartbeat cycle.

## Tasks

### Task 1: Create consolidator module
**File:** NEW `src/angel/consolidator.ts`

Core function `consolidateObservationBatch(db, project, batchSize = 50)`:
1. Query unconsolidated observations: `WHERE consumed = 0 AND consolidated_into IS NULL AND deleted_at_epoch IS NULL` ordered by timestamp_epoch ASC, LIMIT batchSize
2. For each observation, embed via `embedText()` (dynamic import from embed-pipeline)
3. Search Qdrant for similar observations (cosine > 0.8), limit 5, filtered by project
4. Group into clusters: observations that are mutually similar (transitive closure within the batch)
5. For each cluster of 3+ observations:
   - Build LLM prompt with all cluster observations
   - Call Ollama (llama3.2) via CliProxy pattern: "Summarize these related observations into a single high-density summary. Preserve all key facts. Cite source IDs."
   - If Ollama unavailable: create a simple concatenated summary (no LLM needed for basic merge)
   - INSERT new consolidated observation with importance = MAX(cluster importances) + 1 (cap at 5)
   - UPDATE originals: SET `consumed = 1, consolidated_into = <new_obs_id>`
   - Create artifact for the new consolidated observation
6. For clusters of 2: merge content directly (no LLM needed), keep the newer one, update the older with `consolidated_into`
7. For singletons: skip (nothing to consolidate)
8. Return `{ processed: number, consolidated: number, clusters: number }`

All operations wrapped in try/catch — consolidation failure must never crash the heartbeat.

### Task 2: Wire into Angel heartbeat
**File:** `src/angel/heartbeat.ts`

Add consolidation as a new phase in the heartbeat tick, AFTER pattern extraction:
1. Check if pattern extraction is currently running — if so, skip consolidation (don't compete for resources)
2. Call `consolidateObservationBatch(db, project, 50)`
3. Log result via telemetry
4. Rate limit: run consolidation at most once per 5 minutes (not every tick)

### Task 3: Tests
**File:** NEW `src/tests/angel/consolidator.test.ts`

Tests:
1. 5 similar observations → 1 consolidated summary + originals marked consumed
2. Consolidated observation has importance = max(cluster) + 1, capped at 5
3. Originals have `consolidated_into` pointing to new observation
4. Singleton observations are skipped
5. Pair of observations → merged without LLM
6. Ollama unavailable → simple concatenation fallback
7. Already-consumed observations are skipped
8. Batch size limit respected
9. Error in consolidation doesn't crash (non-throwing)

### Task 4: Verify build + tests
Run `bun run build` and `bun run test`. No new failures.
