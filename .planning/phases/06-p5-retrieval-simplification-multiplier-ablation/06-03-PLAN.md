# Plan 06-03 — Simplify hybrid-retrieval per ablation evidence (RETR-01, RETR-02)

**Wave:** 3 (depends on 06-02 verdicts).
**Goal:** Delete the multipliers verdicted DROP. Land the simplified pipeline. RIF + spread retained.

## Requirements addressed
- **RETR-01** — Collapse hybrid-retrieval scoring to RRF(FTS5 + vec0 + recency) → cross-encoder rerank → top-k (budget-gated).
- **RETR-02** — Delete the multiplier chain elements that ablation proved non-load-bearing.

## must_haves
- For every multiplier verdicted `DROP` in `06-MULTIPLIER-ABLATION.md`, the corresponding code path in `hybrid-retrieval.ts` is removed (not gated, not commented — deleted).
- Both `hybridSearchAsync` and `hybridSearchSync` are aligned: the same set of multipliers applies to both. (Closes the latent sync-only `qMultiplier` bug noted in research §1.)
- The `multiplierFlags` mechanism added in W1 remains for **kept** multipliers (so future ablation is cheap) and is removed from **dropped** multipliers (their flag is dead code after deletion).
- Tests in `src/tests/core/hybrid-retrieval.test.ts` updated to match — any value-asserting test re-baselined; any ordering-asserting test untouched.
- After deletion, `runs/06-02-baseline.json` re-run in W6 still meets the SC#1 ≥80% pass rate (W6 verifies; this plan does not run the gate but **does** run the ablation harness post-deletion to confirm no regression).
