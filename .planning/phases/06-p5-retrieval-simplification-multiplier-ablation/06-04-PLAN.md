# Plan 06-04 — Reranker hard-required: telemetry + visibility (RETR-08)

**Wave:** 3 (parallel with 06-03; both depend only on 06-01).
**Goal:** Make cross-encoder fallback observable. Bi-encoder fallback is a **degraded mode**, not a silent default.

## Requirements addressed
- **RETR-08** — Reranker hard-required for production retrieval; bi-encoder fallback explicitly degraded-mode with telemetry counter `reranker_fallback_fired` incrementing visibly.

## must_haves
- Every time `hybrid-retrieval.ts` falls from cross-encoder (port 7439) to bi-encoder (Ollama 11434), one telemetry row with `event_kind='reranker_fallback'` is written, including a `detail` JSON with the fallback reason (`unreachable`, `non_2xx`, `timeout`, `empty_response`).
- A new helper `incrementRerankerFallbackCounter(db, sessionId, reason)` lives in `src/core/telemetry-counters.ts`, non-throwing, used as the only callsite.
- Session-start assembler emits one observational line if any `reranker_fallback` events occurred in the last 24h: e.g. *"Note: cross-encoder reranker fell back to bi-encoder N times in the last 24h. The cross-encoder is the precision layer — restart `services/reranker.py` if this count is non-zero across multiple sessions."*
- The line is **observational** (descriptive), not imperative (no `WARNING:`, no `Apply this:`) — consistent with the Phase 7 framing direction.
- `CLAUDE.md` (project) updated under "Critical Safety Rules" to mark BGE-v2-m3 as **load-bearing infrastructure**, not an enhancement.
- `README.md` updated where the reranker is currently documented to make the same point.
- Tests: cross-encoder unreachable → fallback fires + telemetry row written; cross-encoder healthy → no telemetry row, no warning surfaced.

<task id="06-04-01">
<title>Telemetry counter helper module</title>
<verification>
`src/core/telemetry-counters.ts` exists with `incrementRerankerFallbackCounter(db, sessionId, reason)` that inserts one row into `telemetry` with `event_kind='reranker_fallback'`. Non-throwing. Unit tests in `src/tests/core/telemetry-counters.test.ts` cover the success path and the DB-error swallow path.
</verification>
<steps>
1. New module `src/core/telemetry-counters.ts`:
   ```ts
   import type { Database } from 'better-sqlite3';
   import { cachedPrepare } from './stmt-cache.js';

   export type RerankerFallbackReason =
     | 'unreachable'
     | 'non_2xx'
     | 'timeout'
     | 'empty_response';

   /**
    * Record a reranker fallback event. Non-throwing.
    * Writes one row to `telemetry` with event_kind='reranker_fallback'.
    */
   export function incrementRerankerFallbackCounter(
     db: Database,
     sessionId: string,
     reason: RerankerFallbackReason,
   ): void {
     try {
       cachedPrepare(db,
         `INSERT INTO telemetry (session_id, event_kind, detail, adapter)
          VALUES (?, 'reranker_fallback', ?, 'hybrid-retrieval')`
       ).run(sessionId, JSON.stringify({ reason }));
     } catch { /* non-throwing */ }
   }

   /** Read fallback count over the last `windowSeconds`. Non-throwing. */
   export function readRerankerFallbackCount(
     db: Database,
     windowSeconds = 86400,
   ): number {
     try {
       const row = cachedPrepare(db,
         `SELECT COUNT(*) AS n FROM telemetry
          WHERE event_kind = 'reranker_fallback'
            AND timestamp_epoch >= unixepoch() - ?`
       ).get(windowSeconds) as { n: number };
       return row?.n ?? 0;
     } catch {
       return 0;
     }
   }
   ```
2. Unit tests in `src/tests/core/telemetry-counters.test.ts`:
   - Increment writes one row with the expected event_kind and detail.
   - Reader returns the count over the window.
   - Reader on a closed DB returns 0 (no throw).
</steps>
</task>
