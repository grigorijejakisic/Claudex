<task id="06-01-03">
<title>Add `multiplierFlags` to `HybridSearchOptions` for ablation toggle</title>
<verification>
With `multiplierFlags` undefined, `hybridSearchAsync` and `hybridSearchSync` produce identical scores to the current code (byte-equal `hybrid_score` for the same input). With every flag set to `false`, the scoring reduces to RRF-only (no multipliers, no `(1 + threeFactor)` scaling) — verified by a test that asserts `hybrid_score === rrfScore` for the all-disabled path.
</verification>
<steps>
1. In `src/core/hybrid-retrieval.ts` extend `HybridSearchOptions`:
   ```ts
   export type MultiplierName = 'recency' | 'importance' | 'relevance'
     | 'retrieval' | 'novelty' | 'activation' | 'qvalue';
   /** Per-multiplier ablation flags. Undefined = all enabled (production behavior). */
   multiplierFlags?: Partial<Record<MultiplierName, boolean>>;
   ```
2. Read flags at the top of both `hybridSearchAsync` and `hybridSearchSync`:
   ```ts
   const flags = options.multiplierFlags ?? {};
   const enabled = (n: MultiplierName) => flags[n] !== false;  // default true
   ```
3. Gate each multiplier:
   - `recency` weight collapses to 0 when disabled (i.e. `enabled('recency') ? recency : 0` inside `computeThreeFactorScore` — extend its signature).
   - same for `importance`, `relevance`.
   - `retrievalMultiplier`, `noveltyMultiplier`, `activationFactor`, `qMultiplier` collapse to `1.0` when their flag is false.
4. **Crucial:** when ALL flags are false, the formula becomes `hybridScore = rrfScore × (1 + 0)` = `rrfScore`. Add an assertion test for this in the new ablation harness file.
5. Re-export `MultiplierName` and update the existing `HybridSearchOptions` doc comment.
6. Existing `hybrid-retrieval.test.ts` MUST pass with no edits — undefined flags = production behavior.
</steps>
</task>
