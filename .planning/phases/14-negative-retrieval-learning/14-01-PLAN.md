# Plan 14-01: Negative Retrieval Learning

## Goal
Track surfaced-but-unreferenced artifacts. Demote consistently-ignored items. Implement retrieval-induced suppression.

## Tasks

### Task 1: Enhance retrieval feedback scoring
**File:** `src/intelligence/retrieval-feedback.ts`

Modify `getRetrievalScoreMultiplier()` to include negative learning:

1. Query `retrieval_events` for the artifact: count rows where `was_referenced = 0` (unreferenced)
2. If unreferenced_count >= 3: compute suppression = `max(-0.5, -0.1 * (unreferenced_count - 2))`
3. Apply as multiplier: `baseMultiplier * (1.0 + suppression)` — so 3 unreferenced = 0.9×, 5 unreferenced = 0.7×, 7+ unreferenced = 0.5× (floor)
4. Also consider positive signals: if `was_referenced = 1` count is > 0, scale suppression by ratio: `suppression *= unreferenced / (unreferenced + referenced)`
5. Add a recovery mechanism: if an artifact starts being referenced again, the suppression lifts naturally as the ratio changes

### Task 2: Record reference signals at session end
**File:** `src/adapters/cc-hooks/stop.ts`

In the stop hook, after existing retrieval feedback processing:

1. Get all `retrieval_events` for current session where `was_referenced IS NULL`
2. For each, check if the artifact's summary or content appears (even partially) in any `conversation_turns.assistant_text` for this session
3. Update `was_referenced = 1` if found, `was_referenced = 0` if not
4. Simple heuristic for "referenced": check if any key terms from the artifact summary appear in assistant responses. Use tokenization + intersection (not embedding — keep it fast).

### Task 3: Retrieval-induced suppression (RIF)
**File:** `src/core/hybrid-retrieval.ts`

After `hybridSearchAsync()` or `hybridSearchSync()` produces the final ranked list:

1. The top-K results that get returned are "selected"
2. Candidates that scored above a minimum threshold but below the selection cutoff are "suppressed candidates"
3. For each suppressed candidate: `UPDATE artifacts SET activation_score = MAX(0.1, activation_score - 0.03) WHERE id = ?`
4. This is a lightweight decay — small enough to not matter for a single query, but accumulates over many queries for consistently-not-selected artifacts
5. Only apply RIF to artifacts that were actual candidates (scored above 0.1 in RRF), not to the entire corpus

### Task 4: Tests
**File:** `src/tests/intelligence/retrieval-feedback.test.ts` (modify or new)

Tests:
1. Artifact surfaced 5 times, never referenced → multiplier drops to ~0.7
2. Artifact surfaced 3 times, referenced once → mild suppression accounting for ratio
3. Artifact referenced every time → no suppression (multiplier stays 1.0)
4. Floor at 0.5× multiplier (never fully suppressed)
5. Recovery: previously suppressed artifact that starts being referenced → multiplier improves
6. RIF: non-selected candidate gets small activation_score decrement

Run `bun run build` and `bun run test`.
