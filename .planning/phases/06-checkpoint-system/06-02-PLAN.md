Checkpoint loader with two-layer recovery and inject renderer for assembly pipeline.

**src/checkpoint/loader.ts** — Two-layer recovery chain. Non-throwing public API.

Import `js-yaml` for YAML parsing. Import `fs` and `path`. Import types from `./types.ts`.

`recoverFromDb(db: Database): void` — DB recovery at sessionInit:
- Query all `committed` rows from checkpoint_meta (not yet mirrored)
- For each: parse data column as CheckpointV3, atomicWriteFile to mirror_path (or generate path from checkpoint_id if mirror_path is null)
- Update latest.yaml with the most recent one
- UPDATE status to 'mirrored' for each successfully re-mirrored row
- DELETE all `pending` rows (incomplete writes from crash)
- Non-throwing (silently skip errors per row)

`loadFromFile(projectDir: string): CheckpointV3 | null` — File fallback chain:
- Step 1: Read `{checkpointsDir}/latest.yaml`
  - Parse content: look for `ref: {filename}` pattern
  - Load the referenced file from checkpointsDir
  - If successful: return parsed CheckpointV3
- Step 2: If latest.yaml missing/corrupt: directory scan
  - `fs.readdirSync(checkpointsDir)` -> filter `*.yaml` (exclude latest.yaml)
  - Sort by mtime desc (newest first)
  - Try loading first valid file, return parsed CheckpointV3
- Step 3: If no valid file from scan: return null
- Non-throwing (return null on any error)

Helper: `followHopChain(checkpointsDir: string, startBasename: string, maxHops: number): CheckpointV3[]` — 3-hop chain:
- Start with startBasename
- For each checkpoint: read previous_checkpoint field (basename only)
- Follow the chain, loading each referenced checkpoint
- Track seen basenames in `Set<string>` for cycle detection
- Stop at null previous_checkpoint, max hops reached, or cycle detected
- Return array of loaded checkpoints (newest first)
- Non-throwing (return collected so far on error)

`loadCheckpoint(db: Database | null, projectDir: string, preset?: SelectiveLoadPreset): CheckpointV3 | null` — Main entry point:
- Layer 1 (DB recovery): if db is not null:
  - Query checkpoint_meta: `SELECT * FROM checkpoint_meta WHERE status IN ('committed','mirrored') ORDER BY created_at_epoch DESC LIMIT 1`
  - If found committed: re-mirror (atomicWriteFile from data column), update to mirrored
  - If found mirrored: read from mirror_path (fast path)
  - Parse data column as CheckpointV3
- Layer 2 (File fallback): if DB unavailable or no result from Layer 1:
  - Call `loadFromFile(projectDir)`
- Apply selective loading preset (strip fields not in preset):
  - `ALWAYS`: keep meta, working, thread.topic only
  - `RESUME`: keep meta, working, decisions, files, thread (full), open_items, learnings
  - `GSD`: keep everything from RESUME + gsd
  - Default (no preset / undefined): return full checkpoint
- Return loaded checkpoint or null
- Non-throwing

Helper: `applyPreset(checkpoint: CheckpointV3, preset: SelectiveLoadPreset): CheckpointV3` — Strip fields:
- Create a shallow copy
- Based on preset, null out/empty excluded fields
- ALWAYS: set decisions=[], files={hot:[],read:[]}, thread.summary=null, thread.key_exchanges=[], open_items=[], learnings=[], gsd=null
- RESUME: set gsd=null
- GSD: return full checkpoint

**src/checkpoint/inject.ts** — Converts CheckpointV3 into markdown for assembly pipeline. Non-throwing.

`renderCheckpointMarkdown(checkpoint: CheckpointV3, preset?: SelectiveLoadPreset): string` — Produce markdown:
- Build markdown sections in priority order per Architecture Section 7:
  1. **Working context** (always): task, status, next_action, branch (if present)
  2. **Thread** (RESUME+): topic (ALWAYS), summary and key_exchanges (RESUME+)
  3. **Decisions** (RESUME+): numbered list of decisions with source labels
  4. **Files** (RESUME+): HOT files with last_action, read files as list
  5. **Open items** (RESUME+): bulleted list
  6. **Learnings** (RESUME+): bulleted list
  7. **GSD** (GSD only): raw GSD data formatted as section
- Each section wrapped in markdown header (`### Section Name`)
- Omit sections that have no data (empty arrays, null fields)
- Respect preset: only render sections included in the preset
  - ALWAYS: working + thread.topic only
  - RESUME: all except GSD
  - GSD: all sections
  - No preset: all sections
- Return assembled markdown string
- Non-throwing (return empty string on error)

Section formatting details:
- Working: `### Current Work\n- **Task:** {task}\n- **Status:** {status}\n- **Next:** {next_action}\n- **Branch:** {branch}`
- Thread topic: `### Thread\n**Topic:** {topic}`
- Thread full: append `\n**Summary:** {summary}\n\n**Key Exchanges:**\n` + formatted exchanges
- Key exchanges: `- **{role}:** {gist}` per entry
- Decisions: `### Decisions\n1. [{source}] {content}` per entry
- Files: `### Active Files\n**Hot:**\n- {path} — {last_action}\n\n**Read:**\n- {path}`
- Open items: `### Open Items\n- {item}` per entry
- Learnings: `### Learnings\n- {learning}` per entry
- GSD: `### GSD State\n{formatted gsd}` (JSON.stringify with 2-space indent if object, else string)
