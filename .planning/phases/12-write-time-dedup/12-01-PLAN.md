# Plan 12-01: Write-Time Observation Deduplication

## Goal
Modify `insertObservation()` to check for semantic duplicates before inserting. Prevent observation bloat at source.

## Tasks

### Task 1: Add dedup logic to insertObservation()
**File:** `src/core/observations.ts`

Modify `insertObservation()` (line 56) to:
1. Embed the new observation's `title + ' ' + content` via `embedQuery()` from `../embeddings/embed-pipeline.ts`
2. Search Qdrant `claudex_artifacts` collection for cosine similarity >0.85, filtered by `project` and `artifact_type = 'observation'`, limit 3
3. Decision logic:
   - If no match → proceed with normal INSERT
   - If match found with same `session_id` → SKIP, return existing observation's ID
   - If match found with different `session_id` and similar content → UPDATE existing: increment `access_count`, update `last_accessed_at_epoch`, merge `files_modified` arrays. Return existing ID.
   - If match found with different `session_id` but contradicting content (cosine 0.6-0.85 range — related but different) → INSERT new observation normally
4. Wrap the entire dedup path in try/catch — if Qdrant unavailable or any error, fall through to normal INSERT (never block writes)
5. Import `embedQuery` dynamically (async import) to avoid circular deps and keep the sync path fast when Qdrant is down

**Important:** The Qdrant search is async but `insertObservation` is currently sync. The function signature needs to stay sync for backward compatibility. Strategy: export a new `insertObservationWithDedup()` async function that hooks can call, keeping the original sync `insertObservation()` as fallback.

### Task 2: Wire hooks to use dedup-aware insert
**Files:** Check which hooks call `insertObservation()` and update the primary callers to use `insertObservationWithDedup()`.

Use `grep` to find all callers. Likely in extraction dispatchers and direct hook code. The async version should be used in hooks (which are already async). The sync version stays as internal/test fallback.
