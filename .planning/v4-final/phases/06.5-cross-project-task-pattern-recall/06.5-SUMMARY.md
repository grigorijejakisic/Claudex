## Outcome

Phase 6.5 makes the kid-stove cross-project generalization mechanically work. Lessons stored in one project — say, the Mozzart 429 shadowban finding from `lacuna-betting` — surface in another project's session — say, `big-mozzy-v2` working on a new bookmaker integration — without the new session's prompt containing any of the original lesson's lexical-surface tokens (`rate`, `limit`, `429`, `shadowban`, `cloudflare`, `throttle`, `proxy`, `scraping`). The match fires on perceptual handles + shape vocabulary, not text overlap. This is the substrate-mechanism handoff from Phase 4.1 working as designed.

Two surfaces ship the recall:
1. **Experience Tier** (Architecture B parallel scorer to Critical Reminders) — surfaces top-K cross-project lessons at session-start in advisory voice, within a 200-token budget.
2. **claudex_search query expansion** — when the user types a task-shaped query (verb + domain noun), the MCP `claudex_search` tool expands beyond project-local results to include cross-project artifacts via the same HYBRID equivalence function.

Both consume Plan 01's V21 `artifact_task_pattern` sidecar table and Plan 02's HYBRID equivalence function. Plan 03 ships the user-visible MCP surface, the per-project CLAUDE.md opt-out, and the SC#1 Vesna gate.

## Architecture B enforcement

`tier-utils.ts` extraction enforces "shared infrastructure, separate scorers":
- Both Critical Reminders Tier (RULES) and Experience Tier (EPISODES) consume the same `shouldInjectArtifact`, `advanceTTL`, `resetTTL`, `renderObservationalVariant` primitives.
- Different inputs (rules vs lessons) and triggers (decay/jitter vs handle-overlap match).
- Different budgets (CR=300 tokens, ET=200 tokens) so behavioral rules win on collision-shaped scoring.
- Different top-K (CR=5, ET=3).

50/50 existing critical-reminders tests pass post-refactor — extraction is no-behavior-change.

## Cache-stability invariance

Experience Tier scoring is fully deterministic:
- No `Math.random` — handles via deterministic dispersion (`id * 13 + turnNumber`).
- Tiebreak `(score DESC, id ASC)` deterministic.
- No clock-derived strings in section output.
- `applyEffects` deferred to commit time; no side effects at scoring.

`phase-6-5-experience-tier-cache-stability.test.ts` (4 tests) asserts byte-identical output across runs even under volatile-state mutation (clock advance, unrelated session_events writes).

## Cross-cutting principle update

The "kid-stove principle" is now mechanically testable end-to-end:

> Bound multi-modal episodes recall via perceptual handles, not text similarity. Encoding density matches salience.

This is the same principle Phase 4.1's substrate-validation probes asserted on the substrate; Phase 6.5 hands it forward as a behavioral gate over the Experience Tier scorer + claudex_search expansion paths. The Vesna SC#1 gate enforces lexical-leakage discipline: the prompt MUST NOT contain any of the lesson's surface tokens. Pass = genuinely perceptual.

Add to v4 cross-cutting principles list:

**Principle 6 — Lexical-leakage pre-flight on perceptual gates.** Any test that claims to verify cross-project / perceptual recall MUST start with `expect(prompt).not.toMatch(forbiddenWords)`. If the assertion fails, rewrite the prompt with synonyms; never relax the assertion. This is the substrate-mechanism contract Phase 4.1 (substrate) and Phase 6.5 (mechanism) jointly enforce.
