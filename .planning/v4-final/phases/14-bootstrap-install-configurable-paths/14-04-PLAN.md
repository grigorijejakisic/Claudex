<objective>
Ship the two cross-platform wrappers (`install.sh` for Mac/Linux, `install.bat` for Windows) at the repo root so a stranger cloning the repo can run a single command — `./install.sh` or `install.bat` — and end up with a working install. Both wrappers delegate to `bun run setup` (which 14-03 made complete) after a Bun pre-flight check; they hold no business logic.

INST-01 acceptance is "one-command bootstrap exit 0, idempotent" — `bun run setup` already covers this from 14-03, but the wrappers cover the case where the user doesn't yet know about Bun's `bun run` syntax. The wrappers exist for first-touch UX (CONTEXT.md `<decisions>` line: "Make executable via `git update-index --chmod=+x`").

CONTEXT.md `<plan_authorization>`: "Skip the install.sh/install.bat wrappers if `bun run setup` alone proves sufficient AND the user can be expected to know what `bun` is (but default: ship the wrappers, they're cheap)." We default to shipping them.
</objective>

<execution_context>
**install.sh contents (CONTEXT.md `<decisions>` provides exact shape):**
```sh
#!/usr/bin/env bash
set -e
command -v bun >/dev/null || { echo "Bun not found. Install: https://bun.sh"; exit 1; }
bun install --frozen-lockfile
bun run build
bun run setup
```

**install.bat contents (CONTEXT.md `<decisions>` provides exact shape):**
```bat
@echo off
where bun >nul 2>&1 || (echo Bun not found. Install: https://bun.sh && exit /b 1)
bun install --frozen-lockfile
if errorlevel 1 exit /b 1
bun run build
if errorlevel 1 exit /b 1
bun run setup
if errorlevel 1 exit /b 1
```

The Windows `&&` chain is fragile in batch files — explicit `if errorlevel 1 exit /b 1` after each step is more reliable than relying on `&&` semantics. Use the explicit form.

**Executable bit on install.sh:**
On Windows, `git update-index --chmod=+x install.sh` is the way to set the POSIX executable bit in the index without needing `chmod` (which doesn't work on NTFS). After committing, `git ls-files --stage install.sh` should show mode `100755`. This means anyone cloning on Mac/Linux will get the file with executable bit set automatically.

**Line endings:**
Add or update `.gitattributes` to ensure `install.sh` always checks out with LF endings, even on Windows clones. This prevents `bash: ./install.sh: /usr/bin/env: bad interpreter: No such file or directory` errors caused by CRLF. Suggested line:
```
install.sh text eol=lf
```
And similarly:
```
install.bat text eol=crlf
```

**Out of scope:**
- Bundling Bun, Ollama, or Python — out of scope for v4.1
- Doctor diagnostics — Phase 15
- README walk-through — Phase 16
- Any logic that duplicates `bun run setup` — wrappers must be thin

</execution_context>
