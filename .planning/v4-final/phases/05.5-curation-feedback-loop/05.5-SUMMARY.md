## Scope Shipped

The four-deliverable contract from `.planning/phases/05.5-curation-feedback-loop/05.5-CONTEXT.md` (§Phase Boundary):

1. **`pointer_recall_log` table.** Plan 01. Captures retrieval events keyed by `(pointer_id, session_id, retrieved_at_epoch_ms, helpful_yn, query)`. Written automatically by `claudex_recall` when the resolved artifact_ref points to a lesson file (Plan 02 wires this).

2. **`helpful_yn` capture at `/endsession`.** Plan 03. Two thin CLIs (`list-session-pointers` + `mark-pointers-helpful`) plus a new skill Step 1d in `~/.claude/skills/endsession/skill.md`. Skip-by-default: silence = blank = no marks; `null` is a valid signal.

3. **Auto-archive.** Plan 04. `sweepArchivePointers` runs on Angel heartbeat (24h cadence). Pointers with 0 retrievals in 90 days AND no `helpful_yn=1` row → tier='background' on the lesson file frontmatter. The lesson stays in DB; only the foreground placement demotes.

4. **Auto-promote.** Plan 04. `sweepPromotePointers` runs on Angel heartbeat (7d cadence). Pointers with ≥3 retrievals AND any `helpful_yn=1` → `last_fired_at_epoch` bumped to now. 24h cooldown prevents thrash. Re-promotion implicitly un-archives a previously-archived pointer ("natural rehabilitation path" per CONTEXT.md).

## Deferred (out-of-scope per CONTEXT.md or research)

- **User-note auto-archive.** Byte-preservation contract on `## User Notes` precludes any mutation by Angel. Auto-archive is lesson-only in 5.5; user-note lifecycle is a future-phase question (likely 6.5 or 11).
- **Assembler-side instrumentation.** Only `claudex_recall` is wired in 5.5. Deeper hooks (assembler reads, MEMORY.md inclusion, hybrid-retrieval surfacing) are deferred per RESEARCH §3 — would require careful audit of recall-path latency.
- **Pointer-id stability across lesson rename.** Lessons are filesystem-keyed; if a lesson's filename changes, `lesson_pointer` produces a fresh id. Pointer history doesn't follow the rename. Out of scope for 5.5.
- **Quantitative helpfulness scoring.** Binary `helpful_yn` is locked. 5-point Likert / numeric weight is over-engineering for a phase whose value comes from low-friction signal.

## Schema Change

`PRAGMA user_version` advanced 18 → 19. Two new tables, fully additive:
- `lesson_pointer (id, project, filename, source ∈ {lesson, user_note}, first_seen_epoch_ms)` with `UNIQUE(project, filename, source)` and `idx_lesson_pointer_project`.
- `pointer_recall_log (id, pointer_id FK, session_id, retrieved_at_epoch_ms, helpful_yn NULL, query NULL)` with three indexes: `(pointer_id, retrieved_at_epoch_ms DESC)`, `(session_id)`, partial `(pointer_id, helpful_yn) WHERE helpful_yn = 1`.

`migrateV18toV19` is idempotent (IF NOT EXISTS throughout). Fresh DBs reach V19 via `initializeSchema`'s SCHEMA_V3 + POINTER_RECALL_SCHEMA path; legacy DBs reach V19 via `runMigrations`.

## Behavioral Change Visible to User

- `/endsession` now has Step 1d (skippable) for pointer feedback.
- Pointers with 90d+ silence drop out of `## Lessons` foreground over time (frontmatter `tier: background`).
- Pointers earning ≥3 recalls + ≥1 helpful tap rise to top of `## Lessons` (frontmatter `last_fired_at_epoch` bumped).
- A previously-archived pointer that re-earns ≥3 recalls + helpful flips back to `tier: foreground`.
- Heartbeat tick now reports `pointers_archived` / `pointers_promoted` / `curation_errors` in `TickResult`.
