## Deviations from Plan

**[Rule 1 - Bug] esbuild outbase regression after clean rebuild** — Found during: Task 3 verification (`ls dist/cli/` showed no new artifacts). Issue: when `entryPoints` includes both `src/...` and `scripts/...` paths, esbuild's implicit outbase becomes the project root, putting all artifacts under `dist/src/...` and `dist/scripts/...`. The repo's `setup.ts`, smoke-test loop, and skill commands all assume the legacy `dist/{adapters,cli,...}/...` layout. Verified the bug pre-existed my changes (stashed build.ts, clean rebuild reproduced the wrong layout). Fix: split the single esbuild call into per-root invocations with explicit `outbase: 'src'` and `outbase: 'scripts'`, run all three in parallel via `Promise.all`. Files: `build.ts`. Verification: clean rebuild now produces `dist/cli/list-session-pointers.cjs` + `dist/cli/mark-pointers-helpful.cjs` + all hooks at `dist/adapters/cc-hooks/*.cjs`; smoke tests pass. Commit: `72a2be5`.

**[Rule 2 - Missing Critical] mark CLI db-close on error path** — Found during: Task 2 implementation review. Issue: PLAN.md template does `db.close()` only inside the success path. If `listSessionPointers` throws partway through, the db handle leaks. Fix: scope db to outer let, close in catch with try/ignore. Files: `src/cli/mark-pointers-helpful.ts`. Verification: error-path tests still exit cleanly. Commit: `72a2be5`.

**Total deviations:** 2 auto-fixed (1 Rule 1 — Bug, 1 Rule 2 — Missing Critical).
**Impact:** Build-system regression fix is widely useful (preserves the contract every other repo path depends on); the CLI db-close fix prevents a slow handle leak under error conditions.
