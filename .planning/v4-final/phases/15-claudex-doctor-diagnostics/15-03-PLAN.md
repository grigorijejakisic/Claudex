# Plan 15-03: Ollama + Reranker checks (DIAG-03, DIAG-04)

## Objective

Implement the two diagnostic checks that probe local services over HTTP: Ollama (DIAG-03) and BGE reranker (DIAG-04). Both run independently of plans 15-02 and 15-04 and depend only on the primitives in 15-01.

## Why these are grouped

Both checks are "probe a localhost HTTP endpoint, interpret the response, return a CheckResult." They share the timeout pattern, fetch-error coercion, and warn-vs-fail decisions. Grouping them in a single plan lets the implementer extract a small shared `probeWithTimeout` helper if duplication appears, while still landing two distinct check modules.

A core decision distinguishes them: **Ollama failures are `fail`** (Claudex can't function without embeddings) while **Reranker failures are `warn`** (bi-encoder fallback covers degraded mode). This is locked in CONTEXT.md and reflected in `must_haves`.

## Tasks

<task id="01-check-ollama">
**Create `src/diagnostics/check-ollama.ts`** — DIAG-03.

Re-use Phase 14's `detectOllama` helper from `src/cli/bootstrap-steps/ollama-detect.ts` for binary detection (it knows the platform-specific PATH search) — but DO NOT call its interactive prompt path. Read its exports and use the pure detection function only.

Behavior (sequential — each step gates the next):

1. **Binary detection** — call `detectOllama({ interactive: false })` (or whatever the non-prompting variant is; check the export). If binary not found, return:
   ```
   { name: 'Ollama', status: 'fail', detail: 'Ollama not found in PATH',
     remediation: ollamaInstallMessage(process.platform) }
   ```
   `ollamaInstallMessage` is already exported from `ollama-detect.ts`. Use it; do not duplicate platform branching.

2. **Daemon reachability** — `fetch('http://localhost:11434/api/tags', { signal: AbortSignal.timeout(2000) })`. On thrown error or non-2xx:
   ```
   { name: 'Ollama', status: 'fail', detail: 'Ollama daemon not running on :11434',
     remediation: "Start Ollama: 'ollama serve' (or restart the desktop app)." }
   ```

3. **Model presence** — parse the JSON. The /api/tags response is `{ models: [{ name: 'snowflake-arctic-embed2:latest', ... }, ...] }`. Check whether any model's `name` field starts with `'snowflake-arctic-embed2'` (handles the `:latest` tag suffix).
   - If found: `{ name: 'Ollama', status: 'pass', detail: 'daemon up, snowflake-arctic-embed2 pulled' }`
   - If not found:
     ```
     { name: 'Ollama', status: 'fail', detail: 'snowflake-arctic-embed2 model not pulled',
       remediation: "Pull the embedding model: 'ollama pull snowflake-arctic-embed2'" }
     ```

Implementation notes:
- Use the global `fetch` (Node 22+ / Bun built-in). No `node-fetch` import.
- `AbortSignal.timeout(2000)` is supported in Node 22+ and Bun. If the helper from `src/shared/fetch-utils.ts` already exists with timeout semantics, prefer that.
- Wrap the fetch in try/catch — `AbortError`, `ECONNREFUSED`, and `getaddrinfo` errors all map to "daemon not running."
- Doctor MUST NOT pull the model itself. Diagnose, don't repair.
- Single CheckResult — even though DIAG-03 conceptually has 3 sub-checks (binary, daemon, model), they collapse into one CheckResult by short-circuit. The first failing step decides the result. The CONTEXT.md sample output renders this as one row with a multi-piece detail string ("running" + "model pulled") but a single row keeps the table simpler. The CLI (PLAN-15-05) renders one row per CheckResult.
</task>

<task id="02-check-reranker">
**Create `src/diagnostics/check-reranker.ts`** — DIAG-04.

```ts
import type { CheckFn } from './types.js';

const RERANKER_URL = 'http://localhost:7439/health';
const TIMEOUT_MS = 2000;

export const checkReranker: CheckFn = async () => {
  let response: Response;
  try {
    response = await fetch(RERANKER_URL, { signal: AbortSignal.timeout(TIMEOUT_MS) });
  } catch (err) {
    const errMsg = (err as Error).name === 'AbortError' ? 'timeout' : 'unreachable';
    return {
      name: 'Reranker',
      status: 'warn',
      detail: `port 7439 ${errMsg}`,
      remediation: "Reranker on port 7439 unavailable; bi-encoder fallback active. Run 'bun run setup' or restart Angel to bring it back.",
    };
  }

  if (!response.ok) {
    return {
      name: 'Reranker',
      status: 'warn',
      detail: `port 7439 HTTP ${response.status}`,
      remediation: "Reranker is reachable but unhealthy. Restart Angel to recycle the supervised reranker process.",
    };
  }

  return {
    name: 'Reranker',
    status: 'pass',
    detail: 'port 7439 healthy',
  };
};
```

Notes:
- Status is `warn` for both unreachable AND non-2xx, **never `fail`**. CONTEXT.md is explicit: bi-encoder fallback covers reranker downtime; doctor should surface degraded-mode but not block exit 0. (See CLAUDE.md "Reranker is load-bearing for production retrieval (RETR-08)" — but this is about *production* retrieval; doctor is install health, not runtime SLOs.)
- Probes `/health` specifically, not `/`. The reranker exposes a dedicated health endpoint.
- 2-second timeout matches Ollama. Total parallel doctor wall-clock stays sub-3s even if both probes time out (they run in parallel).
</task>

<task id="03-tests-ollama">
**Create `src/tests/diagnostics/check-ollama.test.ts`** — ≥3 tests.

Mock pattern: `vi.stubGlobal('fetch', vi.fn())` per test, plus `vi.mock` on `../../cli/bootstrap-steps/ollama-detect.js` to control the binary-detection result.

Required cases:

1. **pass**: binary detected; `fetch` returns 200 with `{ models: [{ name: 'snowflake-arctic-embed2:latest' }] }` → status `'pass'`, detail mentions both `'daemon up'` and `'snowflake-arctic-embed2'`
2. **fail (no binary)**: `detectOllama` returns `{ found: false }` → status `'fail'`, remediation contains an install URL (per `ollamaInstallMessage`)
3. **fail (daemon down)**: binary detected; `fetch` rejects with a connection error → status `'fail'`, remediation contains `'ollama serve'`
4. **fail (model missing)**: binary detected; `fetch` returns 200 with `{ models: [] }` → status `'fail'`, remediation contains `'ollama pull snowflake-arctic-embed2'`
5. (optional) **fail (daemon timeout)**: `fetch` rejects with AbortError → status `'fail'`, detail mentions `'not running'` or similar

Total: 4-5 tests for DIAG-03.
</task>
