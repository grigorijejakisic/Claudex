# Plan 15-02: Bun + DB checks (DIAG-02, DIAG-05)

## Objective

Implement the two diagnostic checks that have no external network dependency: Bun runtime version (DIAG-02) and SQLite DB schema version (DIAG-05). These are the simplest checks and good vehicles for stabilizing the per-check pattern that the network-dependent plans (15-03, 15-04) will follow.

## Why this plan exists separately

DIAG-02 reads `process.versions.bun` — pure runtime introspection.
DIAG-05 reads a single SQLite pragma against `~/.claudex/db/claudex.db`.

Both have zero external services to mock and zero shared state with the Ollama / reranker / hooks / Angel checks. Grouping them together lets one implementer ship cleanly without crossing wires with the parallel Wave-2 plans.

export function runMigrations(db: DatabaseLike): void {

  // ... and the trailing setter:

This is a pure refactor — no behavior change. Verify by running the existing migration tests (they should be untouched).

<task id="02-check-bun">
**Create `src/diagnostics/check-bun.ts`** — DIAG-02.

```ts
import type { CheckFn } from './types.js';

export const MIN_BUN_MAJOR = 1;
export const MIN_BUN_MINOR = 3;

export const checkBun: CheckFn = async () => {
  const bunVersion = process.versions.bun;

  if (!bunVersion) {
    return {
      name: 'Bun version',
      status: 'fail',
      detail: 'Bun not found in PATH',
      remediation: 'Install Bun >=1.3: https://bun.sh',
    };
  }

  // bunVersion is like '1.3.5'. Compare numerically.
  const [majorStr, minorStr] = bunVersion.split('.');
  const major = parseInt(majorStr, 10);
  const minor = parseInt(minorStr, 10);

  if (
    isNaN(major) || isNaN(minor) ||
    major < MIN_BUN_MAJOR ||
    (major === MIN_BUN_MAJOR && minor < MIN_BUN_MINOR)
  ) {
    return {
      name: 'Bun version',
      status: 'fail',
      detail: `Bun ${bunVersion} (need >=${MIN_BUN_MAJOR}.${MIN_BUN_MINOR})`,
      remediation: `Install Bun >=${MIN_BUN_MAJOR}.${MIN_BUN_MINOR}: https://bun.sh`,
    };
  }

  return {
    name: 'Bun version',
    status: 'pass',
    detail: `Bun ${bunVersion}`,
  };
};
```

Implementation notes:
- We use `process.versions.bun` (set automatically when running under Bun) instead of shelling out to `bun --version`. Faster, more reliable, no PATH dependency.
- Re-using `src/cli/bootstrap-steps/bun-version.ts` would be inappropriate here — that helper is interactive (prompts the user) and shells out. A pure pass/fail check needs neither.
- The `MIN_BUN_MINOR = 3` matches CONTEXT.md DIAG-02 (>=1.3). Phase 14's bootstrap step uses `MIN_BUN_VERSION = '1.3.0'` as a string; we use numeric majors/minors here for testability.
- Doctor itself runs under Node (the script entry is `node dist/cli/doctor.cjs` per package.json). That means `process.versions.bun` will be `undefined` unless we change the entry. Doctor must be invoked under Bun for this check to be meaningful. **Resolution:** use `bun run doctor` as the documented entry (per CONTEXT.md) — `bun run` invokes the script under Bun runtime, so `process.versions.bun` IS populated. This is consistent with `bun run setup` and `bun run test`. The package.json script entry can remain `node dist/cli/doctor.cjs`, but doctor's check-bun module must call `process.versions.bun` only — anything else (e.g., spawning `bun --version` as a subprocess) defeats the purpose.
- Edge case: when Doctor is run as `node dist/cli/doctor.cjs` (raw node, not via bun-run), `process.versions.bun` is undefined → DIAG-02 reports fail with detail "Bun not found in PATH". This is technically a false negative (Bun may be installed but the operator skipped `bun run`), but it's also actionable: the README specifies `bun run doctor`, and if someone calls raw node they're already off-script. Live with the false negative; remediation message is correct ("Install Bun >=1.3").

If after considering the above, the implementer prefers spawning `bun --version` as a subprocess (so doctor under raw node still detects Bun), do that instead — using `child_process.spawnSync('bun', ['--version'])` with a 1s timeout. Either approach is acceptable as long as the test cases cover the chosen behavior.
</task>

<task id="03-check-db">
**Create `src/diagnostics/check-db.ts`** — DIAG-05.

```ts
import * as fs from 'fs';
import Database from 'better-sqlite3';
import type { CheckFn } from './types.js';
import { getDbPath } from '../shared/paths.js';
import { TARGET_USER_VERSION } from '../core/migrations.js';

export const checkDb: CheckFn = async () => {
  const dbPath = getDbPath();

  if (!fs.existsSync(dbPath)) {
    return {
      name: 'DB schema',
      status: 'fail',
      detail: `DB not found at ${dbPath}`,
      remediation: "DB not initialized. Run 'bun run setup'.",
    };
  }

  let actual: number;
  let db: Database.Database | null = null;
  try {
    db = new Database(dbPath, { readonly: true, fileMustExist: true });
    const row = db.pragma('user_version') as Array<{ user_version: number }>;
    actual = row[0]?.user_version ?? 0;
  } catch (err) {
    return {
      name: 'DB schema',
      status: 'fail',
      detail: `Could not read user_version: ${(err as Error).message}`,
      remediation: 'DB may be corrupted. Restore from backup or run bun run setup on a fresh path.',
    };
  } finally {
    if (db) db.close();
  }

  if (actual === TARGET_USER_VERSION) {
    return {
      name: 'DB schema',
      status: 'pass',
      detail: `user_version=${actual}`,
    };
  }

  if (actual < TARGET_USER_VERSION) {
    return {
      name: 'DB schema',
      status: 'fail',
      detail: `DB schema v${actual} < build v${TARGET_USER_VERSION}`,
      remediation: "Run 'bun run setup' to migrate the DB to the current schema.",
    };
  }

  // actual > TARGET_USER_VERSION
  return {
    name: 'DB schema',
    status: 'fail',
    detail: `DB schema v${actual} > build v${TARGET_USER_VERSION}`,
    remediation: 'Your DB is newer than this build. Update Claudex: git pull && bun run build.',
  };
};
```

Notes:
- Open the DB **readonly** with `fileMustExist: true`. We never want doctor to inadvertently create or migrate the DB.
- Always `close()` the handle in a finally block — Windows file-lock hygiene matters here (see project CLAUDE.md notes).
- `getDbPath()` already resolves to `~/.claudex/db/claudex.db` (cross-platform via `os.homedir()` + `getClaudexHome()`). Re-use; do not hardcode.
- Don't call `runMigrations` from doctor. Doctor diagnoses; it does not repair (CONTEXT.md, scope-locked).
</task>

<task id="05-tests-db">
**Create `src/tests/diagnostics/check-db.test.ts`** — ≥3 tests.

Pattern: build a tiny temp SQLite DB on disk per test, set the desired `user_version` via pragma, point `getDbPath` (or directly the check, by injecting a test variant) at it. The simplest approach is to monkey-patch `getDbPath` via vitest's `vi.mock`:

```ts
import { vi } from 'vitest';

vi.mock('../../shared/paths.js', async () => {
  const actual = await vi.importActual<typeof import('../../shared/paths.js')>('../../shared/paths.js');
  return { ...actual, getDbPath: () => mockDbPath };
});
```

…where `mockDbPath` is set per test in a `beforeEach`. Use a temp directory under `os.tmpdir()` and clean up in `afterEach`.

Required cases:

1. **pass (current schema)**: create empty DB, `PRAGMA user_version = TARGET_USER_VERSION`, run check → expect `'pass'`, detail `'user_version=24'`
2. **fail (missing DB)**: point `getDbPath` to a non-existent path → expect `'fail'`, detail mentions 'DB not found', remediation includes `'bun run setup'`
3. **fail (older schema)**: create DB with `user_version = TARGET_USER_VERSION - 1` → expect `'fail'`, detail mentions `<` and `'bun run setup'`
4. **fail (newer schema)**: create DB with `user_version = TARGET_USER_VERSION + 1` → expect `'fail'`, detail mentions `>` and `'git pull'`

Total tests across this plan: 3+ (bun) + 4 (db) = ≥7. Each must run on Windows; use forward-slashes in temp paths via `path.join(os.tmpdir(), ...)`.
</task>
