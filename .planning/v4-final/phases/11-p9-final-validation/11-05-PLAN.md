
Capture the exact table names with `_old` suffix.

Step 2 — grep for ALL `_old` references across source files:

```bash
# Source code (TypeScript/JavaScript)
rg -n "_old\b" src/ --type ts --type js > /tmp/old-callers-src.txt 2>&1
echo "Source matches: $(wc -l < /tmp/old-callers-src.txt)"

# SQL migrations (excluding V17 itself which legitimately renames TO _old)
rg -n "_old\b" src/db/migrations/ | grep -v "V17" > /tmp/old-callers-sql.txt 2>&1
echo "SQL matches (excluding V17): $(wc -l < /tmp/old-callers-sql.txt)"

# Tests
rg -n "_old\b" src/tests/ > /tmp/old-callers-tests.txt 2>&1
echo "Test matches: $(wc -l < /tmp/old-callers-tests.txt)"

# Scripts and tools
rg -n "_old\b" scripts/ tools/ 2>/dev/null > /tmp/old-callers-scripts.txt
echo "Script matches: $(wc -l < /tmp/old-callers-scripts.txt)"
```

Step 3 — classify each match:
- **Live caller**: source code reads/writes the `_old` table at runtime → BLOCKS DROP
- **Migration internal**: V17 itself or its rollback → does NOT block DROP (V17 is historical)
- **Test fixture**: a test specifically validates the V17 migration behavior → does NOT block DROP if the test is migration-historical; DOES block DROP if it tests live behavior expecting `_old` data
- **Comment / doc / variable name reuse**: a string match that's not a SQL identifier → does NOT block DROP
