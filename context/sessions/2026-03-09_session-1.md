## Decisions Made
- One core, two swappable runtime adapters (CC hooks + OpenClaw bridge)
- Capability-aware event model: host-neutral RuntimeEvent + RuntimeCapabilities declaration (v1.1, accepted Codex's feedback over initial pushback)
- Enrichment disabled on CC hooks via capability check (deadlock risk: hook calling CLIProxyAPI while CC waits)
- Topic-shift micro-injection (keyword Jaccard < 0.15, max 800 token pivot blocks) to address boundary-only gaps
- Archive tables (ALTER TABLE RENAME) instead of DROP for migration safety, with 30-day retention
- One codebase for all platforms — 2-3 process.platform checks, not separate repos
- NULL uniqueness fix: COALESCE sentinel '__global__' instead of nullable project column
- files_modified stored as JSON array with json_valid() CHECK, not comma-separated text
- Stop hook restored in v1.1 (needed for afterTurn event on CC where message_end doesn't exist)

## Learnings
- Both predecessor systems independently converged on boundary-only injection — strong signal this pattern is correct
- 84% of auto-captured observations never surface (access_count=0) — quality gates matter more than capture volume
- Codex CLI on Windows needs a git repo to run (fails with "not inside a trusted directory")
- SQLite NULL doesn't participate in UNIQUE constraints — always use sentinel values for "no project" scoping
- Adapter abstractions that mix optional host-specific fields create "worst of both worlds" — capability declarations are cleaner
- CC hooks calling back into CC's own API from inside a hook = guaranteed deadlock
